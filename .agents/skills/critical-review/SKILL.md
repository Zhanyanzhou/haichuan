# 法庭审校（Critical Review）

## 目的

对重大决策执行一场**模拟法庭**：「原告主张 → 被告抗辩 → 举证质证 → 法官判决」，
强制打断预判式生成的惯性，把分歧收敛到可验证证据，而不是靠说服力。

## 角色身份与作用（必读）

本法庭共四个角色，身份、立场与职责边界如下：

1. **原告（主张方）**：AI 扮演。代表“方案该做”的立场，提出主张、方案、结论，
   并给出支持主张的依据。对应 AI 的生成模式（顺着惯性提方案）。

2. **被告（抗辩方）**：AI 扮演。**承接原“红队”的对抗性挑错职责**，
   代表“风险与反例”的立场，专门找原告主张的漏洞、风险、反例、未验证事实。
   对应 AI 的批判模式（打断生成惯性）。不得为反对而反对，
   找不到实质问题时明说“未发现实质反例”。

3. **法律助理（中立证据整理者）**：AI 扮演。不站队，只认证据：
   整理双方依据、核验事实真实性、归纳争议焦点、给出倾向性意见
   （有明确依据才给，并注明“非判决”）。

4. **法官（用户）**：唯一有裁判权的人。AI 提交庭审纪要后，
   由法官对“AI 无法用证据判断的分歧”做最终判决；AI 以法官判决为准执行。

**要点**：AI 一人分饰原告、被告、法律助理三角，三者立场必须清晰分离、不得混淆；
法官永远是用户，AI 不得行使裁判权。

**边界声明**：被告只能发现 AI 已知范围内的错，发现不了 AI 知识盲区里的错；
后者需靠跨模型、外部工具或用户补足。

## 启用与退出（防止过度触发）

- 本流程**仅在**用户点名“法庭”，或任务明确命中重大问题时启用。
- 回答完毕**立即退出法庭模式**，后续对话恢复普通风格；
  不得因本技能曾加载就持续用法庭腔。
- 日常问答、A 类小改动：即使上下文中包含本技能，也不启用。

## 触发（自查清单）

回答前先自问，命中任一即触发：

- 是否涉及高风险域？（认证 / 权限 / 订单 / 库存 / 金价 / 隐私 / 支付 / 数据库 / 生产配置）
- 是否属于 B 类任务？（改 Schema / 依赖 / .env / 删除文件 / 10+ 文件 / Git 写入 / 部署）
- 是否涉及架构或规则变更？
- 结论若错了，是否会造成数据丢失 / 资金损失 / 安全风险 / 难以回滚？

命中任一 → 开庭审理；全不命中 → 普通问答，不开庭。
规则只提高触发概率；可靠触发靠用户点名“法庭”。

## 庭审流程

1. 原告陈述：先以专业身份独立给出结论（主张），声明视角、关键假设与依据来源。
2. 被告抗辩：换一个对立的专业身份，重新读取需求与文档，逐条质疑原告主张。
3. 举证质证：按问题域分流，用证据检验双方主张；证据不足的提交法官（用户）裁决（见「庭审终结与升级」）。

## 被告独立性（可执行）

- 被告每条抗辩必须附独立可核验出处（代码行 / 文档段 / URL），
  禁止以“原告已论证”作为依据。
- 若环境支持子代理，应优先用独立子代理抗辩；不支持则在单会话内完成上述要求。

## 举证质证（按问题域分流）

- 代码/工程类：分歧转可验证断言（类型检查 / 测试 / 构建 / 页面实查），
  以运行结果为客观证据；AI 只转述结果，不越权判决。
- 决策/业务类：不越权判决，产出「分歧清单 + 双方各自依据 + 需法官裁决的输入」。

## 证据真实性核查

- 主张涉及外部 / 业务事实时，被告必须质证：“这个事实核验过吗？来源是什么？”
- 只有贴 URL 不算核验。有工具面时必须实际打开 / 验证来源；
  无工具面时明说“无工具，无法核验”，降级为待确认。
- 核验不到的事实 → 列入「待法官裁决项」，不得当作已证实事实使用。
- 代码全绿 ≠ 事实正确：类型检查、测试、构建只证明内部自洽。

## 庭审终结与升级（禁止和稀泥）

- 最多 2 轮（被告抗辩 1 轮 → 举证质证 1 轮），禁止无限递归。
- 证据充分时必须给出**明确的法律助理意见**：写明倾向哪一方、依据是什么，
  并注明“这是意见，最终判决由法官（用户）做出”。
  **禁止**用“双方都有道理”“各有优劣”“视情况而定”等含糊话术收场而不下结论；
  给出明确判定条件的结论（如“预算充足选 A，否则选 B”）不算含糊。
- 升级前必须**穷尽可验证手段**：代码类分歧必须先跑类型检查 / 测试 / 构建 / 页面实查，
  未穷尽验证不得提交法官。
- 2 轮后仍无法用证据判断 → **立即休庭并提交法官（用户）**，不得继续和稀泥或假装已有结论，
  输出「庭审摘要」：

  ```text
  ## 庭审摘要（请法官判决）
  ### 争议焦点
  - 原告主张 + 依据
  - 被告抗辩 + 依据
  ### 无法判断的原因
  - 缺什么证据 / 需要什么真实输入
  ### 可选方案
  - 方案 A：利弊
  - 方案 B：利弊
  ### 法律助理意见
  - 有明确依据：给出倾向 + 置信度
  - 无依据：明写“无倾向，请法官定夺”
  - 必须是单一明确倾向或明说无倾向；禁止“建议综合 / 折中”
  ```

- 法官判决后：**执行层**以法官决定为准继续执行，不反复纠缠；
  但涉及高风险 / 安全 / 隐私隐患时，**一次性**明确记录到交付报告，
  提醒后仍按法官决定执行；只有出现新的实质证据时才可重新提出。
- 被告目标是找出被忽略的风险或反例；找不到实质问题时明说“未发现实质反例”，
  不得为反对而反对。

## 模型降级

- 弱模型（Claude Code / GLM）遇重大问题简化为「主要风险 + 依据 + 待确认项」，
  不要求完整三段式；完整辩论交给 Codex 或 Copilot（DeepSeek）。
- 降级时以下底线不可省略：AI 不是法官、禁止和稀泥、事实核查、升级给用户。

## 输出

交付时明确区分“法律助理意见”与“待法官判决”：

```text
### 法律助理意见（仅供参考，非判决）
### 依据
### 被告抗辩要点
### 待法官判决的事项
### 待确认项（含未核验事实）
```
