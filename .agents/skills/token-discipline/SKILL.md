# Token 成本诊断（Token Discipline）

> 历史审计与账单复盘见 `../../../docs/DECISIONS.md` A.11。供应商、价格、缓存、水位和模型路由以当前账号账单、usage 与当前工具适配为准；省钱靠调用结构与模型分层，不靠猜测。
>
> 本技能是咨询/诊断型，只由用户的成本或用量问题触发。日常通用纪律在 `../../../AGENTS.md`；工具专属阈值和自动护栏只在对应工具适配中维护。不要把历史供应商事实改写成当前 Codex 或跨工具的权限、计费规律或完成门槛。

## 一、诊断线索

1. 典型成本来源是回合数、有效上下文体积、工具输出、缓存命中/失效、思考输出和所选模型；先从当前用量记录确认占比。
2. 大型快照、整读文件、全量 diff 与超长命令输出会增加上下文，但是否计费以及幅度取决于当前供应商和工具链。
3. 历史缓存或代理链路观测只能作为线索；当前结论必须回到本账号的 usage、账单和当前工具行为。
4. 公共规则不设置跨供应商固定 Token、缓存时长或模型路由数字。

## 二、成本友好的工作方法

- **阶段闭环**：按可独立验收的阶段收尾或开新会话；不把同一验收闭环机械拆开，也不无限累积无关任务。
- **按需取证**：已知目标时优先读取符号、行段和摘要；浏览器优先精确断言，只有需要整体结构时才使用全页快照。
- **大读取隔离**：当前环境允许、任务可独立分区且能减少主会话负担时，可用子代理或独立会话；否则缩小范围、分段查询或将原始输出沉淀为项目产物后只返回摘要。
- **长命令**：预计耗时较长时使用当前环境允许的后台方式或阶段化执行；等待期间避免插入无关工作。
- **模型与输出**：按风险、成功率和实际价格选择当前可用档位；用户明确要求压缩输出时才使用相应的表达技能，不承诺固定节省比例。

## 三、诊断流程（用户来问成本时按序排查）

1. 看会话形态：本会话/近期会话是否回合过多、上下文过大或多个不相关目标混在一起；用户级转录或账单只在获得精确路径和只读授权后核验。
2. 看工具模式：是否连续浏览器快照/截图、整读大文件、"以防万一"式撒网搜索。
3. 看时间线：是否有长时间等待、反复重试或跨多个无关目标导致上下文重复；缓存是否失效只以当前 usage 或供应商证据判断。
4. 对症给建议：

| 症状 | 建议 |
| --- | --- |
| 回合或上下文持续增长且无收尾迹象 | 分阶段交付，并视当前工具能力开新会话 |
| 单个工具结果异常庞大 | 缩小查询、分段取证，或在获授权且有价值时隔离到子代理/独立会话 |
| 连续快照或截图没有增加证据 | 改用精确脚本、DOM 查询或目标断言 |
| 等待长命令期间插入无关请求 | 停；结果回来后任务闭环即收尾 |
| "以防万一"式读文件/列目录 | 停，按需取用 |

## 四、与既有技能分工

- caveman：用户明确要求时压缩输出文字
- ponytail：最小但完整的实现，减少无证据维护面
- 本技能：消耗结构认知 + 会话级纪律（省输入/缓存/回合总量）
- 三者互补，可叠加使用。

## 五、边界

- 本技能不改任何计费/代理/MCP 配置；配置类治理见 DECISIONS A.11。
- 自动护栏、上下文压缩、缓存和具体阈值属于当前工具与账号事实；未取得当前证据时只标记为待核验。
- 节省不能以牺牲 `../../../PROJECT_RULES.md` 第 13 节“修改后必须验证”为代价；验证命令该跑就跑。
- 缓存命中折扣以当前供应商账单为准，未确认输入命中、未命中和输出占比前，不向用户承诺具体节省比例。
