# 设计品味 — 前端视觉 Skill

> 仅适用于客户前台页面的视觉、布局、响应式、交互、视觉性能和无障碍任务。
> 管理后台使用 `docs/UI_GUIDE.md` 附录 A 与 `docs/ADMIN_COPY_GUIDE.md`，不使用本 Skill；后台中嵌入的公开内容预览只审查预览区域。
> 本 Skill 不具有产品决策权和自动执行权限。

---

## 一、使用前判断

开始任务前，先判断本轮核心问题是否属于：
客户前台视觉设计、页面布局、响应式、交互状态、动画体验、视觉性能、无障碍、上线前界面检查。

属于以上范围时，才允许引用本 Skill。

如果任务主要属于管理后台、后端、API、数据库、权限、环境恢复、路由故障、数据迁移或纯业务逻辑，则本轮不使用本 Skill。管理后台的布局与文案问题分别读取 `docs/UI_GUIDE.md` 附录 A 和 `docs/ADMIN_COPY_GUIDE.md`。

---

## 二、设计分析方法

### 2.1 读取场景信号

1. **页面类型** — 落地页（SaaS / 消费品 / 品牌 / 活动）、作品展示、品牌首页、产品列表/详情、编辑型/博客
2. **氛围关键词** — "高级珠宝"、"安静"、"克制"、"编辑感"、"现代东方"；不能把这些词直接当作设计方案
3. **受众** — 高端消费者、设计师、品牌合作方
4. **当前实现基线** — 从 `docs/DECISIONS.md`、`docs/UI_GUIDE.md`、当前设计令牌和真实字体加载结果读取；不得把实现现状误写成品牌历史、永久资产或授权证明

### 2.2 对照 UI_GUIDE 检查清单

`docs/UI_GUIDE.md` 是项目视觉唯一详细来源。下列内容只规定检查顺序，不复制或覆盖其中的数值：

每次视觉分析按以下顺序进行：

1. **信息层级** — 标题→副标题→正文→辅助信息，层级是否清晰
2. **字体** — 中英文分工、层级、行长和字重是否符合 UI_GUIDE
3. **留白** — 品牌叙事区是否有呼吸感，功能区是否在克制与可用之间平衡
4. **色彩** — 品牌金是否只作克制点缀，正文和状态色是否满足对比度
5. **图片** — 产品图与编辑图是否分轨，比例、材质、裁切、授权和替代文本是否合格
6. **组件** — 按钮、链接、卡片、标签、图标和表单是否使用统一体系且状态完整
7. **布局** — 网格、对齐、单一主焦点和内容密度是否服务页面任务
8. **响应式** — 按 `docs/UI_GUIDE.md` 当前规定的代表性视口，分别检查焦点、裁切、内容顺序、操作可达性和横向溢出
9. **性能与无障碍** — 键盘、焦点、动态偏好、字体、图片和首屏稳定性是否验证

### 2.3 浏览器证据与视觉验收

修改前先获取当前页面桌面和移动端截图，说明页面任务、目标受众、唯一主焦点和本次不改内容；没有可运行页面或截图时明确标记为假设，不得宣布视觉验收通过。

修改完成后，用相同页面、状态和代表性视口在浏览器中对照 UI_GUIDE 检查：

- 品牌色是否正确显示
- 字体是否正确加载
- 间距是否一致
- 响应式是否正常
- 珠宝或页面核心任务是否仍是第一视觉焦点
- loading / empty / error / success / focus 状态是否清晰而不破坏品牌体验

涉及 Hero、系列专题、品牌摄影或编辑影像时，再读取 `luxury-visual`；普通列表、搜索、隐私、账户、表单和服务流程不自动加载摄影规则。

## 三、禁止行为

- 对整个项目做全局视觉大改（只修改当前任务范围内的页面）
- 覆盖 UI_GUIDE 中定义的品牌规范
- 使用默认模板化设计（如标准蓝色链接、灰色边框卡片）
- 在没有产品确认的情况下更改品牌色、字体或 Logo
- 为追求极简隐藏商品事实、错误、隐私说明或服务流程
- 未查看真实页面或截图就宣称视觉问题已解决

---

## 四、规则优先级

发生冲突时按以下顺序：

1. `AGENTS.md` 的安全、权限与内容真实性边界
2. 用户本轮明确授权与已批准产品目标
3. 当前业务合同、数据流、技术架构与 `docs/DECISIONS.md` 的已批准决策
4. `docs/UI_GUIDE.md` 在客户前台视觉与体验范围内的详细规范
5. 本 Skill 的通用审查方法
