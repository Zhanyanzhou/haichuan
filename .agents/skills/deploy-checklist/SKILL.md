# 海川珠宝简明部署规则

> 本 Skill 规定 Codex 的部署决策和与用户沟通方式，不保存环境变量、迁移批次或第三方服务状态。技术细节以当前代码、配置、运行环境和 `docs/PRODUCTION_RELEASE_RUNBOOK.md` 为准，权限仍遵守 `AGENTS.md`。

## 1. 先识别用户要的结果

- 用户只说“部署”“部署一下”而未明确环境时，默认部署到现有**预发布环境**；不得据此公开正式域名、开启交易或发送真实通知。
- “正式上线”“发布给客户”“切到正式域名”表示生产公开放量。Codex 先完成所有可逆准备，只在最终切流、首次生产写入或其他现有授权未覆盖的高风险动作前集中确认一次。
- “回滚”表示恢复上一份已验证的固定版本。先保护数据和当前证据；涉及数据库降级、备份恢复或数据覆盖时另行确认。
- 环境不明确且错误选择会影响真实客户或数据时，用一句通俗问题确认；不要向用户询问 Docker、digest、migration 等技术选择。

## 2. 四类门禁必须分开

不要把所有检查串成一个总开关：

1. **代码制品**：质量检查、构建、SBOM、签名和固定 digest。它不应因页面文案尚未审核而无法生成。
2. **环境部署**：备份、迁移检查、部署、健康检查和回滚点。预发布可以使用明确的安全降级内容。
3. **内容发布**：页面、SEO、法务、联系方式和媒体授权分别审核并留下内容哈希和批准记录。
4. **正式放量**：只有生产要求的代码、环境和内容证据齐备后，才开放正式域名或客户流量。

页面内容不完整只能阻止内容发布或正式放量，不能阻止代码制品构建和预发布环境更新。当前工具若仍把这些门禁绑定在一起，应报告为流水线差距并采用安全降级；不得伪造页面、审核人或成功结果。

## 3. 新手用户交互合同

- Codex 自行选择并执行范围内、可逆的技术步骤，不要求用户复制命令、理解日志或逐项批准。
- 必须让用户决定时，先给主推荐，再用普通中文说明影响；把同一阶段的问题合并为一次确认。
- 不向用户索要密码、Token、私钥或数据库连接串。需要登录、扫码、验证码或平台审批时，明确告诉用户只需完成哪一个界面动作。
- 不能把“安全”解释成无限追加检查。每项检查必须对应当前环境和风险；没有新证据时停止重复扫描。
- 进度更新只说明“正在做什么、为什么需要、是否需要用户动作”。最终使用“已完成 / 尚未完成 / 需要你做的一件事”，不倾倒原始日志。

## 4. 预发布默认策略

- 使用已通过质量检查的不可变镜像或一次性校验过的 release bundle；禁止在服务器上从源码临时构建正式候选。
- 交易、支付、退款、真实短信/邮件、合作商写入和搜索引擎收录默认关闭。
- 内容未完成时使用项目已有的安全短页或失败关闭状态，并标记 `contentReady=false`；测试 seed、虚假联系方式、虚构库存和占位商品不得冒充正式内容。
- 有数据库迁移时先创建可恢复备份并检查迁移计划；没有数据库或媒体变更时，不机械重复完整恢复演练。
- 部署后至少验证健康探针、首页、后台登录入口、关键只读 API、容器/卷身份和关闭中的业务开关。
- 预发布通过只能表述为“预发布已部署/已验收”，不得表述为“正式上线”。

## 5. 正式上线默认策略

- 优先提升预发布已验证的同一代码 SHA 和固定 digest，不在生产前重新修改源码。
- 正式内容、SEO、域名/TLS、持久化、监控、备份和回滚必须有当前证据；真实交易或外部发送只有在用户明确批准并完成对应联调后才能开启。
- 单人经营场景不得为了满足流程伪造第二名员工账号。Codex 可以准备内容和自动检查，但不能审批自己生成的业务事实。由用户对法务、公司资料、联系方式和公开承诺进行一次内容哈希绑定的负责人确认；若当前代码强制双账号审核，应将其作为待实现差距，不能绕过数据库或冒充他人。
- 完整恢复演练用于首次生产部署、包含高风险/不兼容迁移的发布、备份方案变更或定期灾备演练；普通无 Schema 变更发布只复核最新备份健康和回滚可用性。
- 公开放量前给用户一份简短 Go/No-Go 摘要，并只对最终公开动作请求一次确认。

## 6. 动态读取当前事实

每次重新读取，不沿用历史报告：

- `.env.example`：只读取变量名、用途和说明，不读取或输出 `.env` 真实值。
- `docker-compose.yml`、Dockerfile、反向代理配置：核对变量是否实际注入、端口、卷、健康检查、启动命令和默认值。
- `server/prisma/schema.prisma`、`server/prisma/migrations/` 与目标环境 `prisma migrate status`：确认迁移，不把仓库目录名当成生产状态。
- `server/prisma/seed.ts` 与容器环境：首次部署必须证明管理员初始化能执行、可审计且不会重复创建错误账号。
- 当前 CI、依赖清单、鉴权代码和安全配置：以实际文件和命令结果判断，不复述旧盘点结论。
- 静态资源目录、上传目录、私有媒体目录和 Docker 卷：区分构建期资产与运行时媒体，验证持久化、权限和恢复路径。

## 7. 专业技术底线

以下要求只约束其相关阶段；缺少生产证据不得反向阻止安全的预发布更新：

1. **配置**：必需变量存在且被目标服务消费；密钥强度、跨域来源和 Feature Flag 符合本次批准范围。
2. **数据库**：有部署前备份和可回滚点；迁移状态明确；破坏性或数据变更已单独批准。
3. **管理员初始化**：首次环境能安全建立首个管理员；初始化凭据不进入日志、镜像或版本库，完成后按方案撤销或轮换。
4. **媒体**：上传和私有媒体使用持久卷或已批准的对象存储；重建容器不丢失；备份包含数据库与媒体。
5. **边界安全**：公网入口具备 TLS；HSTS、CSP、Cookie、安全响应头、上传体积和反向代理配置与实际资源来源一致。
6. **外部服务**：邮件、短信、物流、支付、微信和对象存储逐项核对“代码实现、变量注入、网络连通、真实凭据、回调配置、失败降级”；六项均成立或明确证明不适用，才可称为已接通。
7. **供应链**：根据当前工作流和锁文件执行适用的依赖审计；发现项按可利用性和生产暴露面分级，不把单次扫描等同于长期安全。
8. **备份恢复**：确认保留周期、异地副本和恢复步骤；需要完整恢复演练的发布按第 5 节执行，否则验证备份健康和回滚点。

## 8. 执行效率

- 首选 CI/CD、镜像仓库和机器部署身份。无法使用时，生成一份可审计、幂等的部署包或脚本，一次上传、一次执行、一次读取汇总结果。
- 浏览器中的云控制台逐条命令只作应急通道。遇到 MFA、扫码或验证码时让用户完成该动作，不以大量网页命令长期替代自动化部署。
- 复用已通过的质量结果和不可变制品；只有代码、依赖、构建输入或内容制品发生变化时才重新构建相应部分。
- 失败后从明确的失败阶段继续，不重复已通过且输入未变化的昂贵检查。

## 9. 交付格式

默认只给用户：

- **已完成**：当前真正完成到哪个环境和版本。
- **尚未完成**：只列会影响用户结果的项目。
- **需要你做的一件事**：仅在登录、业务事实或最终公开动作确实需要用户时出现。

技术证据保留在 CI、manifest 或部署报告中，聊天只给可定位链接和关键结论。始终区分“制品已生成”“预发布已部署”“内容已发布”和“生产已上线”。
