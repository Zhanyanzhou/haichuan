# 06 · 构图正例库（Composition Patterns）

> 用途：给"怎么排才好看"提供可模仿的正例。规范告诉你什么不能错，本库告诉你具体可以怎么排。
> 边界：本库**不规定任何数值**。字号、字重、行高、间距、色值、断点、影像比例一律到 `docs/UI_GUIDE.md` 对应节取（索引进 `docs/design-spec-card.md`）；文中出现的"展示标题级 / 正文级 / 组内距 / 区块距"都是语义层级名，不是新令牌。文中的"7 列 / 5 列"指在 UI_GUIDE 既有 12 列栅格上的落位选择，不是新增栅格或宽度规则。
> 用法：选一个基本型作为本节骨架，再按素材与页面任务变化，不要六种全用，也不要六种都不用。

---

## 0. 先判断素材，再选构图

| 手上有什么 | 首选基本型 |
| --- | --- |
| 一张强编辑影像（有景深、有留白区） | 型 4 全幅影像+下缘文字 |
| 一张作品特写 + 一段叙事 | 型 2 左图右文 / 型 3 右图左文 |
| 两件以上作品、细节与整体并置 | 型 5 编辑错位双图 |
| 单件作品的庄重展示、系列开篇 | 型 1 中轴对称 |
| 没有合格影像，只有文字与事实 | 型 6 纯排印（不要用图库凑数） |

判断顺序：素材质量 → 页面任务 → 基本型。**顺序反了就是套模板**：先定了"我要居中 Hero"，再去找一张能填进去的图，结果必然是平庸的。

---

## 型 1 · 中轴对称（庄严、系列开篇）

```text
┌───────────────────────────────────────────┐
│              眉题（英文小写或全大写）        │  ← 组内距
│              展示标题级，一行或两行           │  ← 组内距
│              一句说明，正文级，窄栏           │  ← 组间距
│                                           │
│            ┌─────────────────┐            │  ← 区块距
│            │                 │            │
│            │    作品或工艺     │            │  图宽约为容器的一半到三分之二
│            │                 │            │  两侧留白必须相等
│            └─────────────────┘            │
│                 作品名 / 材质               │  ← 组内距，辅助级
│                  一个主要行动               │
└───────────────────────────────────────────┘
```

- 焦点：图，不是标题。标题再大字重也受 UI_GUIDE 上限约束，不许靠加粗抢焦点。
- 视线顺序：标题 → 图 → 作品名 → 行动。
- 手机端：顺序不变，图宽放到容器全宽，说明文字行长受 UI_GUIDE 约束。
- 易犯：标题、副标题、眉题、编号、细线全堆在图上，变成"标题墙"；图太小导致整屏都是字。

## 型 2 / 型 3 · 左图右文、右图左文（叙事主力）

```text
┌───────────────────────────────────────────┐
│ ┌──────────────────┐   眉题                │
│ │                  │   区块标题级，两到三行  │
│ │                  │   ─────────          │
│ │    作品 / 工艺    │   正文，窄栏           │
│ │    占 7 列        │   每行不超过规范行长    │
│ │                  │                      │
│ │                  │   一个文字链接式行动    │
│ └──────────────────┘                      │
│        图注（辅助级）                        │
└───────────────────────────────────────────┘
        文字占 5 列，垂直位置偏上，不机械居中
```

- 比例：图 7 / 文 5 或图 8 / 文 4，**不要 6:6 等分**——等分是廉价感的主要来源之一，两方都成不了焦点。
- 文字块垂直位置：偏上对齐图的顶部或上三分之一，不要默认垂直居中。居中是"没做决策"的表现。
- 型 3 是镜像。同一页内左右交替可以用，但**相邻两节不要完全镜像复制**，至少改变图的比例或文字块的垂直位置。
- 手机端：图在上、文在下；图注紧跟图；不要让文字先出现把图推到屏下。
- 易犯：文字栏拉满、段落过长、图与文之间塞一条装饰竖线。

## 型 4 · 全幅影像 + 下缘文字（Hero 专用）

```text
┌───────────────────────────────────────────┐
│                                           │
│                                           │
│            真实编辑影像，有景深              │
│         主体落在中右或中左三分区             │
│                                           │
│                                   ┌───────┤
│  眉题                              │       │
│  展示标题级（真实 DOM 文字）          │ 主体  │
│  一个主要行动                       │       │
└───────────────────────────────────────────┘
  文字压在影像本身的暗部或亮部留区，不另加色块蒙版
```

- 选图标准：影像必须**自带一块可落字的安静区域**。没有，就换图或改用型 2，不要靠加重蒙版把图压灰来救。
- 文字位置：下缘或侧缘，避开主体；标题是可选择的真实文字，不烙在图里（UI_GUIDE §5.2 硬规则）。
- 一屏只有这一套东西。首屏不再叠加第二张图、促销条、统计数据。
- 手机端：单独的安全裁切，必要时文字移到图下方，不要硬压在主体上。
- 易犯：巨大英文口号成为唯一主角；轮播三帧自动切换；蒙层让珠宝失去真实高光。

## 型 5 · 编辑错位双图（细节与整体并置）

```text
┌───────────────────────────────────────────┐
│ ┌────────────────┐                        │
│ │                │      区块标题级          │
│ │   整体作品      │      正文，窄栏          │
│ │                │                        │
│ └────────────────┘                        │
│        ┌──────────────┐                   │
│        │              │                   │
│        │  工艺细节特写 │                   │
│        │              │                   │
│        └──────────────┘                   │
│              图注，辅助级                   │
└───────────────────────────────────────────┘
  两图错位、比例不同、底边不对齐，但共享同一列线
```

- 两图必须有**不同的信息任务**：一个交代整体，一个交代细节。两张同类型美图并置只是装饰。
- 错位要落在栅格上：共享列线，只错垂直位置和宽度。随手乱摆不是编辑感。
- 文字块与其中一张图同组，组内距明显小于它与另一张图的距离。
- 手机端：还原为单列，顺序按"整体 → 文字 → 细节"或"整体 → 细节 → 文字"，不保留错位。
- 易犯：三图四图继续加，变成图库墙；两图同比例同尺寸，错位消失。

## 型 6 · 纯排印（无合格影像时的体面解）

```text
┌───────────────────────────────────────────┐
│  眉题                                      │
│  展示标题级，两到三行，栏宽收窄               │
│                                           │
│  正文，窄栏，每行不超过规范行长              │
│                                           │
│  一个主要行动                               │
└───────────────────────────────────────────┘
  靠字号阶梯、行长和留白成立，不靠色块与边框
```

- 适用：品牌故事过渡节、工艺说明、隐私与服务条款、素材未通过审核时的草稿页。
- 这是**正式构图**，不是"没做完"。比塞一张无关图库图高级得多。
- 易犯：为了填空加色带、加图标、加卡片底。

## 7. 把基本型组合成一页

1. 一页通常 3–5 节，**相邻两节不使用同一基本型**；节奏来自"密—疏—密"的变化，不是等距复制。
2. 全页只有一个主要行动，页末可以重复同一个行动的文字；两个不同行动的按钮不同屏并列（UI_GUIDE §6.2）。
3. 影像语言统一：同一页内的编辑图共享光线、背景与色调方向；产品图与编辑图不混用。
4. 背景不碎片化交替：连续叙事才用次级画布，不在同一视口切换多种近白。
5. 至少一节是"停顿"（纯排印或单图大留白），连续高密度是廉价感来源。
6. 差异化自检：写下本页与站内其他页不同的 3 个版式决定（基本型组合、图文比例、文字块位置、节奏密度都可以），写不出来说明在复制。

## 8. 反面清单：看到这些就重来

- 居中 Hero + 副标题 + 按钮 + 三列卡片 + 底部 CTA，一页到头。
- 所有节都是"标题居中 + 一句说明 + 下方内容"，只是换了图。
- 三列等宽卡片承载品牌叙事（卡片是功能容器，不是叙事容器）。
- 用阴影、圆角、渐变、金色描边补层级。
- 首屏出现两个以上高对比按钮，或眉题、编号、细线、徽标同时抢戏。
- 移动端把桌面构图等比缩小，文字压图、图被裁到主体之外。

## 9. 一张填好的艺术方向卡（示例：首页 Hero）

照这个颗粒度写。字段写不出具体内容，说明还没做决策，不要开始写代码。

```text
页面任务：首页第一屏，让第一次到访的人记住"这件作品"，并愿意进入系列页。
唯一主焦点：单件作品的高光与镶嵌细节（不是品牌口号，不是按钮）。
构图：型 4 全幅影像 + 下缘文字。选它的理由：手上有一张左下暗部干净、
      主体偏右的编辑影像；视线要先到作品，再回落到左下的标题。
      文字落在左下，占 5 列；主体留在右侧三分区，不被文字覆盖。
差异化：1) 首页用型 4，系列页用型 1、工艺页用型 2，三页首屏基本型不同；
        2) 本页标题压影像下缘，其余页标题在图外；
        3) 首屏不放第二个行动，系列页首屏才有文字链接式次行动。
排印：眉题用辅助级、全大写、加字距；标题用展示标题级，字重取规范下限，
      两行以内；中英按 UI_GUIDE 双轨分工，不用加粗制造焦点。
节奏：首屏只有一组内容，眉题—标题—行动之间用组内距；
      与下一节之间用区块距，下一节第一节必须留白充分，形成停顿。
影像：真实编辑影像，保留材质高光；桌面与手机分别给安全裁切，
      手机端文字移到图下方；不加重蒙版救一张不适合落字的图。
色彩落点：只用规范的前台主文/次文与影像上的反白文字令牌，不新增色。
不做清单：不做轮播；不放促销条与统计数据；不用金色描边和装饰细线。
验收：1440 与 390 各一张截图；25% 缩略图先看到作品；
      首屏元素清单 = 眉题 1、标题 1、行动 1、影像 1，无并列主行动。
```

反例（等于没写）：主焦点"品牌形象"；构图"高端大气的 Hero"；差异化"用更好的图"；排印"字体优雅"；不做清单留空。
