> 记录日期：2026-10-07

> 性质：梵克雅宝专项只读技术与体验分析，供海川珠宝后续优化时复用。
>
> 状态：不是已批准的实施计划，不代表相关优化已经完成，也不授权迁移框架、发布页面或使用竞品受保护资产。
>
> 相关总览：[奢侈珠宝网站技术、媒体性能与页面构建器对照](luxury-jewelry-site-technical-benchmark-2026-10-07.md)

## 1. 给非技术人员的结论

### 1.1 为什么“好技术”没有统一所有网站

不存在脱离条件的唯一“最好技术”。更准确的说法是：某项技术在某种公司规模、业务、团队、预算和历史系统下更合适。

所有网站最终交给浏览器的基础其实相同：

- HTML：页面结构；
- CSS：布局、字体和颜色；
- JavaScript：交互和动画；
- 图片、视频和字体；
- HTTP：浏览器与服务器之间的通信。

React、Vue、AEM、Magento、Puck 等技术，是生产、管理和发布这些最终内容的不同工具，不是互相完全替代的同一种东西。

一个网站通常同时存在多个技术层：

| 网站层级 | 解决的问题 | 常见技术 |
| --- | --- | --- |
| 前端页面 | 浏览器怎样显示和交互 | React、Vue、Nuxt |
| 页面编辑器 | 运营人员怎样换图、改字、排版和发布 | AEM Page Editor、Puck、Magento Page Builder |
| 商品与交易 | 商品、价格、库存、购物车、订单 | Magento、自研服务 |
| 后端服务 | 预约、账户、支付、权限和接口 | NestJS、Java、PHP |
| 数据库 | 保存页面、商品、用户和订单 | MySQL、PostgreSQL |
| 媒体系统 | 图片、视频、裁切、派生版本和授权 | AEM DAM、对象存储、自研媒体库 |
| 分发与缓存 | 把资源更快送到用户附近 | CDN、边缘缓存 |

所以，同样是网站，背后仍会出现不同技术组合。

### 1.2 技术选择为什么受公司条件影响

1. **主要任务不同**：全球内容治理、电商交易、品牌展示和预约服务需要的系统不同。
2. **团队能力不同**：已有 Java/AEM 团队和已有 React/NestJS 团队的合理选择不会相同。
3. **历史系统不同**：成熟企业通常已有多语言、商品、客户、审批和媒体资产，整体迁移代价很高。
4. **预算和维护方式不同**：大型企业平台准备了更多能力，但许可、部署和专业人员成本也更高。
5. **“好”是取舍，不是排名**：AEM 擅长企业内容治理，Magento 擅长电商，React/Puck 擅长自定义内容体验。

最终体验不是由技术名称单独决定：

```text
最终体验
= 技术选择
+ 架构设计
+ 开发质量
+ 素材质量
+ 内容运营
+ 性能治理
+ 长期维护
```

使用 AEM 不会自动产生梵克雅宝的高级感，正如拥有专业相机不会自动成为专业摄影师。

## 2. 本次梵克雅宝公开页证据

### 2.1 可确认的公开技术特征

2026-10-07 对梵克雅宝中国首页的公开页面和资源读取显示：

- 页面资源大量使用 `/etc.clientlibs/richemont-vca/...`；
- 媒体资源使用 `/content/dam/vancleefarpels/...`；
- 页面加载 Adobe Granite CSRF 和 AEM ContextHub 相关资源；
- 页面存在 `vca-template-home-page` 模板标识；
- 加载 Richemont/VCA 的 Vue clientlib；
- 加载 Swiper 轮播资源；
- 图片通过 AEM DAM 风格的 `.transform.vca-*` 地址生成多尺寸版本。

因此可以高置信判断，公开页以 AEM 内容与媒体体系为基础，并由 Vue、Swiper 等 JavaScript 增强菜单、搜索、轮播和局部交互。

更接近真实情况的结构是：

```text
AEM 管理模板、页面内容和媒体资产
  ↓
AEM 输出公开页面结构
  ↓
Vue / Swiper 增强局部交互
  ↓
CDN 与 DAM 变体分发图片和视频
```

这不是纯 Vue 单页应用，也不能仅凭公开页面确认它使用的是哪一版 AEM、Page Editor 还是 Universal Editor、怎样审批、怎样部署。后台具体界面和工作流仍不可见。

### 2.2 当前页面媒体样本

本次桌面页面读取到：

| 项目 | 样本值 |
| --- | ---: |
| 图片节点 | 74 |
| 设置懒加载的图片 | 70 |
| `picture` 节点 | 70 |
| 响应式 `source` | 127 |
| 视频节点 | 4 |

图片变体可见 `w350`、`w550`、`w1024`、`w2560` 等宽度，并提供 `1x/2x/3x` 像素密度版本。大量屏下图片先使用极小占位，再在需要时加载真实媒体。

当前可见视频具有自动播放、静音和循环等属性；主要 Hero 视频有静态 poster。页面也存在隐藏菜单视频重复加载等不应照搬的性能反例。流畅感不等于页面资源很轻。

### 2.3 当前首页的信息结构

梵克雅宝首页不是“一个大视频页面”，而是一条完整的品牌探索路径：

1. 当期主题 Hero；
2. 高级珠宝或系列故事；
3. 舞蹈、文化与艺术项目；
4. 世家历史或灵感文章；
5. 礼赠场景；
6. 世家作品分类；
7. 新闻中心；
8. 配送、联系与售后服务；
9. 电子讯息订阅；
10. 完整页脚导航。

它的高级感来自整页叙事、真实作品、编辑影像、克制文字和章节节奏共同作用，不来自单独一个框架或动画库。

## 3. 梵克雅宝与海川的重合度

### 3.1 总体判断

| 维度 | 重合度 | 说明 |
| --- | --- | --- |
| 具体前端代码栈 | 低 | 梵克雅宝是 AEM + Vue/Swiper；海川是 React + Vite |
| 后台页面构建思想 | 高 | 都采用组件、模板、可编辑字段、预览与发布 |
| 页面数据模型 | 中高 | AEM 页面内容对应海川的 Puck `PageDocument` 与模板实例 |
| 响应式媒体基础 | 中 | 海川已有 Hero、商品详情和 Sharp 变体，但未覆盖所有模板节点 |
| 视频运行时 | 中低 | 海川有 Range 基础，但通用模板视频组件未形成完整公开链路 |
| 草稿、版本和发布 | 中高 | 方向一致；AEM 是成熟企业平台，海川是自有定制系统 |
| 达到相近视觉效果的可行性 | 高 | 视觉效果不依赖 AEM 专有渲染，可以在 React/Puck 上实现 |

一句话概括：

> 底层平台低重合，页面治理高重合，最终效果高可实现。

### 3.2 AEM 与海川概念映射

| 梵克雅宝 / AEM | 海川当前对应物 |
| --- | --- |
| Editable Template | `TemplateDefinitionV2`、模板版本和 Template Repository |
| AEM Component | Puck 组件、动态模板节点和内容槽 |
| Page Authoring | 页面装修器 |
| Page Content | Puck `PageDocument` |
| Allowed Components | Puck Config、模板合同和能力白名单 |
| Responsive Layout | 桌面/移动响应式规则 |
| DAM Asset | 海川媒体库 |
| DAM Rendition | Sharp 响应式图片派生 |
| Page Preview | Puck 画布与模板预览 |
| Author / Publish | 页面草稿、模板版本和已发布 `PageDocument` |
| Storefront Rendering | 海川共享 Renderer |
| 商品与内容引用 | Puck ExternalField、商品编码和媒体引用 |

这种映射只表示架构目的接近，不表示数据格式、组件代码或后台界面可以直接迁移。

## 4. 海川当前已经具备的基础

### 4.1 技术基线

- 客户端：React 18、TypeScript、Vite 8、Puck `0.22.4`；
- 服务端：NestJS 11、Prisma、MySQL 数据模型；
- 媒体处理：Sharp；
- 页面实例：Puck `PageDocument`；
- 模板结构：`TemplateDefinitionV2`、版本和共享 Renderer；
- 公开交付：已发布页面文档、SEO 快照和公开路由预渲染。

依赖证据见 [`client/package.json`](../../client/package.json) 和 [`server/package.json`](../../server/package.json)。

### 4.2 页面构建器基础

海川的 Puck 配置目前已经是受控编辑器，而不是允许运营任意写 HTML/CSS：

- 动态模板实例；
- 首屏主视觉；
- 网站全局设置；
- 业务功能区；
- 模板身份与精确版本；
- 页面真实内容与业务引用分离。

证据入口：[`puckConfig.tsx`](../../client/src/page-builder/config/puckConfig.tsx)、[`PuckDocumentRenderer.tsx`](../../client/src/page-builder/runtime/PuckDocumentRenderer.tsx)。

Puck 官方支持把自有 React 组件、字段、视口和数据模型嵌入应用，因此继续完善当前 Puck 架构比迁移 AEM 更适合现有代码库。

### 4.3 已经较成熟的 Hero 图片能力

[`HeroSection.tsx`](../../client/src/components/blocks/HeroSection.tsx) 已包含：

- 桌面和移动两套素材；
- `480/800/1200/1680` 响应式宽度；
- `picture/srcset/sizes`；
- 首屏高优先级和屏下懒加载；
- `IntersectionObserver`；
- `decoding="async"`；
- 固有宽高；
- 图片失败和未就绪状态；
- `prefers-reduced-motion` 处理。

### 4.4 服务端媒体基础

海川已经具备：

- Sharp WebP 派生；
- 禁止把小图放大；
- 公开视频和文件的 HTTP Range；
- `Content-Range` / `Accept-Ranges`；
- 短期响应式媒体内存缓存。

证据入口：[`responsive-public-media.ts`](../../server/src/modules/upload/responsive-public-media.ts)、[`public-uploads.gateway.ts`](../../server/src/modules/upload/public-uploads.gateway.ts)、[`upload.service.ts`](../../server/src/modules/upload/upload.service.ts)。

## 5. 海川当前最重要的差距

### 5.1 通用模板图片能力没有覆盖到 Hero 同等水平

[`DynamicTemplateRenderer.tsx`](../../client/src/page-builder/template-definition/DynamicTemplateRenderer.tsx) 的通用图片节点目前主要输出单一 `<img src>`。优先图片可以 eager，但通用节点还没有统一获得：

- `picture`；
- `srcset/sizes`；
- 桌面和移动独立素材；
- 固有宽高或稳定比例；
- 非首屏明确懒加载；
- 完整解码与占位策略。

因此，Hero 单独放图可以表现良好，但页面装修连续放置多个高分辨率模板图片时，仍可能发生过度下载、解码压力和滚动卡顿。

### 5.2 通用视频组件还不完整

海川有视频文件与 Range 基础，但模板公开运行时还需要形成统一视频组件：

- 桌面和移动源；
- poster；
- `preload` 策略；
- 可见后播放；
- 静音自动播放与暂停控制；
- `prefers-reduced-motion`；
- 图片回退和失败状态；
- 编码、大小和比例约束；
- 不阻塞标题、导航和主要行动。

### 5.3 媒体派生还不是完整发布制品

当前响应式图片主要采用请求时生成和短期内存缓存，缓存约 5 分钟、最多 64 条。后续需要评估：

- 上传或发布时预生成变体；
- 对象存储或 CDN 持久化；
- 内容哈希与缓存版本；
- 已发布素材撤销、归档和清理边界；
- 发布预检显示真实文件大小和预计负载。

由于公开素材仍有授权和撤销语义，不能直接把所有资源改成永久 immutable。

### 5.4 技术能力尚未全部兑现成品牌内容

要接近梵克雅宝效果，海川还需要真实且经过审核的：

- 代表作品；
- 核心系列；
- 工艺细节；
- 品牌事实；
- 定制服务；
- 顾问与预约路径；
- 桌面和移动端编辑影像；
- 授权来源和准确替代文本。

没有真实素材时，不能复制梵克雅宝图片、Logo、文案和标志性动画，也不能用虚构历史或 AI 图冒充可发布珠宝事实。

## 6. 梵克雅宝效果的真正组成

### 6.1 视觉构成

当前首页首屏的主要方法是：

- 极浅中性背景；
- 单一珠宝主体；
- 主体偏一侧，文字使用反向留白；
- 标题、简短说明、一个 CTA；
- 作品发生缓慢动态，文字和界面保持稳定；
- Header 安静、Logo 居中；
- 几乎不用卡片描边、厚重阴影和大面积品牌色。

这可以概括为：

```text
排版驱动
+ 摄影驱动
+ 极简
+ 统一艺术指导
```

### 6.2 整页叙事

海川不能只复制一个首屏构图，还需要让整页形成命题：

```text
一件代表作品或一个系列
  ↓
作品与工艺解释
  ↓
相关系列或使用场景
  ↓
真实服务与顾问入口
```

每一节只承担一个叙事角色。全页应有一个主要视觉焦点和一个主要下一步，后续章节不重复首屏 CTA，也不连续使用相同全幅构图。

### 6.3 技术在其中的责任

技术负责：

- 素材在正确设备加载正确版本；
- 页面不跳动、不卡顿；
- 视频可暂停并尊重减少动态效果；
- 运营只能在允许范围内编辑；
- 商品、服务和价格来自真实业务数据；
- 草稿、预览和公开结果一致；
- 错误素材和缺失事实在发布前被阻断。

技术不负责自动产生：

- 优秀摄影；
- 真实作品；
- 品牌历史；
- 克制文案；
- 艺术指导判断。

## 7. 后续候选优化顺序

> 本节只是以后实施时的优先级依据。开始实际修改前仍需核对当时的代码、工作树、产品决定、已发布页面与真实素材状态。

### P0：统一模板媒体交付

目标：页面装修中的所有图片槽都达到 Hero 的基础媒体质量。

- 通用 Renderer 接入响应式 URL、`srcset/sizes`；
- 明确唯一 LCP 媒体；
- 非首屏图片默认懒加载；
- 输出固有尺寸或稳定比例；
- 桌面/移动端可分别配置素材和安全裁切；
- 缺图、错误图和归档素材稳定收起或失败关闭。

### P0：先把页面章节做成篇

目标：先完成结构、比例、响应式顺序、空素材稳定性和视觉辨识。

- 首页确定一个真实命题；
- 只选择少量能由真实内容支撑的章节；
- 首屏主焦点唯一；
- 后续章节不重复同一全幅构图；
- 主行动唯一且指向真实服务或作品；
- 未准备好的章节隐藏或使用已批准短页。

### P1：建立受控视频组件

目标：视频可以增强作品表现，但不能阻塞页面。

- poster、桌面源、移动源；
- 可见后播放与离开后暂停；
- 静音、循环、暂停控制；
- 减少动态效果时切换静态图；
- 编码、体积和比例预算；
- 加载失败时保留标题、CTA 和图片回退。

### P1：把媒体变体做成发布制品

目标：减少请求时计算和重复下载。

- 上传或发布时生成稳定变体；
- 记录变体清单、尺寸、格式和内容哈希；
- 建立 CDN 缓存和撤销边界；
- 页面发布预检计算预计首屏负载。

### P1：加强页面构建器治理

目标：让运营能够快速编辑，但不能破坏品牌和业务事实。

- 页面类型允许的组件；
- 模板可编辑字段白名单；
- 商品和服务使用稳定引用；
- 草稿、预览、发布和回滚状态清晰；
- 已发布版本回读；
- 素材授权、归档和业务引用失效时 fail closed。

### P2：根据真实证据评估渲染方式

目标：解决真实 SEO、首屏 HTML 或缓存问题，而不是追逐竞品框架。

- 先验证现有预渲染、CDN 和 Core Web Vitals；
- 只有现有链路存在明确缺口时，再评估 React SSR 或混合渲染；
- 不因为梵克雅宝使用 AEM 就迁移 AEM；
- 不因为其他品牌使用 Nuxt 就把 React 改成 Vue。

## 8. 后续实施时的验收标准

### 8.1 视觉验收

- 第一眼焦点是珠宝或核心作品，不是 Logo、按钮或大段文字；
- 桌面与移动分别检查构图、裁切、内容顺序和 CTA；
- 产品图与编辑图分轨；
- 全页只有一套影像语言；
- 标题、说明和行动层级清晰；
- 没有促销腔、价格轰炸、多焦点和无意义装饰；
- 竞品的文案、图片、Logo 和受保护视觉资产没有被复制。

### 8.2 媒体与性能验收

- 唯一首屏关键媒体高优先级；
- 屏下图片不与首屏竞争；
- 手机不下载不必要的桌面原图或桌面视频；
- 图片具有正确 `srcset/sizes` 和稳定尺寸；
- 视频可暂停、可回退，减少动态效果有效；
- 无横向溢出和加载后布局跳动；
- 首页与作品详情以 LCP ≤ 2.5 s、CLS ≤ 0.1、INP ≤ 200 ms 为目标；
- 本机构建、Mock 和视觉观感不能代替真实公开环境验证。

### 8.3 页面构建器验收

- 页面装修与模板设计的保存对象分离；
- 页面草稿和发布动作分离；
- 公开 Renderer 与编辑预览消费同一模板合同；
- 真实页面只使用明确已发布的模板版本和真实内容；
- 系统示例、模板默认图和压力测试文案不进入公开页；
- 页面发布失败保留用户输入；
- 空素材、归档素材和失效业务引用不会导致黑屏或错误公开。

## 9. 明确不建议做的事情

- 为了视觉效果迁移到 AEM；
- 把 React/Vite 改成 Vue/Nuxt；
- 认为放视频就一定高级或流畅；
- 一次扩大大量模板数量；
- 在通用 Renderer 尚未成熟时让运营上传大量原图；
- 复制梵克雅宝图片、Logo、文案、产品命名或标志性动画；
- 用加载动画掩盖网络、解码或主线程阻塞；
- 用 AI 概念图冒充真实商品、材质、证书或工艺结果；
- 把代码完成、构建通过或本机观感当成正式上线证据。

## 10. 后续开始优化前必须重新核对

1. 当前 Git 工作树和目标文件是否与其他修改重叠；
2. 当前已发布首页 `PageDocument`，不能把草稿或模板预览当成线上首页；
3. 桌面和移动端当前页面截图；
4. 真实可用、已授权的作品与编辑影像；
5. 当前模板合同、Repository 版本和共享 Renderer；
6. 页面类型和发布规则是否发生变化；
7. 目标页面的实际网络、CWV 和媒体请求；
8. 本期只优化哪个页面和哪些区块，避免无边界整站重做。

## 11. 证据限制

- 梵克雅宝后台不可访问，AEM 判断来自公开页面资源、DOM 和官方平台能力；具体版本、编辑器、审批流程和发布拓扑无法确认。
- 媒体节点和资源数量是 2026-10-07 的一次浏览器样本，会随活动、地区、Cookie、A/B 实验和内容更新变化。
- 海川本地公开页在专项读取时未运行，因此本文件没有把代码能力写成当前页面已经达到的视觉效果。
- 本文件记录方向与差距，不替代后续实施时的新鲜代码、浏览器和生产证据。
