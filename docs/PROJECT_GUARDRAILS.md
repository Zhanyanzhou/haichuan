## 2. 产品定位

海川珠宝的客户前台是以珠宝作品、材质工艺、品牌内容与顾问服务为核心的数字品牌空间；内部系统负责商品、内容、客户咨询与运营管理。

客户体验目标：

- 先建立发现、理解与信任，再引导预约鉴赏、定制咨询、选款或其他已批准服务；
- 不做批发目录、促销会场、通用商城模板、SaaS 模板或竞品页面复刻；
- 高级感来自真实作品、摄影、排印、比例、留白和服务细节，不来自大面积金色、仿金属效果或强迫式营销；
- 不以“极简”为由隐藏商品事实、费用、隐私说明、服务条件或用户完成当前任务所需的状态。影响主要任务、数据真实性、提交结果或交易资格的 loading、empty、error 和 disabled 状态必须提供可理解反馈与恢复路径；非关键装饰失败可以安全省略或使用中性降级，但不得把未发布草稿、内部占位、旧数据或默认模板伪装成有效公开内容，也不得向访客暴露内部错误细节。

长期经营与服务边界：

- 主要服务区域为中国大陆；公开内容、交易条件、物流、隐私与支付说明必须以该区域真实可提供的能力为准。
- 公开网站提供完整中文与英文体验：中文使用无前缀规范路径，英文使用 `/en` 前缀。两种语言必须覆盖同一核心旅程、法律与交易信息，不能把机器翻译、缺页或自动回退伪装成已完成的双语发布。
- 长期产品目标同时服务标准零售、高级定制和审核通过的合作蜡模客户。三类业务共享同一作品与客户事实，在各自报价、资格、资源和订单状态机内形成真实交易，不复制商品、价格或库存来源。
- 微信支付与支付宝是中国大陆目标支付渠道。标准零售的正式主链由客户本人在订单上下文中发起在线支付，服务端按剩余应收创建渠道交易，并只以验签回调或主动查单确认到账；线下转账和门店收款只作为特殊订单或渠道异常的受限兜底，不得冒充微信或支付宝到账。
- 首发终端为桌面网站和手机网站，渠道顺序为微信支付优先、支付宝第二批，暂不包含小程序。桌面网站采用可扫码的 Native 场景，普通手机浏览器采用 H5 场景；微信内网页属于手机网站范围，只有公众号资质、商户号绑定、对应 AppID 下的 `openid`、支付目录和真实联调均具备时才能作为 JSAPI 场景开放，未具备时必须明确显示不可用状态，不得静默改走人工收款。
- 在线付款的退款方向是审核后原路退回，以渠道受理、查询或回调事实确认结果；人工不得直接把微信或支付宝退款标记为成功。线下异常收款才允许在线下凭据、操作者和审计时间线完整时人工退款。
- 在商户、合规、回调、查单、关单、退款、对账和目标环境门禁分别验收并再次获准上线前，上述支付能力只能作为安全关闭的目标能力，不得展示成可用收款方式。

成熟奢侈品品牌标准在海川的落点：

- **作品先于自我宣称**：第一焦点应是可核验的作品、材质、工艺、佩戴关系或服务价值；Logo、品牌名、英文口号和“高级”形容词只能建立识别，不能代替作品内容或成为画面的唯一主角。
- **先保持真实，再建立独特性**：成熟感不能停留在行业通用的衬线字体、香槟金和“东方”装饰符号。海川自己的 Logo 锁定、正式字体、影像语言、品牌母题和文案语汇只有在授权与品牌审批完成后才能成为长期资产；未确认阶段维持克制的中性系统，不把实现默认值包装成品牌传统。
- **叙事必须有事实支点**：每个系列、年份、主题、工艺和服务主张都要能追溯到已审核内容；没有证据时使用中性、准确的作品说明，不用泛化的年度系列、传承或稀缺话术制造品牌资历。
- **编辑体验与业务事实连续**：首页和作品展陈负责激发兴趣，选款中心负责查找比较，统一详情负责理解作品并进入下一步；任何 CTA 都应携带当前作品或服务上下文，不把用户丢到无关的通用页面。
- **服务本身构成奢侈体验**：预约、咨询、定制、交付、养护与售后只呈现真实可提供的范围，但一旦公开就必须说明清楚的下一步、责任边界和可恢复状态；不能只重视购买前画面而忽略购买前后的人际服务连续性。
- **克制不等于空白**：留白必须服务于作品和节奏。公开页面要么提供经过策划的真实内容，要么呈现明确、体面且有下一步的安全空态；不得用大面积空白、装饰图或内部默认模板掩盖内容尚未准备好。
- **数字款待是品质的一部分**：移动端、键盘、对比度、加载稳定、错误恢复、隐私和性能与摄影排版同等重要；不能把难用、等待和信息缺失包装成“高级感”。

公开页面职责是长期产品边界：

- `/` 是品牌首页，以品牌世界观、当期核心系列、作品与工艺叙事建立第一印象；Hero 必须围绕已审核的具体作品、系列、工艺或真实服务命题，品牌字样只作识别，不以巨大 Logo、泛化英文口号或未核验年度主题替代内容。不直接承载搜索、筛选、购物车、结算或购买控件，所展示作品可以进入统一作品详情。
- `/products` 是编辑式珠宝作品展陈，以高级海报、系列章节和可核验的材质工艺内容呈现作品；不承载搜索、筛选、排序或直接商城控件。正式公开时至少要有一个完整的已审核作品或系列章节；内容不足时应隐藏未准备好的入口，或发布一张有明确状态与顾问/选款下一步的体面短页，不得把大面积空白、编辑器 seed 或单独的“进入选款中心”当作作品展陈。页面中作为真实作品呈现的条目应进入统一作品详情；纯叙事或装饰媒体不得伪装成可点击商品。
- `/catalog` 是唯一的款式搜索、筛选、排序和快速选款中心，不是唯一购买入口；可以呈现来自业务事实源的必要销售状态和克制快捷行动，并把用户带到统一作品详情继续决策或交易。只有达到 `docs/UI_GUIDE.md` 定义的最低公开完整度、且当前允许公开的作品才能进入结果；缺少关键事实或有效主图的记录应留在后台待完善，不能用破图、乱码长名或成排占位符维持目录数量。
- `/products/:reference` 表示统一作品详情，以及服务或交易下一步的决策入口；路由参数的规范公开引用和旧链接兼容规则由技术合同维护，本文件不绑定数据库主键形式。详情必须达到与目录一致的最低公开完整度，并根据业务层解析出的 `SalesMode`、身份、资格和功能开关呈现一个清楚的主要下一步：`DISPLAY_ONLY` 联系顾问了解当前作品，`SELECTION` 将当前作品加入选款或继续选款，`APPOINTMENT` 携带当前作品信息发起预约鉴赏，`DIRECT_PURCHASE` 进入当前已批准的标准零售购买路径，`CUSTOM_INQUIRY` 携带当前作品信息发起高级定制需求。报价确认、下单或资金处理只有在对应状态机、权限和发布门禁实际具备时才能呈现，不得由模式名称推断已经可用。适用设计上的合作报价只对已审核且当前有效的合作商开放；合作身份和专属价格不属于 `SalesMode`。价格、库存、可见范围和交易资格必须来自对应业务事实源。
- `/custom`、`/about`、`/contact` 分别承担定制服务、品牌故事与预约联系，以品牌、服务和高级海报式叙事为主；`/contact` 可以提供完成预约所需的最小表单，三者不直接嵌入购物车、结算、购买或促销会场，但可以通过克制的作品链接进入统一详情。
- `/search` 只保留旧链接兼容并重定向到 `/catalog`，不得维护独立搜索结果、筛选或销售能力。
- 品牌叙事页可以使用克制的作品链接、预约鉴赏或咨询入口，但不得在叙事画面内堆叠价格、库存、加购、结算或强促销控件；交易信息和行动进入统一作品详情后再按商品类型、身份和开关呈现。
- 合作申请入口只放在“我的账户”及其合作服务区域，不进入品牌主导航，也不以供应商招募、批发或低价合作信息干扰公开品牌旅程。

“高级珠宝品牌级体验”是设计目标，不是对品牌历史、世家传承、认证、奖项或行业地位的事实声明。所有对外主张必须有可核验来源。

## 3. 业务与发布边界

- 展示、咨询、购物车、结算、支付、退款、库存与合作伙伴能力必须分别说明当前代码状态、验证环境和公开范围；不得用“电商已完成”概括所有能力。
- 交易开关、路由可见、接口放行、支付凭据就绪和生产业务批准是不同事实，不能互相替代。
- 未经明确上线批准，不得开启真实资金处理、生产第三方写入或发布未经核验的经营承诺。
- Mock、演示数据、代码路径存在或本地成功均不证明生产可用。
- 最小公开版本优先保证品牌展示、作品浏览、咨询转化、隐私与联系信息真实可靠；是否开放交易以单独发布决策为准。
- 内容生产必须保持制单与复核分离：`EDITOR` 只能保存草稿、预览和提交审核；只有 `ADMIN` 或 `SUPER_ADMIN` 可以审核并发布。预览、提交和发布都不得绕过同一内容真实性、权限与版本门禁。
- 行为分析只能在访客明确同意后写入；拒绝或尚未选择时不得创建分析标识或发送分析事件，撤回后停止后续写入。
- 客户通知的长期渠道为站内信、短信和邮件；物流轨迹通过快递100适配层接入。任何渠道都必须以偏好、同意、业务事件、发送状态与失败记录为依据，未配置或未启用时不得伪造成功。

## 4. 品牌与体验边界

- 客户前台品牌与体验细则只认 `docs/UI_GUIDE.md` 正文；管理后台排版、密度与无障碍细则只认其附录 A。其他治理文件不得复制色值、字号、间距或动画时长形成第二套规范。
- 页面装修器、CMS 内容和运营模板同样受品牌、真实性、版权、性能、响应式与无障碍门禁约束。
- 店铺装修的长期产品能力是可持续扩展的模板设计框架，而不是固定数量的成品模板。现有内置模板继续用于历史兼容和快速起步，但其数量、内容与完成度不定义产品边界、长期路线或全部模板工作的验收目标。
- 页面装修与模板设计是同一 Shared Editor Core 下的两种工作模式：模板设计定义完整根构图、槽位、样式、响应式和页面可编辑范围，并只使用系统生成的中性只读示例检查结果；页面装修负责向当前 Template Instance 写入真实文字、媒体、链接和业务引用。两种模式共享基础能力但隔离会话、写入对象和发布结果，具体规则只认 `docs/page-builder/template-design-framework.md`。
- 模板、页面和公开结果始终受品牌、内容真实性、版权、性能、响应式、无障碍与页面职责约束；起步样例、系统示例或历史兼容内容不得被冒充为正式公开内容。
- 管理后台以效率、信息层级、状态完整性和无障碍为先，不全局套用客户前台的大留白、衬线标题或展示动效。
- Logo、核心字体、品牌色、全局设计令牌和整体交互基调的变更属于品牌系统变更，必须明确审批并提供双端验收证据。

## 5. 内容、资产与信任

- 不得编造品牌历史、创始年份、传承、认证、奖项、材质、来源、工艺、产地、宝石等级、稀缺性、库存、销量、价格、保值能力或服务时效；不得使用虚假限量、倒计时、库存紧张或排队人数制造稀缺感。
- 公开品牌表达以作品、设计、材质、工艺和顾问服务为中心，不强调供应商身份，不使用“源头工厂”“厂家直销”“批发低价”“一手货源”等话术建立价值；确需披露的来源或合作事实必须真实、必要并符合对应受众权限。
- 图片、字体、视频、音乐、图标、代码和设计稿必须具备可追溯的商用授权；不确定时只能作为内部草稿。
- 带有第三方或竞品品牌名称、商标、包装、识别性文案或其他受保护元素的素材，未经可追溯授权不得公开。发现已公开的疑似侵权、授权失效、隐私或安全问题素材时，应优先以最快的可逆方式停止其公开暴露，再通过当前获批的内容发布流程完成替换、双端预览、发布前检查和公开复核。只在合法、必要且权限允许的范围内保留版本、操作记录和来源证据；不得通过无记录覆盖或删除掩盖历史，但权利人要求、法律义务、安全事件或获批的数据处置可以要求隔离或删除原文件。
- AI 生成素材不得作为真实珠宝、工艺、证书、佩戴效果或客户案例的证据。
- 客户数据只收集、读取和处理完成对应服务所需的最小范围；应用侧的身份、字段、同意与数据生命周期边界见 `docs/PUBLIC_ACCESS_MATRIX.md`，AI 与开发执行中的敏感信息规则以 `AGENTS.md` 为准。保存期限、删除或匿名化例外尚未批准时，不得宣称应用隐私治理已经形成完整闭环。

## 6. 维护原则

- 稳定原则写入本文件；当前实现、与现行基线的可验证差距及运行状态写入 `docs/CURRENT_STATE.md`，不得在状态文档重新定义方向；决策与理由写入 `docs/DECISIONS.md`；执行方法写入 `WORKFLOW.md`。
- 文档不得用“最近看起来如此”替代代码或运行证据；易变化的数字、开关和模块清单必须带核对日期。
- 旧规则若仍被工具引用，优先改成兼容入口或失效记录，不直接删除文件；确认零引用且经批准后才删除。
- 每条新规则应回答：解决什么风险、适用何处、如何验证、何时允许例外。无法回答的口号式规则不进入权威文件。
