### 身份与请求安全

- 后台员工 `User` 与前台客户 `Customer` 是两套身份域，服务端令牌必须带域标记并由对应守卫校验。
- 浏览器默认使用独立的 `HttpOnly` 会话 Cookie；写请求由共享客户端附加 `hc_csrf` 双提交值，并要求服务端通过精确 Origin 与 CSRF 校验。
- 服务端仍接受受控 Bearer access token 作为兼容入口；它不是浏览器默认持久化方案，不得把 access token 重新写入 `localStorage`。
- 角色、删除、归档和停用语义必须以服务端守卫、Service、Schema 与 `docs/PUBLIC_ACCESS_MATRIX.md` 共同核对，前端隐藏不是权限证明。

### 客户旅程连续性（2026-09-22 本地候选）

- Catalog 到作品详情现以一次性 SPA 内存上下文保存完整筛选 URL、页码、作品位置、滚动位置和进入方式；返回后在对应结果数据到位时恢复滚动，并聚焦原作品的详情入口或快速查看入口。越界页使用替换历史记录，分页和加载状态补充可访问名称、当前页、`aria-live` 与 `aria-busy`。该上下文不写入 `localStorage` 或 `sessionStorage`。本轮真实本地 Chromium 以“星云”筛选进入详情再返回，并覆盖快速查看进入路径，确认 URL、输入值、单条结果、滚动位置和原入口焦点均恢复。
- 联系页和选款咨询在阅读隐私说明前仅于当前 SPA 内存保存合理草稿，返回后不恢复隐私同意；刷新、关闭标签页或超时会失效。已发布定制内容指向高级定制咨询时，运行时会保留有效作品引用，不改写已发布文档。
- 普通咨询与选款咨询的客户安全回执保留兼容来源 `id`，并显式返回 `sourceId`、canonical `leadId`、状态和创建时间；统一 `/leads/:type/:id` 只按 `Lead.id + sourceType` 解析，显式旧来源入口才按来源 ID 解析，避免数字碰撞时操作错误咨询。两类咨询首次已成功落库但响应丢失后，同键同指纹重试都会先恢复原 canonical Lead，再决定是否需要检查当前作品可见性；同键异指纹在作品查询和写入前 409。登录客户恢复仍在事务内锁定并复核 `ACTIVE/authVersion`。回执跳入客户中心时，同一客户的权威 profile 回读只刷新资料，不再错误推进会话代次，因此并发的 canonical Lead 详情不会被误判为旧身份响应并永久停在 loading。匿名选款咨询未带 `Idempotency-Key` 的旧客户端兼容去重现要求完整规范化请求摘要与作品集合同时一致，不能再仅凭手机号和作品集合复用另一位提交者的回执；公开响应不返回内部摘要。
- 客户中心已有成功快照后，如果同页 Cookie 权威 profile 切换到另一 customer id，会先清除上一客户的订单、咨询、地址、通知、合作状态和 profile，再建立新身份并读取新快照；新客户核心读取失败时只显示没有可确认数据，不能继续展示旧客户私有记录或伪装成真实空订单。共享 HTTP 层现在对 GET 和写请求都在成功处理、401 refresh 与全局错误前校验发起时的 session epoch；A 客户迟到的通知已读 PUT 401 不会用 B 会话刷新、重试或退出 B，旧身份成功返回的写请求也不会进入新身份业务处理。结算页同样以 customer id 为会话边界：同页换号会重建购物车、资料、地址、优惠和在途 UI，旧账号迟到的结算成功响应不能写入新账号待支付状态。报价确认转单也绑定发起时的 customer session epoch、报价 ID 与版本：A 客户迟到的成功或失败不能在已切换的 B 客户界面回填订单、提示或焦点。Node `22.23.2` 下交易 UI 全文件 `30/30`、客户咨询整文件 `11/11`、后台身份隔离 `15/15`、报价合同整文件 `16/16`、`public-access` 整文件 `22` 项通过并有 `6` 项真实接口分层跳过。
