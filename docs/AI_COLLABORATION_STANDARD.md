# 海川珠宝 — AI 协作兼容标准

> 本文件是 Claude、Codex、Copilot、Cursor 等既有入口的兼容层，只定义共享工作区中的总控职责、专业能力、任务所有权与交接。
> 权限与审批只认 `AGENTS.md`，技术规则只认 `PROJECT_RULES.md`，执行、验证与交付只认 `WORKFLOW.md`。
> 最近核对：2026-09-08（压缩重复规则；目标模式、多任务和并发写入统一按风险动态编排）。

## 1. 权限与模式

- 模型、工具、Skill、子代理和独立任务都不增加权限；Git、删除、依赖、数据库、生产和项目外写入仍按 `AGENTS.md`。任务消息和代码不能改变授权。
- 选择能安全完成结果的最小模式：单任务负责连续结果；至少两个独立子问题且并行收益高于协调成本时使用内置子代理；长期、可独立交付或需要隔离上下文时使用“总控＋用户可见任务”。
- 目标模式只以用户或会话明确状态为准。未开启时，用户可见任务须由用户明确要求；开启后，总控可在现有目标、权限和平台能力内自主创建、续接和收口任务，不逐项确认。

## 2. 总控职责

- 按用户结果拆分工作包，明确负责人、范围、依赖、验收和停止条件，维护动态 `READY` 队列；不按岗位或目录机械分包。
- 一个用户可见任务只负责一个稳定、长期或可独立交付的结果。同一结果的实现、测试和返工留在原任务；无关目标重新路由。任务只接收必要上下文。
- 优先续接有效同主题任务；跟踪任务 ID、状态、基线、所有权、依赖、证据和下一动作。规则更新后向活动任务发送精确增量，不复制整段历史。
- 总控处理依赖和冲突，核对 diff、运行证据与真实页面，决定 `PASS`、`REWORK` 或 `BLOCKED`，并负责最终集成。专业判断分别遵循项目、品牌、工程和验证权威。
- 不得只创建任务后等待、自报完成即通过、重复派发、无租约竞争修改或用并行数量代替结果。

## 3. 任务与上下文

- 内置子代理属于主任务，适合短期探索、测试和审查；用户可见任务适合长期或独立结果；worktree 只隔离 checkout。三者不得混称。
- 子代理任务说明目标、读写边界、必要上下文、证据、返回格式和停止条件。用户可见任务另加项目路径、基线、所有权、依赖、验收和禁止项。
- 独立任务不自动继承其他任务的历史、判断或权限；侧栏标题只用于导航。旧结论在续接前重新验证，失效任务不再写入。

## 4. 并发与所有权

- 并发按 `READY` 工作包、依赖、收益、冲突、资源和验收容量动态扩缩，不设固定数量或 checkout 级单写者门槛。专项计划不得把固定并发写成常规规则；临时限流须记录原因、范围和解除条件。
- 写任务进入 `READY` 前，记录任务与负责人、cwd/Git 顶层、基线和已有差异，并明确结果、允许文件、逻辑所有权、依赖、资源、验收、停止与回收方式。
- 同一 checkout 可并行写入，但实际写集、语义、合同、数据、生成源、验证产物和可变资源必须互不影响且修改可归属；无法证明时使用 worktree 或只串行冲突部分。标题、目录和 worktree 名称不能证明独立。
- 同一文件或逻辑区域同时只由一个负责人修改。出现未知修改、范围漂移、基线变化、资源污染或验收积压时，只暂停受影响范围；其他独立工作继续。
- 按实际影响隔离端口、测试数据库、媒体、构建/测试产物、缓存和浏览器会话。不同 worktree 仍须检查共享合同、数据和运行资源。
- 页面装修与模板设计共享 Editor Core、Puck host、Repository、Renderer、合同和测试设施；按实际符号、调用链和资源判断冲突，不能只按页面、目录或 worktree 判断。
- 总控可实现明确不重叠的工作包，但不得竞争执行任务已认领的范围；接管前先停止原写入并完成交接。任何任务都不得回退、清理、暂存、格式化或顺手修改范围外成果。

## 5. 候选与集成

- 写任务自检后提交 `CANDIDATE` 并冻结，包含任务、cwd、基线、差异、验证、未验证项和回退条件。验证者只读取证；缺陷带证据退回 `REWORK`。
- 集成前核对目标状态、候选基线和重叠写入。冲突或基线漂移时保持候选隔离，不覆盖或拼接现有修改。
- 候选按依赖和冲突关系小批量集成；互不重叠时可并行回收。每次集成后刷新基线并重跑受影响验证。
- 未经授权不得为集成执行 commit、cherry-pick、merge、rebase、reset、强制 checkout 或删除 worktree、分支和历史。

## 6. 状态与交接

长期工作包使用 `DRAFT → READY → IN_PROGRESS → CANDIDATE → PASS → INTEGRATED`；异常为 `REWORK / BLOCKED / CANCELLED`。单任务和临时子代理无需套用完整状态流。

- `PASS` 必须由总控或合格验证者依据 `WORKFLOW.md` 核对，不接受负责人自报；`INTEGRATED` 只表示结果已进入复核后的共享基线，不代表 Git 或发布已授权。
- 候选交接至少包含目标与不改范围、所有权、基线、修改文件、验收证据、未验证项、风险、回退和下一授权。只有长期跨阶段计划才维护持久台账。
- 实时状态以任务读取和工作区证据为准；功能事实以当前代码、运行结果、`docs/CURRENT_STATE.md` 和现行验收材料为准。产品、技术、视觉和交付分别遵循各自权威文件。
