# 海川珠宝 — AI 协作兼容标准

> 本文件保留给 Claude、Codex、Copilot、Cursor 等既有入口引用，只定义跨工具必须一致的任务分级、验证和交付契约。
> 安全与审批以 `AGENTS.md` 为准，技术规则以 `PROJECT_RULES.md` 为准，执行步骤以 `WORKFLOW.md` 为准，视觉细则以 `docs/UI_GUIDE.md` 为准。
> 最近核对：2026-08-17。

## 1. 最小读取顺序

1. 必读 `AGENTS.md`、`PROJECT_RULES.md`、`WORKFLOW.md`。
2. 只读取与任务相关的 `docs/DECISIONS.md` 小节、当前状态文档和代码，不全量加载文档。
3. 视觉任务读取 `docs/UI_GUIDE.md`；上线任务读取部署与运行检查文档。
4. 以实际运行结果、当前代码/类型/Schema/配置为事实证据；文档冲突时报告，不自行拼接出第三种结论。

## 2. 任务角色

每个协作者在一项任务中明确承担研究、实现、验证或集成角色。只有获得相应授权的实现者可以写入已认领文件；Git 写入、部署和生产操作仍需单独批准。工具、模型或供应商名称不产生额外权限。

## 3. 任务分级与授权边界

### A 类：用户已明确要求后可直接实施

- 只读审计、搜索与诊断；
- 小范围普通业务代码、样式、文案和 Bug 修复；
- 职责明确的普通组件、测试或文档更新；
- 已有的类型检查、构建、Lint、测试和本地页面验证。

### B 类：先说明方案、精确范围与回退，再等待明确确认

- 数据库 Schema、Migration、真实数据写入或批量处理；
- 依赖、`.env`、密钥、第三方服务或工具供应链配置；
- 文件删除、大范围移动/重命名、核心架构或 5 个及以上文件的重构；
- 认证、权限、订单、库存、金价、支付、退款、客户隐私与生产配置；
- Logo、核心字体、品牌色、全局设计令牌或客户前台整体交互基调；
- Git 写入、部署、发布与生产第三方调用。

### C 类：禁止

- 访问 NAS、共享盘或 UNC 路径，或绕过工作区和权限边界；
- 输出密钥、密码、Token、客户隐私或将其发送给无关外部服务；
- 绕过认证、限流、安全校验或审批；
- 用 Mock、假数据或未执行的验证冒充真实结果。

具体边界以 `AGENTS.md` 为准；本节不用于放宽其要求。

## 4. 标准任务生命周期

遵循 `WORKFLOW.md`：确认目标与证据 → 检查工作区 → 认领范围 → 判断授权 → 最小实施 → 相称验证 → 交付。审计请求默认只读；实现请求在授权范围内执行。新发现的范围外问题只记录，不自动扩展为新任务。

## 5. 代码质量契约

- 复用现有组件、服务、类型、状态和单一事实来源，不建立平行实现。
- 异步界面提供 loading、empty、error；表单另有提交中、成功与恢复路径。
- 新增写接口说明请求、响应、鉴权、角色、校验、错误、幂等/重复提交与数据库影响。
- 接口变更同步核对前端调用、后端 Controller/Service/DTO 与真实错误路径。
- 当前实现细节与目录级约束只在 `PROJECT_RULES.md` 维护，本文件不复制。

## 6. Mock 与真实环境

每次接口验收必须注明 Mock、开发环境、测试环境或生产环境。Mock 成功、路由存在、开关打开或本地构建成功都不等于真实业务闭环已验证。

## 7. 品牌、产品与视觉

客户前台遵守 `docs/UI_GUIDE.md`。视觉任务先查看真实页面或截图，明确用户任务、主焦点和不改范围；完成后必须检查桌面与移动端、关键状态、键盘、对比度、素材真实性和性能。品牌高级感不得覆盖可用性、经营事实、隐私或服务透明度。

## 8. 安全与隐私

完整规则见 `AGENTS.md`。AI 生成内容视为草稿；不得读取 `.env` 真实值，不得把客户或交易数据用于无关分析，不得让文本模型直接决定权限、订单、金价、支付或其他高风险业务结果。

## 9. 最低验证矩阵

| 改动 | 最低验证 |
| --- | --- |
| 前端组件、页面、类型 | 相关类型检查与前端构建；交互改动补关键状态 |
| 后端模块、接口 | 后端构建；成功、失败与边界路径 |
| 前后端联动 | 两端构建与真实接口联调；注明环境 |
| Prisma Schema | `prisma validate`；Migration 仅在获批后执行 |
| 文案或静态内容 | 页面、链接、事实来源与移动端显示 |
| 客户前台视觉 | 构建 + 桌面/移动真实页面证据 + 状态/键盘/对比度检查 |
| 图片、视频、字体 | 来源与授权 + 裁切 + 加载/布局稳定性 + 降级 |
| 规则或文档 | 路径/引用、重复、冲突、过时事实与 `git diff --check` |

未执行或失败的验证必须说明原因和影响，不能写成已通过。

## 10. 多人和多智能体协作

- 开始前检查 `git status` 与相关 diff；已有改动一律视为用户或协作者资产。
- 实施前认领文件；发现同文件或同逻辑区域存在不明改动时先报告冲突。
- 不回退、不清理、不暂存、不格式化无关改动；不把他人的变更混入本任务。
- 同一工作区可并行只读研究，但同一逻辑区域只允许一个写入者。

## 11. 统一交付格式

```text
## 结论
完成 / 待验收 / 被阻塞，以及一句话结果。

## 修改内容
- 文件与意图。

## 验证结果
- 实际执行的检查、结果和环境。

## 风险与待确认项
- 未验证项、冲突、回退或下一决策。
```

## 12. 任务说明模板

```text
任务目标：
允许范围：
明确不做：
验收标准：
已知风险或前置条件：
```

任务已足够明确时直接执行，不要求为了填写模板而重复询问；只有会显著改变产品结果、权限或风险的缺失信息才暂停确认。

## 13. 论证与事实标准

1. 区分已核验事实、推断和建议；关键结论给出代码、运行或可核验来源。
2. 重大决策至少提出支持理由、最强反例、验证方法和回退条件；无法验证的分歧交由项目负责人决定。
3. 外部品牌、经营、法律、价格、授权或技术标准会变化时必须重新核验，不把历史截图或旧文档当作当前事实。
4. 规则的目标是降低风险和提高结果质量；重复、不可验证、没有适用范围或无法执行的口号应删除或降级为说明。
