# 海川珠宝 AI 协作开发标准

> 适用对象：项目负责人、人工开发者，以及 Codex、DeepSeek、Claude、Copilot、Cursor 等所有 AI 开发工具。
> 目标：让不同协作者在同一项目中保持一致的事实来源、变更边界、质量标准和交付方式。

## 1. 使用方式与优先级

每个协作者开始任务前必须遵循：

1. 阅读 `AGENTS.md`，遵守安全、权限、工作区和敏感信息规则；
2. 阅读 `docs/PROJECT_GUARDRAILS.md`，了解项目不可擅自改变的边界；
3. 按任务需要读取下列相关文档，而不是一次性读取全部文档：
   - 项目与现状：`docs/PROJECT.md`、`docs/CURRENT_STATE.md`；
   - 架构与模块：`docs/ARCHITECTURE.md`、`docs/MODULES.md`；
   - 数据与接口：`docs/DATA_AND_API.md`；
   - 视觉与体验：`docs/UI_GUIDE.md`、`docs/design-qa.md`；
   - 开发流程：`docs/DEVELOPMENT_WORKFLOW.md`；
4. 再读取本次任务相关代码、类型、接口和测试。

规则优先级从高到低：安全规则 → 项目基线 → 本协作标准 → 详细项目文档 → 单次任务需求。

当文档、代码和需求相互矛盾时，不得猜测；必须指出冲突，说明证据，并等待项目负责人决定。

## 2. 项目事实基线

项目为高端珠宝展示、商品管理、品牌内容管理和选款咨询平台，当前不开放真实支付与资金交易。

固定技术栈：

- 前端：React 18、TypeScript、Vite、Ant Design 5、Tailwind CSS、Zustand；
- 后端：NestJS 10、Prisma 5、MySQL 8、Redis、Bull；
- 认证：JWT + bcrypt；
- 图片处理：Sharp；
- 内容编辑：现有 EditorWorkbench 与 Puck 页面构建器相关代码。

未经明确确认，不得替换技术栈、迁移框架、升级依赖、删除核心目录或改变项目定位。

## 3. 任务分级与授权边界

### A 类：可在用户明确提出需求后直接实施

- 读取、搜索、审计项目文件；
- 小范围业务代码、样式和文案修改；
- Bug 修复；
- 新增职责明确的普通组件、页面或服务代码；
- 已有脚本的类型检查、构建、Lint 和测试；
- 更新与实际代码一致的项目文档。

### B 类：必须先给方案，等待明确确认

- 修改数据库 Schema、执行 Prisma Migration；
- 安装、升级、删除依赖或修改 `package.json`；
- 修改 `.env`、密钥、第三方服务配置；
- 删除文件、大范围移动或重命名；
- 一次影响 10 个以上文件；
- 认证、权限、订单、支付、金价、客户隐私等核心业务改动；
- 替换页面构建器或其他核心架构；
- Git add、commit、push、rebase、reset、restore；
- 部署、发布或调用生产第三方服务。

### C 类：禁止执行

- 访问 NAS、共享盘、UNC 路径或项目目录外的文件；
- 输出真实 API Key、Token、密码或客户隐私；
- 绕过权限、限流、安全校验、审批流程；
- 将 Mock 数据伪装成真实业务结果；
- 未经授权开启支付、真实交易或生产写入。

## 4. 标准任务生命周期

每项任务必须按以下顺序推进：

```text
接收任务
  → 明确目标、边界和验收标准
  → 读取最小必要的文档与代码
  → 检查当前 Git 状态（只读）
  → 输出方案与影响范围
  → 必要时等待确认
  → 实施最小改动
  → 验证
  → 汇报结果与遗留风险
```

不得把需求分析、架构重构、数据库变更、代码实现和文件清理混成一个未经确认的大任务。

开始实施前必须回答：

- 当前问题是什么，证据在哪里；
- 本次要修改什么；
- 本次明确不修改什么；
- 会影响哪些文件、接口、数据和用户流程；
- 存在哪些风险、前置条件或待确认事项；
- 如何判断任务完成。

## 5. 代码变更标准

### 前端

- 新增或修改异步界面必须处理 loading、empty、error 三态；
- 表单必须有字段校验、提交中状态、成功反馈和失败提示；
- 不得用空白页面、随机数据或静默失败掩盖错误；
- 优先复用现有组件、类型、Hooks、服务层和状态管理；
- 不新增无类型的 `any`；确实无法避免时必须说明原因和收敛范围；
- 不得在页面组件中复制大段接口转换或业务逻辑，应放入服务、Hook 或工具函数；
- 所有面向用户的文案必须使用简体中文，不能编造品牌与商品事实；
- 页面视觉遵循 `docs/UI_GUIDE.md`，并在桌面与移动端验证。

### 后端

- Controller 只负责路由、鉴权、参数接收和响应；
- Service 负责业务规则；数据库读写通过 Prisma Service；
- 新增输入必须使用 DTO 和 `class-validator` 校验；
- 新增写接口必须考虑鉴权、角色权限、非法参数、重复提交和异常返回；
- 不得在 Controller 或日志中输出密码、Token、客户隐私或完整第三方响应；
- 不得以 `(this.prisma as any)` 作为新增功能的常规实现方式；
- 修改接口时，同步检查前端 `client/src/services/api.ts`、调用页面及后端 Controller、Service、DTO。

### 数据与接口

统一响应结构保持：

```json
{
  "code": 200,
  "data": {},
  "message": "success",
  "timestamp": "..."
}
```

每个新增或变更接口必须在方案中说明：路径、方法、请求字段、响应字段、鉴权、角色限制、校验、错误情形及是否写入数据库。

数据库 Schema 或 Migration 只能在获得明确同意后修改和执行。

## 6. Mock、真实接口与真实数据

- Mock 仅用于前端开发和演示；
- Mock 返回成功不代表真实接口已完成；
- 真实接口不可用时，必须向用户展示可理解的错误或降级状态；
- 不得在真实接口失败时自动返回随机成功数据；
- 每次涉及接口的任务，必须说明当前使用 Mock 还是真实接口；
- 上线前必须在 `VITE_USE_MOCK=false` 的真实接口环境做联调验证。

## 7. 视觉、内容与可访问性标准

- 视觉方向：高端、克制、东方、现代；避免廉价渐变、过度圆角、无意义动画和模板化卡片；
- 颜色、字体、间距和布局优先复用既有设计令牌与 `docs/UI_GUIDE.md`；
- 新增图片需提供 alt 文本；交互控件必须可聚焦，不能只依赖颜色传达状态；
- 关键流程至少检查 1440、1024、768、390 像素断点；
- 视觉改动完成后，构建成功不等于完成，必须做截图或实际页面验收；
- 文案和素材只能使用已提供或已确认的事实；未确认内容必须标为草稿或占位。

## 8. 安全、隐私与 AI 使用规则

- 不读取或输出 `.env` 真实值；只允许检查变量名或示例结构；
- API Key 只能存在于服务端环境变量，绝不能进入 `client/`、浏览器端代码、文档或日志；
- 客户姓名、电话、地址、邮箱、咨询正文、订单信息不得发送到外部模型进行无关处理；
- AI 文案、分类、摘要等结果均为草稿，必须经业务确认；
- 文本模型不得未经验证直接取代图片识别、权限、订单、金价或支付逻辑；
- 所有 AI 调用必须有失败处理、调用超时与清晰的用户提示。

## 9. 验证标准

验证必须与改动类型匹配：

| 改动类型 | 最低验证 |
| --- | --- |
| 前端组件、页面、类型 | TypeScript 检查和前端构建；视觉改动增加断点检查 |
| 后端模块、接口 | 后端构建；必要时调用相关接口验证 |
| 前后端接口联动 | 前后端构建及真实接口联调 |
| Prisma Schema | `prisma validate`；Migration 仅在获批后执行 |
| 文案或静态内容 | 页面核对、链接核对、移动端显示检查 |
| 规则或文档 | 检查链接、路径和描述是否与代码事实一致 |

验证失败时必须如实报告失败原因、影响范围和下一步建议，不能声称任务完成。

## 10. Git 与多人/多 AI 协作

- 每次任务开始前执行只读 Git 状态检查；
- 工作区已有改动默认属于其他协作者或用户，不得覆盖、还原、删除、暂存或混入本次任务；
- 只修改本任务已确认的文件；
- 不得把格式化、无关重排或自动生成文件混入功能改动；
- 代码与文档使用 UTF-8 编码；
- 接口、Schema、路由或项目规则变更后，必须同步更新相关文档；
- Git 写入操作必须由项目负责人明确批准后执行。

## 11. 统一交付格式

所有 AI 和开发者在任务完成时，按以下格式报告：

```text
## 结论
一句话说明任务是否完成。

## 修改内容
- 文件路径：做了什么、为什么。

## 验证结果
- 执行的命令或人工检查；
- 成功、失败或未执行的真实结果。

## 风险与待确认项
- 尚未解决的问题；
- 需要项目负责人决定的事项。
```

## 12. 给任何 AI 的任务模板

```text
请遵守 AGENTS.md、docs/PROJECT_GUARDRAILS.md 和 docs/AI_COLLABORATION_STANDARD.md。

任务目标：
{用一句话描述要实现或审计的目标}

范围：
{允许涉及的页面、模块或文件}

明确不做：
{数据库、依赖、支付、删除文件等限制}

验收标准：
{用户看到什么结果才算完成}

先阅读最小必要的相关文件，输出“现状与证据、最小方案、影响文件、风险、验收标准”。
除非我明确说“开始实施”，否则不要修改代码。
```
