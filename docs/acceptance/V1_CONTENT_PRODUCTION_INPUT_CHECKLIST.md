## 1. 分层验收定义

| 层级 | 通过条件 | 证据边界 |
| --- | --- | --- |
| CODE_READY | 冻结候选通过对应工程门禁及批准范围的真实联调 | 记录版本、环境、身份、数据来源与未覆盖项；本地或隔离数据库结果不证明目标库已迁移 |
| CONTENT_READY | 正式主体、联系方式、作品、品牌内容和媒体授权签认，并完成对应内容版本的桌面/移动验收 | 内容版本与候选公开范围一致；草稿和测试素材不作为正式内容 |
| PRODUCTION_READY | 对同一候选完成目标环境、TLS、持久化、告警、恢复、外部服务与回退实证 | 先生成签名制品，再受控部署取证；不由配置存在推断环境通过 |
| RELEASE_READY | 上述三层证据与批准范围一致，发布负责人作出具体候选 Go/No-Go | 表示具备公开放量条件；实际上线还须记录放量结果和上线后验收 |

## 9. 推荐交付顺序

1. 先交正式主体、联系方式、隐私责任人与客服负责人。
2. 再交分类、作品事实和逐媒体授权记录。
3. 在已批准的内容准备环境通过现有后台逐项录入、预检和发布对应内容版本；此处内容发布不等于生产公开放量，不直接批量写真实数据库。
4. 完成桌面 1440×900 与手机 390×844 的正式内容浏览器验收，关闭 CONTENT_READY 缺口。工程门禁、冻结候选和签名制品准备可以并行推进，不以内容全部就绪作为生成 manifest 的前置条件。
5. 按 [发布手册第 5 节](../PRODUCTION_RELEASE_RUNBOOK.md#5-发布与回滚判定树) 核对唯一环境、制品与部署前条件，准备 migration、配置、部署、备份恢复和回滚方案；当前有效授权已精确覆盖的动作直接执行，未覆盖的受控动作集中申请。
6. 先生成并验证正式 release manifest，再执行获批的受控部署；在尚未公开放量的状态取得同一候选的目标环境与真实业务证据。只有 CODE_READY、CONTENT_READY、PRODUCTION_READY 全部通过并获得对应放量批准，才判定 RELEASE_READY、公开放量并进行上线后验收。
