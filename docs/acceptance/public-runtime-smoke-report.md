## 缺陷与复现

### P1-1：隐私同意必填提示缺失（已修复，保留原始发现）

- 路由：`/contact`
- 影响视口：桌面 `1440 × 900`、移动 `390 × 844`
- 复现步骤：
  1. 以匿名新上下文进入 `/contact`。
  2. 不填写或勾选任何字段，点击语义名称为“提交需求”的按钮。
  3. 观察各必填项反馈。
- 预期：当未勾选“我已阅读并同意隐私说明”时，页面应提供与其他必填项同等清晰、可见的错误说明，例如“请阅读并同意隐私说明”。
- 初次实际：姓名、手机号、咨询类型、方便联系时间、需求描述均出现文字错误；隐私同意项仅改变标签颜色，未出现可见错误文字。桌面与移动端复现一致。
- 浏览器证据：页面无 `pageerror`；空提交场景未产生非 GET `/api` 请求，因此未提交任何咨询数据。
- 修复：`client/src/pages/public/Contact/index.tsx` 在既有 `errors.privacyConsent` 存在时，渲染可见的“请阅读并同意隐私说明”文本（`role="alert"`），并以 `aria-describedby="cf-privacy-consent-error"` 和 `aria-invalid="true"` 关联复选框。
- 复验：桌面 `1440 × 900` 与移动 `390 × 844` 均已看到该提示；错误元素 ID 为 `cf-privacy-consent-error`，复选框 ARIA 属性匹配；两种视口均未产生非 GET API 请求，且无 `pageerror`。

## 运行时观察

- 所有已记录路由均未捕获浏览器 `pageerror`。
- 商品接口返回 410 时，目录、搜索与详情页均以文字错误态或“当前暂不可浏览”降级，未出现空白页。
- 页面装修内容会影响首页可见文案，故首页验收采用页眉、主区域和无横向溢出的稳定语义证据，而未把某个固定营销标题当作必需内容。
- 当前实现的联系页标题/按钮为“提交咨询需求”/“提交需求”；现有部分测试仍使用“预约私人顾问”/“提交预约”的旧文案，若直接运行这些旧断言会产生非功能性失败，应在后续测试维护中统一基线。

## 复现命令

在 `client` 目录启动本地前端服务后，可用 Playwright 的 Chromium 以独立上下文访问上表 URL，使用：

```text
npm run dev -- --host 127.0.0.1 --port 5174
```

复现时使用桌面 `1440×900` 与移动 `390×844` 视口；对每个 URL 断言 `banner`、目标角色/文本、最终 URL，并断言 `document.documentElement.scrollWidth <= document.documentElement.clientWidth`。联系页只点击空表单的“提交需求”，不得填入真实资料或继续提交。
