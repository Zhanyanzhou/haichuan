# 历史已发布 Puck 页面内容审计与下线清单

> 适用对象：后台运营、内容审核与业务确认人员。
> 适用范围：所有已经发布、可能被访客访问的 Puck 页面及其发布快照。
> 文档性质：**操作清单，不是已完成的审计报告。**本文不表示任何历史页面已经检查、修改或下线。

## 1. 目的与重要边界

本清单用于逐页排查历史已发布页面中的高风险文案、商品引用、素材、链接和转化入口，并在确认前阻止不准确或无证据的内容继续对外展示。

本次系统收敛已经带来两项保护：

- 新发布页面会校验所引用商品必须同时满足 `PUBLISHED`、`PUBLIC` 且未删除；不满足时无法发布。
- 当前默认内容已安全化，活动等待确认内容应使用“待确认”类中性提示，而不是自动带入具体承诺。

**这两项保护不会自动改写已经存入数据库的历史 Puck 文档或其已发布快照。**历史内容可能保留旧文案、旧商品 ID、旧图片或旧链接，仍须由运营人员按本清单逐页打开、核对、保存草稿并重新发布。

系统发布校验是最低技术门槛，不能替代业务、法务、品牌和素材授权审核；例如，能通过 URL 格式校验的外链仍可能失效、越权、误导或未经授权。

## 2. 后台入口、可证实系统能力与人工责任

### 2.1 后台入口

- 使用已获授权的后台账号进入页面构建器，当前路由为 `/admin/editor/:pageKey`；旧入口 `/admin/homepage` 会跳转到首页编辑器。
- `:pageKey` 由后台当前可选页面决定。不要根据本文虚构页面标识、公开 URL、版本号或区块；在获授权的后台中逐页确认实际页面。
- 编辑器提供桌面端、平板端和移动端画布尺寸；工具栏“预览”只切换当前内存画布，不会保存草稿或发布。运营必须以明确的“页面草稿已保存”或“页面发布设置已保存”反馈判断持久化成功，不能把进入/退出预览当作保存证据。

### 2.2 代码已保证与运营仍需确认

| 事项 | 代码已保证（当前实现） | 运营仍须逐页确认，代码不能替代 |
| --- | --- | --- |
| 草稿与并发 | 保存会把页面写为草稿；发现其他编辑者更新时会拒绝覆盖并提示重新加载 | 保存成功后，确认编辑的是目标页面、没有遗漏本地更改，并协调其他编辑者 |
| 发布设置保存 | 内容负责人、SEO 与素材授权通过同一 PageDocument 草稿接口保存；保存期间锁定设置表单，成功才关闭抽屉。失败时保留字段并把页面标记为未保存，刷新/关闭继续受离开保护 | 错误提示后核对字段仍在，排除网络或并发问题再重试；不得因抽屉曾打开或按钮曾点击就记录为已保存 |
| 发布前预检 | 编辑器调用服务端预检；服务端校验 Puck 数据结构、可见内容、区块 ID、必要图片、资源/链接格式、视频、轮播、活动结束时间、商品引用，并要求每个当前公开素材 URL 有来源与授权编号 | 预检只能证明记录完整，不能证明填写的来源、授权编号或证据真实有效；仍须核对原始授权材料与适用范围 |
| 商品公开性 | 发布校验会拒绝不同时满足 `PUBLISHED`、`PUBLIC`、未删除的被引用商品 | 每个商品仍须核对名称、图片、描述、CTA、价格展示及专题适配性；不得把可访问 ID 当作公开授权 |
| 发布快照 | 发布会创建新的已发布版本，公开读取的是已发布快照而非后台草稿 | 发布后仍须用实际公开访问路径核对当前版本、显示效果与跳转结果 |
| 版本历史、载入草稿与线上回滚 | 后台先读版本摘要，再读取单版本可信详情；“载入当前草稿”只替换当前内存编辑状态，显式保存前不写服务端。线上回滚是另一项独立操作 | 载入后可撤销/重做，仍须显式保存、重新审计、预览、预检并发布；线上回滚只用于切换已发布指针，不覆盖当前草稿 |
| 默认内容 | 当前默认内容已安全化，待确认场景应使用中性提示 | 历史 Puck 文档和既有发布快照不会被自动改写，必须逐页人工清理或确认 |

### 2.3 权限、校验、历史载入与线上回滚边界

端点、角色、预检/发布调用链、历史载入、草稿保存、乐观并发和线上回滚的当前实现只在[页面构建器实现边界](../architecture/page-builder-boundary.md)维护。本清单只保留运营需要执行和停止的动作：

- 前端路由和按钮不是最终权限证明；以服务端守卫、角色声明和实际响应为准。
- `EDITOR` 可以按现行权限编辑、保存和预检；只有获准角色可以发布。精确角色以当前服务端代码和访问矩阵复核。
- 历史载入只进入当前内存编辑状态；取消或刚载入时不写服务端。采用后仍须显式保存、重新预检并发布。
- 线上回滚只切换已发布指针，不覆盖当前草稿，也不能替代载入后的保存流程。
- 遇到 409、保存失败、权限异常或版本不一致时立即停止，刷新并重新核对基线；不得反复覆盖、删除版本或共享账号规避冲突。

以上是操作边界，不证明真实路由、账号、数据库、缓存、事件传播或多人并发已经通过；正式操作前仍须在获批环境取得新鲜证据。

## 3. 操作员逐页循环标准流程

对每一个实际存在的已发布页面，严格按以下顺序完成；上一页未完成记录前，不要将“已浏览”标为已审计。

1. **定位页面。**在页面构建器选择目标页面，记录页面标识、公开 URL、当前已发布版本（如后台可见）、审计人和开始时间。先打开版本历史，确认是否存在可用的已审核版本；此时不恢复、不发布。
2. **先保存草稿。**先执行“保存草稿”，等待明确的成功提示。若出现并发冲突、保存失败或权限异常，停止该页处理并移交开发/管理员，不要继续发布或用其他页面草稿替代。
3. **完成区块检查与授权登记。**从首个可见区块到最后一个可见区块，以及所有插槽/数组项，按第 5 节检查文案、商品、素材、链接和活动信息；在“发布设置”的“媒体来源与授权”区域逐项填写可追溯来源和授权/存档编号。每发现一项问题立即写入第 8 节记录模板，并选择下线、改为中性表述或等待书面证据。
4. **预览。**在编辑器中依次检查桌面端与移动端；可同时检查平板端。预览只读取当前内存草稿，不会代为保存或发布；进入预览前应确认第 2 步的保存已成功，预览期间的新增修改仍须显式保存。检查素材裁切、文字可读性、热区/轮播、CTA、空态和错误提示；预览仅用于检查当前草稿，不等同于公开页面。
5. **发布前预检。**点击发布前的预检/发布操作，查看服务端返回的全部问题。预检报错时，定位对应区块、修复或下线后重新保存草稿并再次预检；不得绕过或忽略报错。预检通过后仍须完成业务事实和授权复核。
6. **发布。**仅当第 10 节通过标准全部满足时，在确认发布对话框中发布当前草稿。发布会更新公开快照；发布后立刻记录新发布日期和版本信息（如后台可见）。
7. **公网复核。**使用该页实际公开 URL，在未登录或符合公开访问范围的浏览器环境中复核。确认页面更新、商品可见性、链接、CTA、图片、移动端和活动日期正确；不读取接口响应、不将测试数据写入真实业务系统。
8. **完成记录。**补全第 8 节每一行的处理方式、证据/确认人、复核人和发布日期；若有待补材料，标明责任方、截止时间和当前页面是否已下线/保留草稿。

**停止条件：**任一步出现保存失败、预检失败、事实/授权无法确认、可能泄露非公开信息、异常跳转或公开复核不一致时，停止发布。先保留草稿和审核记录，再按第 9、11 节处理。

## 4. 审计前准备

1. 从后台页面构建器列出全部已发布页面，按页面标识、公开 URL、最近发布日期、负责人建立待审清单；不要据此文档猜测数据库中存在的页面或区块。
2. 每次只处理一个页面：先记录当前已发布版本和公开 URL，再进入编辑器查看该页全部主内容区及插槽（如有）。
3. 在桌面和移动预览中逐块检查下表项目；对每项异常记录区块顺序、区块 ID（如可见）和截图或书面凭证编号。
4. 发现可能违法、误导、侵权、泄露非公开信息或无法立即确认的内容时，优先将该区块设为不可见或改为中性内容，保存为草稿；未完成复核前不要重新发布。

## 5. 逐页审核主清单

下列项目应检查页面标题、正文、眉题、按钮、图片内嵌文字、替代文字、热区标签、轮播项、商品关联、地图链接，以及所有区块和插槽中的数组项。不能只检查首屏。

| 审计类别 | 逐项检索与复核内容 | 可接受条件 | 不通过时的处理 |
| --- | --- | --- | --- |
| 价格与折扣 | 价格、起售价、到手价、优惠、满减、会员价、折扣比例、赠品、赠券、礼遇 | 有适用商品、适用条件、有效期和业务书面确认；不与当前公开商品规则冲突 | 无法完整证明：**下线**相关区块或改为“价格与活动请咨询顾问”等中性表述；有证据后再补齐并重新发布 |
| 限时与倒计时 | “限时”“仅剩”“截止”“倒计时”、目标日期、活动权益、数量/库存紧迫性 | 真实且未过期的活动日期、时区、规则、范围和负责人确认一致 | 过期、日期无效或证据不足：下线活动区块；或删除倒计时、改为中性常规内容；补齐书面活动规则后再发布 |
| 保养、维修、退换与服务承诺 | 保养周期、免费维修、终身、退换条件、售后范围、服务保障 | 与现行售后政策完全一致，并有业务/法务书面确认 | 下线承诺，或改为“具体服务范围以书面确认/咨询结果为准”的中性表述；补齐政策证据后重新发布 |
| 包邮、保价与配送 | 包邮、顺丰/保价、配送时效、签收、保险与风险承担 | 明确适用地区、金额、商品、时段和责任边界，并有履约确认 | 下线或移除具体承诺；补齐配送规则与责任人书面确认后重新发布 |
| 鉴定、证书与材质 | “权威”“国检/国际证书”、成色、产地、宝石等级、认证机构、证书图片 | 每个具体宣称能对应有效业务证据，且证书图片可公开使用 | 下线该证书/宣称，或改为不作具体认证承诺的中性描述；补齐可公开证据与确认人后重新发布 |
| 具体工期与定制流程 | “X 天交付”“现货”“加急”、选石、设计、打样、交付流程 | 工期与流程适用于当前业务，包含前提条件，且已获得履约方确认 | 删除具体天数/保证语，或下线区块；补齐书面服务范围、适用条件和确认人后重新发布 |
| 地区、门店与联系信息 | 门店名称、地址、营业时间、电话、地图、可到店/服务地区 | 与当前实际营业信息一致，地图跳转正确且不泄露内部地点 | 下线错误门店信息或改为“联系顾问确认”；经门店负责人确认后更新并重新发布 |
| 客户案例、评价与实拍 | 客户称呼、购买信息、评价、案例故事、顾客图片、前后对比 | 已获得可公开的书面授权；事实可核；不泄露个人信息或夸大效果 | 无授权或无法核实：立即下线评价/实拍区块或替换为无个人信息的中性品牌内容；补齐授权后再发布 |
| 外链与 CTA | 所有按钮、文本链接、轮播链接、热区链接、地图链接、电话/预约入口 | 指向预期、可访问、适合公开用户且文案与落地页一致；无钓鱼、追踪泄露、失效或越权页面 | 下线链接或改为不跳转；修复为已确认的站内/公开目标后重新发布 |
| 图片、视频与版权 | 主图、移动图、轮播、证书、门店、实拍、视频封面、图片内文字和替代文字 | 有使用授权或自有权利；来源、授权范围、有效期可追溯；内容与文案一致 | 无授权、来源不明或不适配：下线区块/素材，或以已授权素材替换；记录授权证据后重新发布 |

### 商品引用公开性复核（每个关联商品均须执行）

适用于“产品展示行”“单品焦点推荐”“佩戴灵感”及任何可跳转到商品详情的区块。

- 在后台商品管理中逐个核对关联商品，确认其状态为 **`PUBLISHED`**、公开范围为 **`PUBLIC`**、且**未删除**。
- 同时确认商品名称、图片、描述、价格展示和 CTA 与页面文案相符；不要只因 ID 有效就认定商品可公开。
- 任一商品不满足公开条件、已下架、资料待核或不适合当前专题时：从页面关联中移除，或将整个导购区块设为不可见；保存草稿并在预览中确认空态不会留下错误入口后再发布。
- 不要把会员、合作商家或内部可见的商品放入可公开访问的 Puck 页面；页面隐藏不能替代商品公开范围校验。

## 6. 区块与展示状态专项检查

除第 3 节外，对每个可见区块完成以下检查：

- **图片与视频：**桌面图、移动图、焦点位置、裁切、替代文字、加载失败时的显示，以及图片中文字是否仍完整可读。
- **活动日期：**限时活动的结束时间使用真实 ISO 日期时间；发布当天、到期前后均确认倒计时和过期降级文案正确。
- **CTA：**按钮文字不承诺当前不能提供的购买、支付、配送、退款或售后能力；预约/咨询入口可用，落地页能解释下一步。
- **移动端：**在移动预览逐屏检查标题截断、按钮可点击、热区命中、图片裁切、轮播和倒计时；同时确认桌面端没有重叠、横向溢出或不可读文本。
- **空态：**商品为空、图片缺失、证书/评价/活动权益为空、链接失效或区块隐藏时，页面不得展示虚假的占位承诺、空白主视觉或无效 CTA。必要时下线整个区块。
- **可见性与插槽：**确认不应公开的草稿、编辑器说明区、隐藏区块和插槽内容不会在公开页面出现；不要通过临时保留不可见内容来代替完成审计记录。

## 7. 处理动作与发布流程

每个问题选择以下一种处理方式，并记录原因：

1. **下线：**对不能立即确认、可能造成风险或失去时效的区块，设为不可见；保存草稿，完成全页复核后发布。
2. **改为中性表述：**删除具体价格、赠品、时限、售后、证书、工期、地区或客户背书，替换为不作事实承诺的说明，例如“详情请咨询顾问”或“以书面确认信息为准”。
3. **补齐业务书面证据：**向业务负责人收集活动规则、售后政策、资质/证书、门店信息、客户授权、版权授权或履约确认；未取得前保持下线或中性表述。
4. **重新发布：**仅在所有问题已处理、预览无误且复核人签字/确认后，使用后台的“保存草稿”与“发布”流程生成新的发布版本。

不得为完成审计而删除历史页面数据、发布历史或素材；本清单只要求通过保存草稿、调整可见性/内容和重新发布实现可逆处理。

## 8. 可直接复制的审核记录模板

每个发现的问题单独记录一行；同一页面有多个区块或多个问题时不得合并为“已检查”。

将下表整体复制到获授权的审核记录中；每个问题占一行，同一页面多个问题不得合并。不得在表内复制客户联系方式、订单、支付信息或其他无关敏感数据。


## 9. 必须移交的升级规则

运营人员只能处理已有书面规则能够明确覆盖的内容。遇到下列情形，停止发布并移交；不得仅以预检通过、历史页面已经存在或默认模板包含类似文字为由自行发布。

| 情形 | 必须移交给 | 运营的即时动作 |
| --- | --- | --- |
| 价格、折扣、赠品、活动资格、活动日期、配送/保价、工期、保养维修或退换规则无法由现行书面政策覆盖 | 业务负责人；涉及合同、消费者承诺或监管要求时同时移交法务 | 下线相关区块或改为中性表述，保存草稿，不发布 |
| 证书、材质、产地、鉴定、质量等级、功效或“权威/保证”等宣称缺少可公开证据 | 业务负责人和法务/合规负责人 | 下线具体宣称与证书图，保留证据缺口记录 |
| 客户评价、实拍、姓名、购买信息、肖像或案例缺少公开授权，或可能含个人信息 | 业务负责人和法务/隐私负责人 | 立即下线该评价/图片/案例，不以打码或模糊处理替代未获确认的授权 |
| 图片、视频、字体、地图、外链落地页或第三方素材的授权范围、可访问性、版权归属不明 | 业务负责人和法务/品牌负责人 | 下线素材或链接；不要自行判断“网络可见”即代表可使用 |
| 保存草稿冲突/失败、预检异常、发布失败、版本列表或恢复失败、公开页面与草稿不一致 | 开发负责人或后台管理员 | 停止发布，保留草稿、错误时间和最小必要截图；不要通过反复发布或复制其他页面数据绕过 |
| 需要新增区块能力、修改校验规则、调整公开访问范围、修复空态/移动端渲染或处理无法安全下线的页面缺陷 | 开发负责人 | 仅记录问题和复现步骤，不改模板、服务端、路由、数据库或业务代码 |

## 10. 上线前通过标准

页面只有同时满足以下条件，才可由复核人同意发布：

- 已按第 5、6 节逐项检查该页全部可见区块和插槽，并完成审核记录。
- 所有价格、折扣、赠品、时限、售后、配送、鉴定、工期、门店、客户案例和版权内容已有适用的书面证据；无证据项已下线或改为中性表述。
- 每个商品引用均已复核为 `PUBLISHED + PUBLIC + 未删除`，且前台展示信息适合公开。
- 所有图片/视频、外链、CTA 与活动日期有效；桌面和移动预览均无误，空态与失败态不会造成误导。
- “媒体来源与授权”已覆盖当前页面全部可见媒体和社交分享图，且每条编号都能回查到真实授权证据；不得只为通过技术预检填写无法追溯的占位编号。
- 已保存草稿并完成业务复核；发布后再次打开公开页面，确认显示的是本次已审核内容和正确版本。

## 11. 安全回退方式（不删除数据）

如果重新发布后发现风险、内容错误、外链异常或公网复核不一致，采用从低影响到高影响的以下方式：

1. **停止发布 / 保留草稿。**尚未确认发布时，取消发布确认或停止在预检错误处；保存已处理的草稿以免丢失工作，但不要发布。草稿不会直接更新公开页面。
2. **快速风险下线。**若当前公开页面存在明确风险，将有问题的区块设为不可见或替换为已确认的中性表述，保存草稿、完成必要预检后发布；此操作不要求删除页面数据。
3. **载入上一已审核版本，再选择保存或回滚线上（受控使用）。**“载入当前草稿”只把可信详情放入当前内存，可撤销/重做，取消或刚载入时均不写服务端；确认采用后须显式保存，并执行第 3 节的预览、预检、发布和公网复核。若风险要求立即切回既有正式版本，应使用独立“回滚线上”动作；它只切换发布指针，不覆盖当前草稿。在真实 MySQL 多连接并发验收完成前仍应避免多人同时保存或回滚，出现 409 时刷新并重新核对，不得反复覆盖。
4. **等待开发处理。**若没有可用版本、无法恢复、发布失败或公开内容未按预期更新，停止进一步操作并按第 9 节移交开发；不要删除文档、历史版本、素材或真实业务数据。

历史详情载入、草稿显式保存和线上回滚已按第 2.3 节分离职责并具备相应代码级保护，但实际后台是否显示目标版本、账号是否具备权限、真实数据库多人并发是否符合预期，以及历史内容是否仍适合当前业务，均须在获授权环境中确认，不能由本手册预先保证。
