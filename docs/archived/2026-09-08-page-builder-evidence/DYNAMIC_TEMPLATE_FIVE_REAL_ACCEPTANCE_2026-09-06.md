# 动态模板设计器：5 种真实构图适配与端到端验收

日期：2026-09-06  
范围：当前 `TemplateDefinitionV2` 动态网站模板设计器、页面实例、NestJS/Prisma 持久化、公开 Renderer 及真实 Chromium 闭环。

## 结论

原始 5 个方案如果被理解为可导出的社交媒体位图海报，均不符合本项目产品边界；当前项目是网站页面装修与内容模板系统，不是 Fabric/Konva 式自由画布或海报导出器。

将方案解释为网站内容区的设计比例后，05 最适合，04 适合，01/02 可适配，03 只能降级为纵向大图加内容区，不能诚实实现全画布背景图、渐变遮罩和自由叠字。

隔离真实环境已经通过 5 个母模板的 UI 创建、保存、刷新、重新打开、发布、版本 API、目录读取及桌面/窄屏检查。完整真实闭环结果为 `4 passed, 1 skipped`；跳过项是当前 UI 无 Product Slot 创建入口，不能用内部 API 伪造通过。

这 5 个模板暂未写入当前开发库。当前模板设计器存在一份来源未明的“尚未保存修复方案”，按项目资产保护规则不得替用户保存、丢弃、刷新或覆盖。隔离验收创建的数据已随一次性 MySQL 卷清理，`cleanup_remaining=0`。

## 当前真实数据流

```text
TemplateDefinitionV2
  -> Template Editor Session / Zustand
  -> serialize + validate
  -> DynamicTemplate draft / version API
  -> Prisma DynamicTemplate + published version
  -> published catalog
  -> PageDocument 中的 DynamicTemplateInstance
  -> contentBySlotId + 固定 templateId/version
  -> DynamicTemplateRenderer
  -> 公开页面 Renderer
```

母模板只保存结构与槽位规则；真实标题、正文、按钮和图片属于页面实例。因此母模板的 `defaultContent` 与 `previewContent` 保持空对象是正确架构，不应把 5 份业务内容硬编码进母模板。

## 5 个方案的项目适配结果

| 方案 | 项目内模板 | 桌面设计尺寸 | 移动设计尺寸 | 适配判断 | 真实限制 |
| --- | --- | ---: | ---: | --- | --- |
| 01 方形社交宣传 | 01 方形作品入口 | 1080×1080 | 390×488 | 可适配 | 是网站方形作品入口，不是可导出社交图片 |
| 02 竖版信息流 | 02 纵版作品海报 | 1080×1350 | 390×585 | 可适配 | 可做大图与文字层级；不是自由海报画布 |
| 03 Story 全屏活动 | 03 移动沉浸品牌故事 | 1080×1920 | 390×693 | 有条件适配 | 当前 UI 无 Stack/Shape/渐变/透明遮罩创建能力，不能做真正叠字背景图 |
| 04 横向链接推广 | 04 横向工艺专题 | 1200×627 | 390×520 | 适合 | 桌面左右分栏可用；移动端只能按全局节点顺序纵排 |
| 05 16:9 Hero | 05 系列主视觉 Hero | 1920×1080 | 390×693 | 最适合 | 可做大型网站 Hero；自由旋转、装饰 Shape 与位图导出不属于当前能力 |

每个隔离模板都由当前 UI 从空白模板创建，包含：一个根 Canvas/Section、一个或两个内容区域、一个 Image Slot、一个 Heading Slot、一个 Button Slot、多个 Text Slot、独立桌面/移动尺寸、间距与留白规则。没有写入测试 fixture、静态 seed、独立 Schema 或按 templateId 特判 Renderer。

## 已验证通过

- 5 种尺寸均能在编辑器显示并保存设计坐标：1080×1080、1080×1350、1080×1920、1200×627、1920×1080。
- 5 个模板均完成 CREATE -> EDIT -> SAVE -> API/DB -> RELOAD -> DESERIALIZE -> EDITOR -> PUBLISH -> VERSION API。
- 保存后桌面宽高、移动端宽高、根节点层级、Image/Heading/Button 槽位类型、图片 `cover`、空默认内容均恢复正确。
- 发布后的 5 个版本均进入真实 published catalog；1600×1000、1366×768、980×800 三档页面没有水平溢出。
- 独立 1920×240 网站模板闭环验证了：图片上传与替换、标题/正文/按钮内容、图片替代文字、保存重载、公开 Renderer、1200×900 与 390×844、固定版本、v1 -> v2 显式升级、公开快照隔离、回收站与恢复。
- 另一个真实 Hero 闭环验证了桌面图片、移动端独立图片设置、页面素材来源/授权门禁、草稿保存、刷新和公开页面读取。
- 一次性环境实际执行 50 个 Prisma migrations、真实 SUPER_ADMIN 登录、NestJS API、Nginx/Vite 生产构建和 Chromium；结束后容器、网络、镜像、MySQL 卷全部清理。
- 根 `npm run typecheck` 通过；动态模板合同检查通过：schema v1、42 种节点、34 种槽位、SHA-256 `5db5bfdec251`。

## 图片槽位判断

当前系统确实有 Image Slot 与普通图片内容的职责区分，但还不是专业海报工具的完整 Image Slot。

已具备：槽位宽高、宽高模式、宽高比、`cover/contain/fill`、图片替换、外部布局不随实例图片改变、页面实例图片缩放、焦点 X/Y、保存与重载、替代文字和素材门禁。

未达到：任意裁切矩形、裁切框可视化、独立平移边界、蒙版形状、滤镜、旋转后的裁切、每次换图的裁切重置策略完整压力测试。1:1、4:3、9:16 的槽位规则已保存验证，但“每个槽位分别替换 1:1/9:16/16:9 三张真实图片并二次重载”尚未完成，不能宣称通过。

## 文字槽位判断

已具备：标题、正文、按钮，多层字号与字重，行高、对齐、最大行数、`wrap/clip/ellipsis` 规则，以及固定宽度内换行。

不足：Schema 和当前简化 UI 没有完整提供 `fontFamily`、`letterSpacing`、文字 opacity、Auto Fit/Auto Resize Text。短、普通、超长标题没有完成三组真实页面实例压力矩阵，因此只能确认可换行，不能确认所有模板在极长标题下不会溢出。

## 已修复问题

- 简化工具箱缺少“添加区域”入口：已复用现有 `addDynamicTemplateNode`、Session、校验和选择状态补齐，没有建立第二套结构。
- 服务端生成校验器缺少与客户端一致的模板元数据结构锁校验：已通过官方合同生成命令更新生成物。
- 真实 Nginx/NestJS QA 因 HTTPS 代理头缺失产生 308：测试配置支持显式 `X-Forwarded-Proto: https`。
- 真实闭环测试仍引用旧版按钮、槽位和升级文案：已对齐当前 UI，并加入 429 `Retry-After` 恢复路径。

## 已确认 Bug

### P1

- 移动端画布中，根节点透明选择层会被子区域选择层拦截，根节点无法用鼠标直接选中；键盘聚焦后 Enter 可选中。
- 连续创建 5 个模板时，动态模板目录会触发全局 60 次/分钟限流。UI能显示“重新读取”，但高频正常设计流程会被中断。
- 发布 v2 后直接切到页面装修会复用发布前目录缓存，版本面板仍显示 v1 为最新；刷新后才发现 v2。
- 页面实例刚显式升级到 v2 后，立即从目录新增同一 v2，卡片鼠标点击和键盘 Enter 都可能只获得焦点而不插入新实例。该问题已重复观察，但尚未做独立最小复现和代码修复。

### P2

- 多层透明选择区使层级越深越容易截获父级鼠标操作，画布与结构树的选中能力不对称。
- 高级元数据和导航兼容设置隐藏在“更多模板操作 -> 模板资料与使用限制”，发布阻断与修复入口关联不够直接。

## Missing Capability

### P1

- Product Slot、Collection Slot 等能力存在于 Schema/Renderer，但当前简化模板工具箱没有创建入口；因此 Product Slot 真实 E2E 被明确标记为 `fixme`，不能算可用能力。
- 没有按设备独立调整子节点顺序。桌面“左文字/右图片”改成移动纵排后，只能保持“文字在上/图片在下”。
- 空白模板 UI 没有 Stack 创建入口，无法建立真实 image-over-text/Z-index 构图。
- 图片裁切能力尚未达到专业槽位标准；缺少完整可视化裁切与换图裁切策略。

### P2

- 缺少通用 Shape、渐变、透明遮罩、装饰图形。
- 缺少文字 Auto Fit、完整字体家族/字距/透明度控制。
- 缺少自由画布级 Rotate、Multi-select、Group/Ungroup、Copy/Paste、Snap、Guides、Safe Area 约束。
- 现有 gap、padding、align 与视图辅助可以帮助排版，但不是网格/安全区系统。

### P3 / 产品边界

- 没有社交媒体位图导出、固定像素海报导出、印刷出血与色彩管理；不应把网站模板设计器误称为海报生产工具。

## 尚未完成与真实阻断

- 最终 5 个模板尚未进入当前开发库，因此启动当前项目后还看不到它们。
- 原因不是保存 API 不工作；隔离真实 API/DB 已证明保存与加载可用。阻断是当前浏览器中存在受保护的“尚未保存修复方案”，其来源与处置权不明。
- 要完成最终落库，需要模板所有者先明确处理该草稿：保存它，或明确授权丢弃它。之后才能在当前真实系统中通过相同 UI 流程创建并保存 5 个模板。
- 未完成每个 Image Slot 的 1:1/9:16/16:9 三图替换矩阵、全部异常操作、全部元素操作和三个超长标题矩阵；这些项目不得被记为通过。

## 验收判定

当前模板系统足以支撑结构化网站内容模板和 Hero/专题区，但不足以支撑原始定义中的自由海报设计。核心结构、版本、保存、重载、页面实例和公开 Renderer 已成立；图片专业裁切、自由叠层、响应式独立排序、高级文字排版与完整组件创建入口仍是进入“真实海报设计”之前的关键差距。
