# 区块模板标准

> 生效：2026-10-12，依据 [D.41](../DECISIONS.md)。用户采纳审查后的七项推荐。本文规定一块区块模板的规格、第三层取值、响应式几何、槽位、验收和版本兼容。
> 页面目的仍只认 [PROJECT_GUARDRAILS](../PROJECT_GUARDRAILS.md) 第 2 节；页面准入、四层内容和整页成篇仍只认 [store-decoration.md](store-decoration.md)；创建向导的操作步骤和四区编辑仍只认 [template-creation-rules.md](template-creation-rules.md)，但向导选项和第三层数值以本文为准，两者冲突时以本文为准。色值与字号定义仍只认 [UI_GUIDE](../UI_GUIDE.md)。
> 2026-10-12 同日补强：收掉行宽与分栏比例的冲突、补上无图导语的完整规格、限定只有第一个全幅首屏吃视口高度，并写明角色怎么选、图片替代文本不能写什么；页面准入改回只认 store-decoration §2，作品卡栏数、按钮级别、精调取值不再互相打架。这些在 D.41 之内。
> 同日依据 [D.42](../DECISIONS.md) 加入影像轮播与横向滑动（§4.7）及其他交互的取舍（§4.8）。D.42 是目标态，落地前不能创建这两种变体。§16 用“正确做法 / 错误做法”对照全文；§16.4 写明两条规则看起来打架时听哪一条。
> 标有 **【建议初值】** 的数值已经作为现行工作阈值；用真实内容实测后可以收紧或放宽，但必须改本文并说明理由。
> 本文是文档规则。机器合同、生成器和渲染器尚未按本文收紧，差距见 [CURRENT_STATE](../CURRENT_STATE.md) 与[审查报告附录 A](../research/template-standard-review-2026-10.md)。在合同落地前，发布检查与人工审查承担本文中“必须”但合同尚未执行的项。
> 问题来源见[审查报告](../research/template-standard-review-2026-10.md)，官方依据见[研究记录](../research/template-standard-official-sources-2026-10.md)。

## 0. 状态、规则级别与权威关系

### 0.1 规则级别

本文沿用 UI_GUIDE §1.2 的思路，每条规则只用三种用词：

| 用词 | 含义 | 违反时 |
| --- | --- | --- |
| **必须** | 硬门槛 | 模板不得发布版本，或页面不得发布；能机器检查的由合同或发布检查拦截 |
| **应当** | 默认做法；偏离要在模板说明里写明理由 | 发布检查提醒，人工审查决定 |
| **可以** | 允许的受控变化 | 不检查 |

### 0.2 本文管什么、不管什么

- **管**：一块区块模板（一节）应当长什么样、包含什么、两端怎么变、空了怎么办、怎么验收、改版怎么兼容。
- **不管**：页面目的（只认 PROJECT_GUARDRAILS §2）、色值与字号的定义（只认 UI_GUIDE §2.3、§4.1）、内容来源分层（只认 store-decoration §3）、公开条件和三种恢复动作（只认 D.38、D.40）、编辑器四区如何操作（只认 D.37 与 template-creation-rules §9）。本文引用这些规则，不复制、不改写。
- **状态不写进本文。** 哪些已经实现、哪些还差，只记在 [CURRENT_STATE](../CURRENT_STATE.md) 和审查报告附录 A。

### 0.3 与现有文档的关系

| 现有文档 | 现在的职责 |
| --- | --- |
| store-decoration.md | 继续承担页面目的落地、四层内容、整页成篇。第 2 节的角色表是**唯一的页面准入名单**；本文规格卡里的“页面准入”只是抄录，两者不一致时以 store-decoration 为准，并同时修正本文 |
| template-creation-rules.md | 收缩为“创建向导与编辑器操作”；第 7 节的风格和像素预设由本文 §2.3 取代；向导各步骤的选项从本文 §3 过滤（§13） |
| launch-template-set.md | 收缩为“首发七块的骨架与清单”；共同不变量改为引用本文；实现状态移至 CURRENT_STATE |
| UI_GUIDE.md | 全站标题字重仍是 300～500，全站正文行长仍是 45 字。本文在该范围内按角色把大标题收到不超过 400，并把区块叙事正文收到每行 40 字。手机区块间距在 UI_GUIDE 补档前暂用 3xl |

## 1. 术语

| 海川术语 | 含义 | Shopify 对应 | Puck 对应 |
| --- | --- | --- | --- |
| 区块角色（`sectionRole`） | 这一节在页面上承担的职责，例如“系列叙事” | section 类型 | 组件类型 |
| 母模板 | 一个角色的结构、槽位、规则和默认图文，保存为 `TemplateDefinitionV2` 的不可变版本 | section 文件 + schema | ComponentConfig |
| 变体 | 同一角色内命名好的构图选择，例如“左图右文 / 右图左文” | preset | 同一组件的不同 defaultProps |
| 槽位（slot） | 母模板里允许页面填写的位置：标题、正文、图片、链接等 | setting / 静态 block | field |
| 结构槽位 | 母模板固定存在、页面不能删除和移动、只能填写或隐藏的槽位 | 静态 block | 实例权限关闭 drag / delete |
| 可开放设置 | 允许页面选择的少数外观选项，例如变体、配色方案 | section settings | field |
| 页面实例 | 页面上锁定了 `templateId + templateVersion` 的一节 | JSON 模板里的 section 实例 | 页面数据里的一个组件 |
| 模板默认图文 | 母模板附带的预览内容，只在后台判断层级用，不公开（D.40） | preset 默认值 | defaultProps |
| 内容端点 | 产生不同内容来源的宽度边界。海川只有两个：小于 768px 为手机内容，768px 及以上为桌面内容（D.16、D.36） | — | — |
| 几何档位 | 同一份内容在不同宽度下的栏数、间距、高度适配。只改几何，不产生第三份内容 | — | — |
| 配色方案 | 一组成对的背景色角色与前景色角色，模板只能选方案，不能单独改色 | color scheme | — |

## 2. 三层治理（重写）

一块模板按三层约束。模板设计**只能**在第三层内变化；第一、二层由本文和上游文档固定。

### 2.1 第一层：全站不变量

每块模板都**必须**满足。来源列只写权威出处，本文不复制具体数值。

| 编号 | 不变量 | 权威出处 |
| --- | --- | --- |
| L1-1 | 色值只能来自 UI_GUIDE §4.1 共享底盘，并通过 §7.6 的配色方案引用 | UI_GUIDE §4.1、§6.5 |
| L1-2 | 字号只取 UI_GUIDE §2.3 六个语义层级。全站标题字重仍是 300～500（D.40）；展示标题、页面标题、区块标题不超过 400，系列名和副标题可以用到 500（D.41）。正文 400 | UI_GUIDE §2.3、§2.4；D.40、D.41 |
| L1-3 | 只有两个内容端点：小于 768px 为手机内容，768px 及以上为桌面内容 | D.16、D.36 |
| L1-4 | 一页一套影像语言；一节一个视觉焦点 | UI_GUIDE §3.4；store-decoration §4 |
| L1-5 | 一块模板只承担一节：不含页眉、页脚、导航、搜索、购物车、结算、Cookie 同意 | store-decoration §4 |
| L1-6 | 不出现价格轰炸、虚假限量、倒计时、促销会场；价格类槽位按 D.38 处理 | UI_GUIDE §8.2；D.38 |
| L1-7 | 关键文字必须是真实页面文字，不得烙在图片或视频里 | UI_GUIDE §5.2 |
| L1-8 | 达到 §9 的 WCAG 2.2 AA 映射与 §8 的性能规则 | 本文 §8、§9 |

### 2.2 第二层：区块角色不变量

每个角色的用途、准入、槽位、上限和禁区由 §3 的规格卡定义。模板设计**不得**改变规格卡里标为“固定”的项。

### 2.3 第三层：受控变化

第三层只允许下面七个维度变化，每个维度只能取列出的值。**所有取值都是令牌引用，不写原始像素或色值。**

| 维度 | 可取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| 变体 | 规格卡列出的变体 | 规格卡第一项 | 相当于 Shopify preset |
| 画幅 | §6.4 比例令牌中、规格卡允许的那几个 | 规格卡推荐值 | 画幅落在媒体外框上；含正文的节根部一律随内容增长 |
| 留白密度 | 标准 / 宽松 | 标准 | 映射见下表 |
| 影像权重 | 影像主导 / 图文均衡 / 文字主导 | 规格卡指定 | 12 列里图文栏数为 8:4、7:5、6:6。文字列再受 §7.3 的 40em 上限，多出来的宽度留白，不把行拉长 |
| 对齐 | 左对齐 / 居中 | 分栏左对齐，中央构图居中 | 不提供右对齐正文（中文长文右对齐难读） |
| 配色方案 | 浅色 / 次级 / 深色（§7.6） | 浅色 | 深色只用于局部承托，不作整站默认 |
| 图片形状 | 直角 / 圆形 | 直角 | 圆形只用于人物头像与 Logo。D.41 取消 0/8/16/24/32 圆角预设和图片默认 24px 圆角 |

**留白密度与间距令牌的映射**（令牌名取自 UI_GUIDE §3.2）：

| 用途 | 标准（桌面 / 手机） | 宽松（桌面 / 手机） |
| --- | --- | --- |
| 同组元素之间（标题与正文） | lg / lg | xl / lg |
| 图与文之间 | 2xl / xl | 3xl / xl |
| 节内模块之间 | 3xl / 2xl | 4xl / 3xl |
| 节的上下内边距 | 由页面统一给出，见 §10.2 | 同左 |

手机不使用 UI_GUIDE 标为后台用途的 md（16px）。同组元素在手机上用 lg（24px）。

**页面左右边距**不属于模板，统一由页面容器按 UI_GUIDE §3.5 给出：桌面 4xl，约 1024 宽时 2xl，约 768 宽时 xl，手机 20px。模板**不得**再按“画布短边 × 百分比”另算边距。

**已取消的第三层项**（D.41；template-creation-rules §7 不再另立数值）：

- 四个风格名“简约 / 高端 / 温暖 / 极简”。理由：参数组合不可区分，“高端”与“极简”完全相同；名字无法验收。
- 圆角 0/8/16/24/32 五档预设与图片默认 24px 圆角。
- 基础间距 12/16 两档（前台不用）与内容边距 4%/6%/8%。

### 2.4 文档不变量与机器合同对照

“必须”类规则应当尽量由合同或发布检查执行。下表列出现状；“需收紧”的项见审查报告附录 A，本轮不改合同。

| 规则 | 合同字段 | 现状 |
| --- | --- | --- |
| 色值来自底盘 | `slotRules.color`、`backgroundColor` | 需收紧：接受任意十六进制（A1） |
| 标题字重 300～500 | `slotRules.fontWeight` | 需收紧：允许 100～900（A2） |
| 字号不低于辅助级手机值 | `instanceEditPolicy.minFontSizePx` | 需收紧：最低 8（A3） |
| 公开页文字不截断 | `slotRules.overflow`、`maxLines` | 需收紧：允许 clip、ellipsis（A4） |
| 图片不变形 | `slotRules.objectFit` | 需收紧：允许 fill（A5） |
| 字号用 clamp 表达 | `length` | 需扩展：只有单值（A6） |
| 六个排印层级 | `slotRules.fontRole` | 需扩展：只有五值（A7） |
| 节点父子关系 | `DYNAMIC_TEMPLATE_NODE_REGISTRY.allowedParents` | 已执行 |
| 角色词汇 | `metadata.sectionRole` 枚举 | 已执行（只是标签，不含准入与上限，A14） |
| 页面锁定精确版本 | 页面实例 `templateId + templateVersion` | 已执行 |

### 3.1 角色分类

| 角色 | 现行口径 | 问题 | 本轮决定 |
| --- | --- | --- | --- |
| `page-hero` | 用途 | — | 保留，并吸收 `editorial-media` 作为“非首屏影像章节”变体 |
| `collection-story` | 用途 | — | 保留 |
| `editorial-split` | 布局名 | 与工艺、品牌事实重叠 | 本轮不改 key、不改用途。重叠留到首轮上线后，与暂缓的两个角色一起处理 |

| `service-invitation` | 用途 | — | 保留 |

| `page-intro` | — | 缺：无图导语；`/catalog` 目前用 M1 克制变体凑合 | **已决定新增**，见 §3.12。合同落地前不能创建 |
| 候选 `creation-spotlight` | — | 缺：单件作品聚焦 | 首轮上线后再决定，现在不创建 |

### 3.1.1 这一节用哪个角色

key 本轮不改，但重叠必须能判。按下面顺序，命中即停：

| 顺序 | 这一节实际在做什么 | 用 |
| --- | --- | --- |
| 1 | 只有标题和一两句导语，没有图 | `page-intro` |
| 2 | 本页第一个需要占住视线的画面，或一张弱文字大图 | `page-hero`（后者用变体 ④）。同一主题还要两三个角度才说清，并且只在首页或作品展陈的第一屏，才用变体 ⑤ |
| 3 | 一个系列或专题，主图加一句主张 | `collection-story` |
| 4 | 一道工序或一组有顺序的工艺步骤 | `craft-detail` |
| 5 | 两三条可核对的品牌或工坊事实 | `maison-fact` |
| 6 | 一个人、一处空间，或一段没有步骤编号的说明 | `editorial-split` |
| 7 | 三到六件作品并置，不讲单件工艺 | `creation-grid` |
| 8 | 一个真实的预约、咨询或定制下一步 | `service-invitation` |
| 9 | 必须用运动画面才说得清 | `video-story`；视频槽位落地前不发布 |

同一节不要混用两行。例如“三张作品图加一段工艺步骤”拆成 `creation-grid` 和 `craft-detail` 两节，不塞进同一块模板。同一系列要有主张和两三句说明，用 `collection-story`，不要做成首屏轮播。三到六件不同作品并置，用 `creation-grid`，不要做成首屏轮播。

### 3.2 规格卡模板

每张卡**必须**填写下列各项；新增角色也按此模板写。

| 项 | 写什么 |
| --- | --- |
| 用途 | 一句话：这一节为页面完成什么 |
| 页面准入 | 抄录 store-decoration §2，方便对照；准入只认那一张表 |
| 每页上限 | 同一页最多出现几次（相当于 Shopify `limit`） |
| 首发母版 | launch-template-set 中对应的 M 编号；没有则写“延后” |
| 变体 | 允许的构图变体，第一项为默认 |
| 画幅 | 桌面与手机的媒体外框比例（§6.4 令牌） |
| 影像权重 | 默认值（§2.3） |
| 槽位 | key、类型、排印角色、必填级别、字数或条数、说明 |
| 可开放设置 | 页面可选的外观项，最多 4 项（§5.1） |
| 标题层级 | 本节主标题在首个可见主视觉与其他位置时的层级 |
| 行动策略 | 能否承担本页主要行动；用按钮还是链接 |
| 空态 | 哪些槽位是成立前提；缺了是收起局部还是整节不公开（D.38） |
| 首图策略 | 是否可能成为 P-1 的高优先级图片 |
| 禁区 | 这一节不得承载的内容 |
| 专项验收 | 除 §12 通用矩阵外，本角色特有的检查 |

字数为 **【建议初值】**：“建议”是编辑器显示的推荐范围，“上限”是超出后发布检查提醒、并要求两端预览确认的阈值。字数按中文字计。

“可开放设置”只算外观选项。焦点、替代文本、链接地址是内容，不写进这一行，也不占 4 项名额（§5.1）。

每个角色怎样算做对、怎样算做错，集中写在 §16.2，规格卡里不重复。

### 3.3 `page-hero` 页面首屏

| 项 | 规格 |
| --- | --- |
| 用途 | 用一个已审核作品、系列或工艺画面建立本页第一印象，承担页面级标题 |
| 页面准入 | 抄录 store-decoration §2：六个页面都可。选款中心只用克制导语。变体 ⑤ 只用于首页和作品展陈的第一个可见主视觉 |
| 每页上限 | 不限（D.31）。只有第一个可见者获得 h1 和高优先级图片；其余**应当**用“非首屏影像章节”变体 |
| 首发母版 | M1 |
| 变体 | ① 全幅叠字（默认）② 图上文下 ③ 克制导语：不铺满首屏、无主行动、可无图 ④ 非首屏影像章节：原 `editorial-media`，D.41 已并入 ⑤ 影像轮播：2～3 帧，按 §4.7，D.42 目标态，落地前不能创建 |
| 画幅 | 桌面 16:9，高度受 R-2 上限约束；手机用手机竖图自身比例（9:16～4:5），无竖图时 4:5 且文字在图下。轮播各帧同一比例 |
| 影像权重 | 影像主导 |
| 可开放设置 | 变体；文字锚点（下方居左、下方居中、正中三选一）；文字配色（反色文字 / 主文字） |
| 标题层级 | 第一个可见时 h1（display 或 pageTitle）；其他位置 h2（sectionTitle 字号） |

**专项验收：** 390 与 1440 下整节高度随两句导语增长，不出现空图片框，也不出现 16:9 或 4:5 的空白媒体框。

### 3.13 暂缓的两个角色

`creation-spotlight`（单件作品聚焦）和 `process-steps`（定制流程）仍不做。单件作品先用 `collection-story` 或 `craft-detail` 表达；定制怎么进行，先用 `editorial-split` 加 `service-invitation`。首轮页面上线后再决定是否新增。合同枚举不先加这两个 key。

## 4. 槽位规格

### 4.1 所有槽位的共同属性

| 属性 | 规则 |
| --- | --- |
| key | **必须**是英文 camelCase，表达语义而非位置（`collectionLabel`，不是 `text2`）。**发布后不得改名、不得复用给别的含义**（§11） |
| 标签 | **必须**是运营看得懂的中文业务名，例如“系列名”；不用“文本 2”“CTA”这类技术词 |
| 帮助文字 | **应当**写出字数建议、比例与最小像素、填写示例，例如“建议 2～10 字”“建议 3:2，至少 1600px 宽” |
| 必填级别 | 三级：**公开必须**（页面不填就不能发布，D.38、D.40）/ **建议填写**（只提醒）/ **可选**。公开必须只由页面自己的值满足 |
| 可隐藏 | 结构槽位默认可隐藏；“公开必须”的槽位**不得**同时可隐藏（D.38 已判为冲突） |
| 空值 | 公开页上空槽位**必须**整体收起，不留空框、不回填模板默认图文（D.40）；编辑器内显示“待填写”占位 |

### 4.2 文字槽位

- **溢出必须换行。** 公开页不允许省略号、裁切或 line-clamp 截断；`maxLines` 只作为编辑期的“超出建议行数”警告。理由：WCAG 1.4.12 要求放大文字间距后不丢内容。
- **文字容器不得固定高度。** 需要稳定画幅的只能是媒体外框。
- **字数上限**按规格卡；超过上限时编辑器就近提示，**不得**静默截断用户输入。上限按“中文字”计，英文与数字两个字符算一个字。
- **标题建议长度跟 UI_GUIDE §8.1。** 标题建议 2～10 个中文字。规格卡里写得更宽的建议范围，以 2～10 为准；提醒上限不超过 16 字。不为了凑短而把意思写丢。一个视觉单元默认是“一个标题 + 一句必要说明”；规格卡里的第二个标题（系列名、步骤名、品牌名称）算节内小标题，不是第二个主张。
- **标题层级由位置决定，不由模板写死**：本页第一个可见主视觉的主标题为 h1（D.31），其余各节主标题为 h2，节内小标题为 h3。模板只声明“这是本节主标题 / 节内小标题”。
- **富文本**只允许段落、有序列表、无序列表、强调和站内链接；不允许标题标签、行内颜色、行内字号和任意 HTML。

### 4.3 图片槽位

| 项 | 规则 |
| --- | --- |
| 用途声明 | 每个图片槽位**必须**声明“信息图”或“装饰图”。信息图的替代文本为“公开必须”；装饰图输出空替代文本。**不得**因漏填而静默变成装饰图 |
| 替代文本 | 只写画面里看得见的作品、材质和关系。8～40 字。不堆关键词，不重复相邻标题。不写克拉、证书、价格、库存、年份、奖项，也不写“最佳”“限量” |
| 填充方式 | 只允许“填满裁切”（默认）和“完整显示”（抠底产品图）。不允许拉伸变形 |
| 焦点 | 每个图片槽位在桌面与手机各有一个焦点（横向、纵向百分比），裁切以焦点为中心。默认焦点是画面中心；主体不在中心时必须改 |
| 文字安全区 | 叠字只允许出现在距图片四边至少 xl（32px）的矩形内，并且文字组高度不超过图片高度的 40%。对比度只在这个矩形里测量（§7.6）。超出就按 R-4 移到图下 |
| 双图源 | 只有可能成为本页第一个可见主视觉的槽位**可以**有“桌面图 + 手机图”两个来源，用 `<picture>` 按 768px 切换；每个来源写自己的宽高；两图共用一个替代文本，因此替代文本必须同时适用两种裁切 |
| 最小像素 | 见下表 **【建议初值】**；低于下限时编辑器提醒，不阻断保存 |
| 形状 | 默认直角；圆形只给人物头像和 Logo（§2.3） |

| 槽位用途 | 显示宽度 | 建议源图最小宽度 |
| --- | --- | --- |
| 全幅主视觉（桌面） | 100vw | 2400px |
| 手机竖向主视觉 | 100vw（手机） | 1080px |
| 半栏主图 | 约 50vw | 1600px |
| 副图、卡片 | 约 25～33vw | 1000px |
| Logo | 固定小尺寸，高度不超过 48px | 优先 SVG；位图至少显示尺寸的 2 倍 |

图片内容还要守住 UI_GUIDE §5，模板侧只加下面这些可检查的项：

- 产品图和编辑图不放进同一个图片槽位混用。作品陈列用同一套裁切；叙事节用编辑图或工艺图。
- 图里若有艺术字，页面上仍要有同样意思的真实文字。替代文本不负责承担标题。
- 不把未经授权的第三方商标、包装或竞品识别物放进公开图。
- 裁切后主体（宝石、戒面、佩戴关系）必须仍落在焦点附近。只剩背景或只剩一只被切掉的手，这一张不算合格。

### 4.4 链接与按钮槽位

- **按钮**只放在规格卡写明“可以承担本页主要行动”的角色里，并且应当只为本页那一个主要行动服务（§10.3）；其余行动用文字链接。
- 文字**应当**是“动词 + 对象”，2～8 字，并准确描述点击后的结果，例如“预约鉴赏”“查看系列”。**不得**单独使用“点击这里”。“了解更多”只有在本节标题已说明对象时才可用。
- 目标**必须**是已发布的站内路由或经批准的外部地址；目标失效时发布检查阻断。
- 可点区域**必须**不小于 44×44px（UI_GUIDE §6.2），并有可见焦点样式。

### 4.5 视频槽位

视频槽位目前不存在于合同中（审查报告 A12）。在它落地之前，`video-story` 角色不得发布模板（§3）。落地时**必须**满足：

| 项 | 规则 |
| --- | --- |
| 封面图 | 公开必须；作为视频加载前和“减少动态效果”时的替代画面；按图片槽位规则提供替代文本 |
| 自动播放 | 默认不自动播放。确需自动播放时**必须**静音、内联播放、循环不超过 30 秒 **【建议初值】**，并提供可见的暂停按钮；系统开启“减少动态效果”时只显示封面 |
| 预加载 | 默认不预加载，只加载封面；视频是首屏主视觉时预加载封面，不预加载视频本体 |
| 字幕 | 有对白或解说的视频**必须**有字幕 |
| 体积 | **【建议初值】** 手机源不超过 4MB，桌面源不超过 8MB |
| 双端 | 手机与桌面可以是两个来源，比例分别遵守规格卡 |

### 4.6 重复组（卡片、事实条目）

- 重复组**必须**声明最少与最多条数（相当于 Shopify `max_blocks`、Puck 数组 `min`/`max`）。
- 组内各条**应当**结构一致；某条缺图时整组保持同一比例，不出现高低不齐的空洞。
- 条数不足最少值时，公开页收起整组，并在发布检查中说明。

### 4.7 轮播与横向滑动（D.42 目标态）

两种形态都已经批准为目标，但合同里还没有对应节点。落地前**不得**创建、发布这两种变体，也**不得**用多个首屏叠在一起、或用脚本拼出一个“临时轮播”来替代。

| 形态 | 用在哪 | 一句话 |
| --- | --- | --- |
| 影像轮播 | `page-hero` 变体 ⑤ | 第一个可见主视觉里，同一个系列或同一件作品的 2～3 个画面依次出现 |
| 横向滑动 | `creation-grid` 变体 ③；三格在手机上的几何适配 | 一排作品卡可以左右滑，露出下一张的一部分，提示还有内容 |

#### 4.7.1 影像轮播

| 项 | 规则 | 级别 |
| --- | --- | --- |
| 帧数 | 2～3 帧（UI_GUIDE §7）。公开时只剩 1 帧有效内容，就按普通首屏渲染，不显示任何轮播控件 | 必须 |
| 内容关系 | 三帧讲同一个系列、同一件作品或同一道工艺的不同画面。不得把新品、活动、服务三条无关消息放进同一组 | 必须 |
| 每帧有什么 | 一张图（可桌面、手机双图源）、替代文本、可选的一句图注（≤24 字）。图上不烙字。没有每帧标题，没有每帧按钮 | 必须 |
| 不随帧变的 | 页面标题（h1）、副标题、主要行动按钮、文字锚点和配色。它们在轮播外层，只出现一次。换帧是换同一主题的角度，不是换主张，所以仍算 L1-4 的“一节一个视觉焦点” | 必须 |
| 每帧链接 | 各帧不得带链接。行动只放在外层那一个按钮。没有按钮时，这一节就没有链接，用户往下看 | 必须 |
| 比例 | 各帧同一个媒体框比例，两端分别统一；源图的固有尺寸也应当一致，避免 LCP 元素在切帧时变化 | 必须 |
| 默认播放 | 不自动播放 | 必须 |
| 自动播放 | 只能由模板设计者打开，页面不能单独打开。打开后：每帧停留不少于 6 秒 **【建议初值】**，图注越长停得越久；播完一轮自动停在第一帧；鼠标悬停、键盘焦点进入、手指触碰时立即停止，并且不自己恢复；系统开启“减少动态效果”时不自动播放 | 必须 |
| 暂停按钮 | 一旦能自动播放，就必须有可见的“暂停 / 播放”按钮，按钮文字随状态改变，并且是轮播里 Tab 顺序的第一个控件（W3C APG；WCAG 2.2.2） | 必须 |
| 上一帧 / 下一帧 | 必须有两个原生按钮，可点区域不小于 44×44px，在浅色和深色图上都看得清（非文字对比度 ≥3:1） | 必须 |
| 当前位置 | 必须显示“1 / 3”这样的文字或等价的选帧控件。只用小圆点不算：小圆点达不到 44px 可点区域 | 必须 |
| 手势 | 手机上可以左右滑动，但不能只靠滑动，按钮必须同时存在 | 必须 |
| 切换动效 | 只用 `transform` 和 `opacity`，时长不超过 400ms **【建议初值】**；“减少动态效果”时直接切换 | 必须 |
| 循环 | 可以从最后一帧回到第一帧，但不得在 DOM 里复制首尾帧来做无缝循环 | 必须 |
| 加载 | 第一帧按 P-1，必须出现在首屏 HTML 里。其余帧 `loading="lazy"`，不加高优先级，**不得**用绝对定位叠在同一个可见框里——叠在视口里的图，浏览器会当成已经看见，lazy 不会生效。不靠脚本后插第一帧 | 必须 |
| 无脚本 | 没有脚本时按普通首屏渲染第一帧；其余帧以列表接在这一节后面，用户仍能读到替代文本和图注，但不出现上一帧 / 下一帧按钮 | 必须 |
| 隐藏帧 | 有脚本之后，看不见的帧加上 `inert`（或等价做法），不能被 Tab 到，也不能被读屏软件当成当前画面读出来 | 必须 |
| 语义 | 外层为带名称的 `region` 或 `group`，`aria-roledescription="carousel"`；每帧为 `group`，`aria-roledescription="slide"`，名称用图注或“2 / 3”；不自动播放时帧容器 `aria-live="polite"`，自动播放时为 `off` | 必须 |
| 对比度 | 每一帧都单独按 §7.6 检查，任何一帧不达标都按那一帧的问题处理 | 必须 |
| 每页 | 一页最多一个影像轮播 | 必须 |

**轮播验收：** 键盘从页面进入轮播时，第一个焦点是暂停按钮（若有自动播放），否则是上一帧按钮；焦点进入后不再自动换帧；1440 与 390 下切帧时 CLS 为 0；只剩一帧时控件全部消失；关掉脚本后只看见第一帧加后面的帧列表，没有坏掉的空框；第二、第三帧的请求不早于用户切到那一帧（或距离视口足够近，由浏览器 lazy 决定）；200% 放大时按钮和“1 / 3”仍在、不遮住图注。DOM 里找不到各帧自己的链接。

#### 4.7.2 横向滑动

| 项 | 规则 | 级别 |
| --- | --- | --- |
| 条数 | 变体 ③ 必须是 4～6 件。只有 3 件时用变体 ①，不要创建变体 ③ | 必须 |
| 什么时候出现 | 变体 ③：桌面和手机都是一排可滑动的卡。变体 ①（三格）：768px 及以上仍是三列；小于 768px 改成横滑，这是几何适配，不产生新内容，也不是变体 ③ | 必须 |
| 露出提示 | 手机上一屏显示约 1.2～1.5 张卡，让下一张露出一部分；不靠文字“左滑查看更多”提示 | 应当 |
| 自动播放 | 不允许。横向滑动永远由用户操作 | 必须 |
| 实现方式 | 应当用原生横向滚动加 CSS `scroll-snap`，不劫持页面的竖向滚动 | 应当 |
| 按钮 | 768px 及以上有上一组 / 下一组按钮（≥44×44px）；手机可以只靠滑动，因为卡片本身仍可以用 Tab 逐张到达 | 必须 |
| 键盘 | Tab 逐张聚焦卡片链接时，被聚焦的卡自动滚入可视区；焦点不被两侧遮罩挡住 | 必须 |
| 末端 | 到最后一张就停，不循环，不复制卡片 | 必须 |
| 图片 | 全部 lazy；卡片比例 4:5 不变 | 必须 |
| 不出现 | 滚动条被完全隐藏且没有按钮；两侧大面积渐隐遮住卡片内容；页面竖滑时被它“吸住” | 必须 |

**横滑验收：** 390 宽露出下一张；1440 宽按钮可用、到末端时“下一组”按钮变为不可用并仍可被读屏识别；竖向滑动经过这一节时页面正常滚动；键盘 Tab 到第 6 张时它完整可见。

### 4.8 其他交互：允许、暂缓、不做

| 交互 | 状态 | 说明 |
| --- | --- | --- |
| 视频播放 | 已有规则（§4.5），视频槽位落地前不发布 | 点击播放为默认 |
| 影像轮播、横向滑动 | 目标态（§4.7、D.42） | 落地前不能创建 |
| 图片放大查看（灯箱） | 暂缓 | 单件作品聚焦角色（§3.13）做时一起定，现在不在区块里做 |
| 改款前后对比 | 暂缓 | 与定制、改款服务有关，首轮页面上线后再决定；旧的对比组件已随旧固定模板删除，不直接恢复 |
| 图片热点（点图上位置出说明） | 暂缓 | 需要逐点替代文本和键盘路径，首轮不做 |
| 折叠问答、选项卡 | 暂缓 | 服务说明真的需要时再提，不用来把长文藏起来 |
| 跑马灯、Logo 自动滚动墙 | 不做 | 违反 UI_GUIDE §7，也和奢侈品克制基调不符 |
| 视差、滚动劫持、滚动触发的大幅位移 | 不做 | UI_GUIDE §7 |
| 3D 翻转、封面流、鼠标跟随、光效扫字 | 不做 | UI_GUIDE §7 |
| 进入页面自动弹窗、悬浮咨询气泡 | 不做 | 区块模板只承担一节（L1-5） |

“暂缓”表示现在不能创建，以后要用必须先有新的产品决定；“不做”表示提出来也按 UI_GUIDE 拒绝。

## 5. 设置治理

### 5.1 页面能改什么

页面实例**只能**：

1. 填写、替换、清空或隐藏槽位内容；
2. 在规格卡列出的“可开放设置”里选择，每个角色**不得**超过 4 项。焦点、替代文本和链接地址不算这 4 项，它们是内容；
3. 调整图片焦点；
4. 使用 D.38 的三个恢复动作。

页面实例**默认不得**改槽位位置、尺寸、层级和字号（D.41）。现行合同 `instanceEditPolicy` 仍允许这些改动，在合同收紧前由发布检查标为“超出本文、待人工核对”，不得当成推荐做法。已有页面里的几何覆盖继续读取，不自动清除。

### 5.2 模板设计能改什么

模板设计者在第三层（§2.3）内调整。需要自由定位的只有一种情况：全幅主视觉的前景文字组，在安全区内选择九宫格锚点之一（左上、正中、下方居中等），偏移只取间距令牌，不允许任意坐标。模板设计者从九个锚点里挑出最多三个开放给页面（`page-hero` 默认开放下方居左、下方居中、正中）。

模板设计者的精调同样只取令牌：间距取 UI_GUIDE §3.2，颜色取配色方案角色，字号取 §7 排印角色及其 clamp 上下限，图片形状只有直角和圆形。可以填任意数值的只有几何尺寸：媒体外框的宽高、分栏的列宽分配。历史模板里已有的非令牌值照原样读取，编辑器标为“非标准值”并提供“改为最近的令牌”，不自动改写。

### 5.3 设置的写法

- 每项设置**必须**有中文标签和默认值，默认值**应当**就是最常用的选择。
- 只有在相关时才显示的设置**应当**条件显示（Shopify `visible_if`、Puck `resolveFields`），例如“完整显示”只在选择抠底图时出现。
- 选项**必须**用描述性名称（“左图右文”），不用编号（“布局 1”）。
- 非法输入保留原值并就近报错，不静默夹取（沿用 template-creation-rules §9.3）。

## 6. 响应式

### 6.1 两个内容端点不变

沿用 D.16、D.36：小于 768px 为手机内容，768px 及以上为桌面内容，不新增平板内容。手机只覆盖改过的项，其余继承桌面。

### 6.2 几何档位（只改几何，不产生新内容）

内容端点只有两个，但验收和几何适配按下列档位描述。档位名只用于沟通和测试，**不写入模板**。

| 档位 | 宽度 | 内容来源 | 典型设备 | 参考 |

| 标准手机 | 390～599 | 手机 | 主流手机竖屏 | 手机代表视口 390 |

### 6.3 几何适配规则

| 编号 | 规则 | 级别 |
| --- | --- | --- |
| R-1 | **分栏按最小文字栏宽自动转为上下排列。** 文字栏可用宽度小于正文的 24em（正文 15px 时为 360px，约 24 个字）时，左右图文改为上图下文。用 em 是为了文字放大后门槛一起变大。这是几何规则，与设备无关；约 768～900px 的竖屏平板会因此变成单栏 | 必须 |
| R-2 | **只有第一个可见的全幅主视觉吃视口高度。** 它的高度取“比例高度”和“100svh 减去页头高度”中的较小值。后面的全幅节只用自己的比例，放在 1280px 内容宽度里，不得再用 100svh。这样超宽屏、横屏手机不会出现超过一屏的首屏，后面的节也不会各占一屏 | 必须 |
| R-3 | **矮视口不叠字。** 视口高度小于 480px 时，全幅主视觉的文字改到图下，图片高度不超过 R-2 上限 | 必须 |
| R-4 | **叠字放不下就移到图下。** 任何宽度下，若文字组超出安全区或对比度不达标，文字移到图下，不缩小字号、不截断 | 必须 |
| R-5 | **内容最大宽度。** 文字与网格的容器最大 1280px（UI_GUIDE §3.3）。叙事正文再受 §7.3 的 40em 限制，不用把 720px 当成区块正文的目标宽度。全幅影像可以铺满视口，上面的文字仍在 1280px 容器内，并且行宽仍受 40em 限制 | 必须 |
| R-6 | **作品卡栏数。** 768px 及以上一律 3 列（768 宽时每张约 219px）。小于 768px：六格 2 列；三格改为横向滑动（§4.7.2 的几何适配），横滑落地前改为单列，不排成“两张一排加一张落单”。变体 ③ 两端都按横滑，不受“768 以上三列”约束。区块里不用 4 列，因为一组最多 6 件，4 列会剩 2 张。卡片比例两端不变 | 必须 |
| R-7 | **竖向素材延续。** 第一个可见全幅主视觉在小于 768px 用手机竖图。D.41 方案 B：768～1023 且视口为竖向时，**可以**继续使用这张手机竖图。这仍是两套素材之一，不是第三份内容（D.36 继续有效） | 可以 |
| R-8 | **后面的全幅章节在桌面和手机都不占满一个视口**（R-2 的后半句，以及 store-decoration §4） | 必须 |

### 6.4 比例令牌

把现行“画幅预设”（template-creation-rules §3）和“图片比例”（§5）合并为一组，避免角色推荐 3:2 却选不到的情况：

| 令牌 | 比例 | 用途 |
| --- | --- | --- |
| 宽幅 | 16:9 | 桌面全幅主视觉、横向影像、视频 |
| 编辑横版 | 3:2 | 系列、工艺、分栏主图 |
| 均衡横版 | 4:3 | 信息较多的分栏 |
| 方形 | 1:1 | 头像、Logo 承托、少量方形作品图 |
| 竖向卡片 | 4:5 | 作品卡、手机分栏主图、无竖向素材时的手机主视觉 |
| 竖向编辑 | 3:4 | 人物与佩戴编辑图 |
| 手机全幅 | 9:16 | 仅限手机端第一个可见主视觉的媒体框，且受 R-2 上限约束 |
| 随内容 | auto | 节根部与无固定画幅的容器 |

自定义比例只允许模板设计者在有明确素材理由时使用，并在模板说明中写明理由。

### 6.5 预览与验收视口

- 设计代表视口：桌面 1440×900，手机 390×844（沿用现行）。三处预览（编辑画布、模板预览、公开渲染）**必须**使用同一个 Renderer 和同一组代表视口。

## 7. 排印与颜色

### 7.1 排印角色

槽位只能引用下列六个角色，数值取 UI_GUIDE §2.3、§2.4：

| 角色 | 对应层级 | 典型槽位 | 字体 | 字重 |
| --- | --- | --- | --- | --- |
| display | 展示标题 | 首屏品牌大标题 | 衬线 | 300 |
| pageTitle | 主标题 H1 | 首屏页面标题；非首屏时降为 sectionTitle 的字号 | 衬线 | 300～400 |
| sectionTitle | 区块标题 H2 | 各节主标题 | 衬线 | 400 |
| subtitle | 系列名 / 副标题 | 系列名、步骤名、品牌名称 | 衬线或无衬线 | 400～500 |
| body | 正文 | 描述、事实条目、链接与按钮文字 | 无衬线 | 400（按钮文字可 500） |
| caption | 辅助 | 图注、时间地点 | 无衬线 | 400 |

### 7.2 字号用 clamp 表达

每个角色的字号**必须**写成 `clamp(手机值, 中间值, 桌面值)`，在手机代表宽度 390 到桌面代表宽度 1440 之间线性过渡。中间值**必须**含 rem 分量，不能是纯 vw，否则浏览器文字放大会失效（WCAG 1.4.4）。

| 角色 | 手机 → 桌面 | 参考写法（1rem = 16px） |
| --- | --- | --- |
| display | 40 → 68 | `clamp(2.5rem, 1.85rem + 2.667vw, 4.25rem)` |
| pageTitle | 28 → 34 | `clamp(1.75rem, 1.611rem + 0.571vw, 2.125rem)` |
| sectionTitle | 20 → 24 | `clamp(1.25rem, 1.157rem + 0.381vw, 1.5rem)` |
| subtitle | 16 → 18 | `clamp(1rem, 0.954rem + 0.19vw, 1.125rem)` |
| body | 14 → 15 | `clamp(0.875rem, 0.852rem + 0.095vw, 0.9375rem)` |
| caption | 11 → 12 | `clamp(0.6875rem, 0.664rem + 0.095vw, 0.75rem)` |

模板设计者**可以**在同一层级内调整上下限，但下限**不得**低于该层级的手机值（UI_GUIDE §2.3）。

### 7.3 行长、行高与字距

- 区块里的叙事正文每行**不得**超过 40 个中文字（D.41）。文字列设 `max-width: 40em`。正文 15px 时，40em 等于 600px。栏更窄是允许的，那一行会短于 40 字；栏更宽时多出来的空间留白，不把字距拉开，也不两端对齐。UI_GUIDE §2.6 的 45 字仍是区块以外场景的上限。720px 是全站正文栏的绝对上限，叙事正文用上面的 40em，不再另取 720px。
- 以前写的“文字主导占 7/12”会在 1280px 容器里得到约 747px 的文字列，按 15px 约 50 个字，超过 40 字。所以影像权重改成 8:4、7:5、6:6，并且一律再套 40em 上限。6:6 在 1280px 容器里约 640px，也会被 40em 截住。
- 标题行高 1.2～1.4，正文 1.6～2.0；中文标题不加字距，英文全大写标题加宽（UI_GUIDE §2.5、§2.6）。
- 正文**不得**两端对齐。

### 7.4 字体加载

- 只用 WOFF2，中文字体按实际用字子集化；每页字体文件**应当**不超过 4 个 **【建议初值】**。
- 用 `font-display: swap` 并配 `size-adjust` 等度量调整，减少换字体时的位移。

### 7.5 字重

前台不出现 700。后台标题 600 不适用于区块模板。

### 7.6 配色方案与图上文字

模板**只能**选择配色方案，不能单独指定色值。三个方案均由 UI_GUIDE §4.1 的语义角色组成：

| 方案 | 背景 | 主文字 | 次级文字 | 分隔线 |
| --- | --- | --- | --- | --- |
| 浅色 | 主画布 | 主文字 | 次级文字 | 分隔线 |
| 次级 | 次级画布 | 主文字 | 次级文字 | 分隔线 |
| 深色 | 深色画布 | 反色文字 | 次级文字不靠透明度做。对比度不够就改用反色文字，或把次级句移出深色底 | 强分隔线 |

**文字叠在图片上时**，按下列顺序处理，直到达标：

1. 在桌面与手机两端，分别在文字安全区内测量实际对比度：正文至少 4.5:1，大字（24px 及以上，或 18.67px 及以上粗体）至少 3:1；
2. 不达标时，调整焦点或安全区位置；
3. 仍不达标时，加一层平涂遮罩。只允许深色画布这个角色，透明度只有两档：45% 和 70%。不允许彩色渐变，也不允许第三档透明度。
4. 70% 仍不达标时，按 R-4 把文字移到图下。不得再把遮罩加黑来硬过。

对比度无法可靠自动测量时，发布检查标为“待人工核对”（D.38 检查分级）。

## 8. 媒体与性能

### 8.1 加载优先级

| 编号 | 规则 | 级别 |
| --- | --- | --- |
| P-1 | 本页第一个可见主视觉的图片：立即加载，加 `fetchpriority="high"`，**不得**用 CSS 背景图，**必须**能从首屏 HTML 直接发现 | 必须 |
| P-2 | 一页最多一个高优先级图片（双图源的 `<picture>` 算一个；影像轮播只有第一帧算） | 必须 |
| P-3 | 其余图片：`loading="lazy"` + `decoding="async"` | 必须 |
| P-4 | 视频默认 `preload="none"` 并显示封面；视频是首屏主视觉时，封面按 P-1 处理 | 必须 |
| P-5 | 动画只用 `transform` 和 `opacity`；一节只保留一个主要动效；尊重“减少动态效果”（UI_GUIDE §7） | 必须 |

`svh`、`fetchpriority` 和 `<picture>` 按宽度换源，在微信内置浏览器和部分手机厂商浏览器上还没有本项目的实测。在测到之前，这些环境按比例高度排首屏，并且可以只用一张图；文字在图下（R-4）在这些环境里仍然成立。不得把未实测的浏览器当成已经支持。

### 8.2 防止布局跳动

- 每个媒体框**必须**预先声明比例或宽高，图片加载前就占好位置。
- 可选图片缺失时，**必须**在渲染时就决定收起，不能先占位、加载失败后再收起。
- 迟到的内容（字体、视频）**不得**推挤已经显示的文字。

### 8.3 响应式图片

- 所有图片**必须**输出 `srcset`，并给出与实际版式一致的 `sizes`：全幅 `100vw`；半栏 `(max-width: 767px) 100vw, 50vw`；六格卡片 `(max-width: 767px) 50vw, 33vw`；三格与横滑卡片 `(max-width: 767px) 80vw, 33vw`。
- 派生宽度阶梯**应当**覆盖到 2400px，供全幅槽位在宽屏与高密度屏使用（审查报告 A19）。

### 8.4 预算 **【建议初值】**

| 项 | 预算 |
| --- | --- |
| 首屏高优先级图片传输体积 | 手机 ≤ 250KB，桌面 ≤ 450KB |
| 首屏内（无需滚动可见）图片张数 | ≤ 3；轮播里看不见的帧不算，但它们不得在首屏抢先下载 |
| 单节图片张数 | ≤ 6 |
| 单页可装修区块数 | ≤ 8（§10.1） |
| 视频 | 见 §4.5 |

### 8.5 指标

- 以 Core Web Vitals 第 75 百分位为目标：LCP ≤ 2.5s、CLS ≤ 0.1、INP ≤ 200ms（UI_GUIDE §9.3）。
- 实验室代理指标：首页、作品展陈、关于三页，在手机与桌面分别用真实内容跑 Lighthouse。下限参照 Shopify 主题商店（性能 60、无障碍 90）；海川目标 **【建议初值】** 性能 ≥ 75、无障碍 ≥ 95。
- 无法实测时**必须**标“未验证”，不能用本机观感代替（UI_GUIDE §9.3）。

## 10. 整页编排

单块合格不等于整页合格。本节补充 store-decoration §4，不取代它。

### 10.1 区块数量

- 单页可装修区块**应当**不超过 8 节 **【建议初值】**。Shopify 的 25 节是平台上限，不是设计目标；奢侈品牌公开页通常短而完整。
- `/catalog` 只放一节 `page-intro`（合同落地前用 `page-hero` 克制导语），主体是固定业务区（store-decoration §2）。装修节不得复制搜索、筛选、排序或结果列表。
- `/contact` 的表单、`/catalog` 的结果区、页眉、页脚、购物车都不进区块模板。模板停在这些固定区之前或之后，按钮可以指向它们，但不能再做一套。

### 10.2 节间距与背景

- 相邻两节之间只有一档间距，放在节内（store-decoration §4）。桌面取 5xl（96px，UI_GUIDE §3.2）。手机取 3xl（64px）。UI_GUIDE 还没有单独的手机区块间距，在它补上之前就用这一档，不再另写一套像素。
- 相邻两节配色方案相同时共用这一档间距；方案不同时各自保留上下内边距，背景色块边缘对齐页面全宽。
- 深色方案每页**应当**不超过 1 节，用于局部承托。

### 10.3 主要行动

三条规则分清级别，避免“必须只有一个”和“两个也能确认发布”互相打架：

| 规则 | 级别 |
| --- | --- |
| 整页**应当**只有一个主要行动（UI_GUIDE §6.2），用按钮呈现，放在本页主焦点那一节；其余节用文字链接 | 应当 |
| 按钮**必须**只出现在规格卡“行动策略”允许的角色里（目前是 `page-hero` 与 `service-invitation`），其他角色放按钮是模板错误，不能发布模板 | 必须 |
| 页面上出现两个及以上按钮时，发布检查**必须**提醒并要求运营确认后才能发布（D.41）。确认的意思是“我知道这页有两个行动”，不是取消上一条 | 必须 |

首页同时放 `page-hero` 和 `service-invitation` 时就会触发确认。推荐做法是只保留一个按钮，另一节改用文字链接。两个按钮的文字也**不得**相同。

### 10.4 相邻关系

- 相邻两节**不得**使用同一全幅构图，**不得**是同一角色的同一变体。
- 页面上的影像**必须**是一套影像语言（UI_GUIDE §3.4）：色调、光线、景深一致。这一项由人工核对。

### 10.5 标题大纲

- 每页**必须**恰好一个 h1：由第一个可见的 `page-hero` 或 `page-intro` 承担（D.31）；页面没有有效首屏标题时，由公开渲染补一个视觉隐藏的 h1。影像轮播的 h1 在轮播外层，不随帧变化。
- 其余各节主标题为 h2，节内小标题为 h3，不跳级。

### 10.6 起始配方

六个页面的起始配方留在 launch-template-set §4，它是建议而不是准入。配方中的角色必须满足 store-decoration §2 的页面准入；不一致时以 store-decoration 为准，并同时修正配方。

## 11. 版本与兼容

### 11.1 版本身份

- 母模板版本以 `templateId + templateVersion` 标识，发布后不可变；页面锁定精确版本，只能显式升级（D.38）。
- 合同结构版本由 `schemaVersion` 和生成物哈希承担，按 `contracts:generate` / `contracts:check` 流程变更。

### 11.2 变更分级

| 级别 | 例子 | 要求 |
| --- | --- | --- |
| 兼容 | 改模板默认图文；改帮助文字；新增可选槽位；新增变体；收窄字数建议 | 发新版本即可；页面升级时不丢任何内容 |
| 需迁移 | 改槽位类型（text 改 richText）；把一个槽位拆成两个；把“建议填写”改为“公开必须”；删除一个变体 | **必须**附迁移转换，并在升级预览中逐字段显示“保留 / 移动 / 需重新填写” |
| 破坏性 | 删除槽位；改槽位 key；改变角色 | 改 key 与复用 key **一律禁止**。删除槽位改为“标记弃用”：新版本不再渲染，旧页面数据保留，升级预览说明该内容将不再显示。改变角色等于新建母模板 |

### 11.3 迁移转换

- 转换**必须**同时容忍新旧两种数据，重复执行结果不变（参照 Puck `transformProps` 的要求）。
- 转换只移动或改写页面自己的内容，**不得**把模板默认图文写进页面（D.40）。
- 页面**不得**被自动升级。升级是运营在页面装修里的显式动作，升级后仍需“发布页面”才更新前台。

## 12. 质量检查与量化验收

### 12.1 三个检查环节

| 环节 | 谁做 | 检查什么 | 不通过时 |
| --- | --- | --- | --- |
| 模板发布前 | 模板设计者 + 自动检查 | 规格卡、§4 槽位、§6 几何规则、§9 中“模板发布”项、§12.2 压力矩阵 | 不得发布模板版本 |
| 页面发布前 | 运营 + 自动检查 | 公开必须内容、替代文本、链接目标、对比度、§10 整页编排、§9 中“页面发布”项 | 按 D.38 分级：阻断、提醒或待人工核对 |
| 上线前抽检 | 用户或指定审查人 | 真实内容的 §8.5 指标与 UI_GUIDE §11.2 视觉验收 | 记录为未通过，不发布到生产 |

### 12.2 压力矩阵

每块模板发布前，**必须**用下列内容组合，在 §6.5 的十二个视口中逐一渲染：

| 内容组合 | 怎么填 |
| --- | --- |
| 极短 | 每个文字槽位 1～2 字 |
| 典型 | 每个文字槽位取规格卡建议范围的中间值 |
| 满额 | 每个文字槽位填到上限 |
| 超额 | 上限再加 20%：期望编辑器警告，公开页仍完整换行 |
| 长英文 | 系列名填一个 30 字符、无空格的英文词 |
| 缺可选图 | 逐个移除可选图片 |
| 只剩必须 | 移除全部可选内容 |
| 轮播满额 | 变体 ⑤：3 帧，每帧图注 24 字，外层标题和按钮取上限 |
| 轮播只剩 1 帧 | 变体 ⑤ 只填第 1 帧：期望没有轮播控件，按普通首屏渲染 |
| 横滑满额 | 变体 ③：6 件；另测 4 件。不要测 5 件缺一角的六格 |

另做五项无障碍压力：浏览器 200% 放大（在 1280 宽下）；320px 宽重排；WCAG 1.4.12 文字间距（行高 1.5 倍、段距 2 倍、字距 0.12em、词距 0.16em）；系统“减少动态效果”；只用键盘走完本节。影像轮播还要加两项：关掉脚本后第一帧仍在；打开自动播放后，焦点进入即停且不自己恢复。

### 12.3 通过阈值

| 检查 | 阈值 | 方式 |
| --- | --- | --- |
| 横向滚动 | 页面竖向容器在任一验收视口都没有横向滚动。`creation-grid` 按 §4.7.2 声明的横向滑动除外，且不得把整页也带着横滑 | 自动 |
| 文字裁切与重叠 | 文字元素之间、文字与非背景图片之间重叠面积为 0；无省略号 | 自动 |
| 空框 | 公开渲染中没有空图片框和空文字容器 | 自动 |
| 布局跳动 | 单页实验室 CLS ≤ 0.1 | 自动 |
| 触控目标 | 所有链接与按钮 ≥ 44×44px | 自动 |
| 对比度 | 正文 ≥ 4.5:1，大字与非文字元素 ≥ 3:1；图上文字在安全区内测 | 自动 + 人工 |
| 标题大纲 | 恰好一个 h1，不跳级 | 自动 |
| 高优先级图片 | 每页恰好 1 个（无首屏图时为 0） | 自动 |
| 源图像素 | 不低于 §4.3 建议值，否则提醒 | 自动 |
| 首屏高度 | 只有第一个可见全幅主视觉不超过一屏；后面的全幅节不用视口高度（R-2） | 自动 |
| 阅读顺序 | 两端 DOM 顺序与视觉顺序一致 | 人工 |
| 行宽 | 叙事正文行盒宽度不超过 40em | 自动 |

### 12.5 一组可以手算的数

下面用正文 15px、容器 1280px 验算，避免比例和行宽各说各的。768 这一档的边距取 xl（32px），图文间距取桌面的 2xl（48px），因为 768 已经是桌面内容端点。

| 情况 | 计算 | 结果 |
| --- | --- | --- |
| 40 个中文字的行宽 | 40 × 15px | 600px，即 40em |
| 影像主导 8:4 的文字列 | 1280 × 4 / 12 | 427px，约 28 字，不用再截 |
| 图文均衡 7:5 的文字列 | 1280 × 5 / 12 | 533px，约 36 字，不用再截 |
| 文字主导 6:6 的文字列 | 1280 × 6 / 12 = 640px，再套 40em | 显示宽度 600px，约 40 字 |
| 分栏改上下的门槛 | 24 × 15px | 360px。文字列窄于它就改为上图下文 |
| 768 宽、左右边距 32px、栏间距 48px 的双栏文字列 | (768 − 64 − 48) / 2 | 328px，低于 360px，所以这一档是单栏 |
| 第一个全幅首屏在 2560×1440、页头 80px | min(2560 × 9/16, 1440 − 80) | 取 1360px，不超过一屏。后面的全幅节不再用这个算法 |

上表的 8:4、7:5、6:6 还没减去栏间距。减去 2xl（48px）之后，文字列更窄，仍然不超过 40 字。字号不是 15px 时，用当时的正文字号重算 em，不把 600px 和 360px 写成不随字号变化的死数。

## 13. 创建向导与规格卡的关系

七步向导（template-creation-rules §1～§8）保留，但每一步的选项**必须**从所选角色的规格卡过滤，向导不再自带一套独立的推荐表：

| 4 图片 | 规格卡里的图片槽位：用途声明、最小像素、焦点、形状 |
| 5 内容 | 规格卡里的文字槽位：公开必须的槽位默认勾选且不可取消；可选槽位可增减 |
| 6 样式 | §2.3 的留白密度、影像权重、配色方案、对齐 |

“自由布局”不再作为创建选项（D.41）：每块模板都必须有角色。需要定位的只有首屏前景文字组，按 §5.2 用锚点表达。

## 16. 正确与错误做法对照

本章把前面的规则翻成“这样做对、那样做错”。表里的“后果”沿用 §0.1：**阻断**＝模板不能发布版本或页面不能发布；**提醒**＝发布检查提示，需要确认；**人工**＝自动检查查不出来，由审查人判断。合同还没收紧的项，现阶段都靠人工。

### 16.1 判断顺序

拿不准时按这个顺序问自己，前一问答“否”就不用往下问：

1. 这一节在本页有没有用（PROJECT_GUARDRAILS §2）？没有就不放。
2. 它该用哪个角色（§3.1.1）？
3. 这个角色允许放在这一页吗（store-decoration §2）？
4. 内容是不是页面自己的真实内容，而不是模板默认图文（D.40）？
5. 手机 390 和桌面 1440 上都完整、可读、没有空框吗（§6、§12）？

### 16.2 按角色

**`page-hero` 页面首屏**

| 场景 | 正确做法 | 错误做法 | 后果 | 依据 |
| --- | --- | --- | --- | --- |
| 标题 | “臻选婚戒”“海川高级珠宝”，2～10 字说清本页主题 | “全场新品限时特惠立即抢购每一款都值得拥有” | 超 16 字提醒；促销话术人工判定不合格 | §4.2、L1-6 |
| 手机图 | 上传一张单独构图的手机竖图，焦点落在戒面；没有竖图就用 4:5，文字放在图下 | 把 16:9 横图在手机上居中裁成竖幅，戒指只剩半边 | 人工 | R-7、§4.3 |
| 按钮 | 一个按钮，例如“预约鉴赏” | “立即购买”和“了解更多”两个按钮并排 | 两个按钮触发发布确认 | §10.3 |
| 字压在图上看不清 | 先挪焦点，再加 45% 平涂遮罩，再试 70%，还不行就把字放到图下 | 加彩色渐变；把字号缩小硬塞进去；遮罩加到 90% | 对比度不达标阻断；彩色渐变人工判定不合格 | §7.6、R-4 |
| 一页有两个首屏 | 第二个用变体 ④，标题是 h2，图片 lazy，高度只按比例 | 第二个也占满一屏、也是 h1、也加高优先级 | 两个 h1 阻断；第二个占满一屏人工判定不合格 | D.31、R-2、P-2 |
| 横屏手机 844×390 | 文字放在图下，图高不超过一屏 | 文字叠在只有 390 高的图上，标题被页头挡住 | 人工 | R-3 |
| 要不要轮播 | 一张图就能说清就用变体 ① 或 ②。同一件作品或同一个系列还要两三个角度，并且是首页或作品展陈的第一屏，才用变体 ⑤ | 选款中心、关于、定制、联系用轮播；或把三个部门的三条消息塞进一个首屏 | 人工；选错页面阻断 | store-decoration §2、§4.7.1 |
| 轮播内容 | 同一系列的三个画面：佩戴、侧面、细节。标题和按钮在外层，三帧共用 | 第 1 帧新品、第 2 帧活动、第 3 帧招聘；每帧换一个标题或换一个按钮 | 人工；每帧换按钮阻断 | §4.7.1、L1-4 |
| 轮播链接 | 行动只在外层那一个按钮上 | 每帧各挂一个链接，或第 1 帧去系列、第 2 帧去活动 | 阻断 | §4.7.1、§10.3 |
| 轮播控件 | 上一帧、下一帧按钮加“1 / 3”；能自动播放就有暂停按钮，并且它是轮播里第一个 Tab | 只有三个小圆点；自动播放没有暂停；暂停按钮藏在最后 | 阻断 | §4.7.1、WCAG 2.2.2 |
| 轮播加载 | 第一帧在首屏 HTML 里高优先级；其余帧 lazy，并且不叠在同一个可见框里 | 三张图绝对定位叠在首屏上还标 lazy；三帧都加高优先级；用脚本后插第一帧 | 阻断 | §4.7.1、P-1、P-2 |
| 没有脚本 | 看见第一帧普通首屏，后面跟着其余帧的图和替代文本 | 没有脚本就整节空白，或只剩坏掉的控件 | 阻断 | §4.7.1 |
| 只剩一帧 | 按普通首屏渲染，不显示任何轮播控件 | 仍显示灰掉的“1 / 1”和不能点的箭头 | 阻断 | §4.7.1 |

**`collection-story` 系列叙事**

### 16.3 按主题

**文字**

| 场景 | 正确做法 | 错误做法 | 后果 | 依据 |

| 场景 | 正确做法 | 错误做法 | 后果 | 依据 |
| --- | --- | --- | --- | --- |
| 要不要轮播 | 先用一张图说清；确实需要同一主题的几个画面，并且只在首页或作品展陈第一屏，才用 2～3 帧 | 因为几个部门都想上首屏，就做成轮播；或把系列主张做成轮播，而不是 `collection-story` | 人工 | §3.1.1、§4.7.1 |

### 16.4 两条规则看起来打架时听哪一条

| 看起来打架的两句话 | 听哪一条 | 不要理解成 |
| --- | --- | --- |
| “一节一个视觉焦点”和“首屏可以有 2～3 帧” | 焦点是主题、标题和行动，不是图片张数。三帧必须是同一主题的不同角度 | 三帧可以讲三件不同的事 |
| “按钮应当只有一个”和“两个按钮确认后能发布” | 默认一个。两个必须确认，确认不是推荐 | 确认了就可以每节都放按钮 |
| “叙事正文 40 字 / 40em”和“UI_GUIDE 正文栏 720px / 45 字” | 区块叙事正文用 40em。720px 和 45 字是区块以外的场景 | 文字列可以拉到 720px |
| “768 以上作品卡三列”和“横向滑动变体两端都横滑” | 三列管变体 ① ②。变体 ③ 不受这句管 | 横滑在桌面也必须掰成三列 |
| “页面不得横向滚动”和“作品卡可以左右滑” | 页面竖向容器不横滚。只有这一节内部可以滑 | 整页可以跟着横滑，或 320 宽出现页面滚动条 |
| “所有帧写在 HTML 里”和“后几帧不得抢下载” | 第一帧在首屏可见盒里。后几帧在文档里，但不叠在那个可见盒里，并且 lazy | 三张图绝对定位叠在首屏上 |
| “规格卡抄了页面准入”和“store-decoration §2 才是准入” | 以 store-decoration §2 为准，发现不一致就改规格卡 | 规格卡写了六个页面，轮播就能上选款中心 |
| “手机同组间距用 lg”和“UI_GUIDE 把 md 标成后台” | 手机前台不用 md | 手机标题和正文之间用 16px |
| “D.42 已经写入标准”和“现在做不出轮播” | 规则是目标态。合同和渲染器落地前不能创建，也不能用脚本拼一个临时轮播 | 标准里有了就可以在页面上先做出来 |
