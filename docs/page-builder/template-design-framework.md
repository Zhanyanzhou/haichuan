## 2. 一套编辑器、两种工作模式

### 2.1 Shared Editor Core 是唯一编辑器底座

产品不是两个独立编辑器，而是一个 Shared Editor Core 下的两种工作模式：页面装修模式和模板设计模式。当前模板组件库、结构面板、Canvas、属性面板四区主体框架与顶部工具栏继续保留；不得因为两种模式的用户任务不同而复制 Page Editor、Template Editor、Page Canvas、Template Canvas 或另一套基础控件体系。

以下能力原则上属于共享底座：Editor Shell、模板库基础 UI、Template Repository Client、Renderer、Canvas 基础能力、结构树基础组件、属性面板引擎与字段控件、Selection 基础能力、Hover、设备视口、缩放、Preview、素材与图片选择、History Engine、Undo/Redo 基础设施及保存基础设施。实现可以按职责拆分组件和模块，但不能形成可独立漂移的第二套业务能力。

两种模式的差异集中在 Mode Interaction Policy / Capability / Permission：选择粒度、Canvas 可执行命令、结构树展示深度、属性可见范围、工具栏业务动作、保存对象和发布动作。权限必须同时约束命令、快捷键、拖拽、写入入口和服务端业务边界，不能只隐藏按钮。模式判断应集中在策略或能力层；允许在模式入口和组合边界分派实现，不得把大量 `if (pageMode)` / `if (templateMode)` 散落到共享控件和 Renderer 中。

共享底座不表示共享业务会话。页面与模板模式可以并且必须隔离各自的 selection、history、dirty、preview 和 save state，防止模板操作写入页面草稿；这种状态隔离不得被实现成两套重复编辑器。

### 2.2 页面装修模式：模板组合与内容配置

页面装修模式以 Template Instance 为主要操作粒度，负责使用、添加、排列、复制、删除、显示/隐藏模板，修改模板明确允许的实例内容，完成预览、保存和发布页面。页面 Canvas 的职责是 Preview + Selection + Arrangement，不是模板内部自由视觉设计。

页面 Canvas 可以展示实际效果、Hover、选择模板实例、整体排序和通过命中模板内部可编辑内容定位右侧属性面板。内部命中的语义是 `Template Instance + 可选的 field/slot focus`：结构树仍选择该模板实例，属性面板切换或滚动到对应的页面可编辑字段；它不把内部内容升级成页面级 Node，不显示移动或 Resize 手柄，也不允许拖动文字/图片、改变内部布局、调整嵌套、执行公开链接或直接触发上传器。命中未声明为页面可编辑的内容时回退到模板实例的总体属性上下文。

页面结构面板只展示 Page 与 Template Instance 层级，不默认展开模板内部完整 Node Tree。结构树底层组件可以与模板模式共享，但页面模式不得通过展示完整 Node Tree 变相开放内部设计能力。

### 2.3 模板设计模式：模板视觉设计

模板设计模式负责创建和修改 Template 本体，遵循 Canvas First / Mouse First。它可以在同一 Canvas 与 Renderer 上开放节点级 Select、Hover、Drag、Drop、Move、Sort、Resize、Nest、Parent/Child、Duplicate、Delete、Copy/Paste、Keyboard Shortcut、Alignment 和合同允许的布局操作；结构面板展示完整 Template Node Tree，属性面板显示完整内容、布局、样式、高级属性与“页面可编辑”配置。

模板设计模式中的自由度仍受节点注册表、嵌套规则、画框、尺寸、安全令牌、品牌与发布合同约束，不等同于任意 HTML/CSS 或无边界 Figma 式画布。

### 2.4 一个 Template Repository，两类保存对象

产品只维护一个 Template 业务模型和一个 Template Repository。页面装修与模板设计必须读取同一 Template Query、Search、Category、Card、Thumbnail 和目录数据；分类、标签、来源、用途和状态只属于 Template metadata，不得据此另建 PageTemplate、SectionTemplate、ComponentTemplate、BlockTemplate 或“页面模板数据 / 模板设计数据”两套业务模型。当前兼容层中的技术名称不构成新的产品模板类型。

模板模式负责新建、打开、修改、复制、启用/停用和发布 Template；启用且满足当前可见性规则的 Template 自动进入页面装修模板库。页面模式负责浏览、搜索、预览、使用并加入页面。差异通过 mode/action/permission 控制，不复制 Repository 或目录合并逻辑。

Template 是模板本体，Template Instance 是 PageDocument 中对模板的使用。页面模式只写入当前 Page 及其实例内容/允许覆盖，不能直接修改 Template Repository、其他实例或其他页面；模板模式保存 Template，不能把模板草稿写入当前 PageDocument。共享保存基础设施不得把 Page 与 Template 设计成同一业务对象。

具体实例序列化、版本绑定和兼容读取继续以当前已批准合同与实现为准。本规则不授权重新设计 Template、Page、Node、Template Instance Schema、持久化或版本模型，也不授权提前扩展 Slot、Variant、Inheritance、Auto Sync、CMS Binding、Realtime Collaboration 或 Plugin System。

### 2.5 共享 Renderer、Tree 与 Property Panel

Canvas、Preview、缩略图和最终页面应尽可能消费同一套 Rendering Logic；编辑器装饰、选择框和交互层可以按模式叠加，但不得复制业务 Renderer。设计结果、预览和公开结果的差异只能来自明确的编辑态装饰、权限或运行时数据，不得来自三套独立渲染规则。

页面和模板模式共享 Property Panel Engine 与 TextInput、NumberInput、Select、Switch、ColorPicker、ImagePicker、AssetPicker、LinkEditor、FocalPoint、Spacing、Typography、Border、Radius 等基础控件。模板设计定义属性以及哪些字段“页面装修时允许修改”；页面属性面板根据 Template 的 page-editable 配置自动生成或过滤字段，禁止每新增一个 Template 就硬编码一套页面表单。产品 UI 使用“页面可编辑”等用户语言，不优先暴露 exposed props / property exposure 等工程术语。

### 2.6 任务与变更治理

审计、检查和现状分析保持只读；规划任务只形成方案；只有用户明确要求实现、修改、开发或执行具体 Task 才进入写入。新任务先核对现有 Component、Hook、Store、Service、Schema、Utility、Renderer 和 Editor interaction，优先复用或扩展共享能力。

未经当前任务明确授权，不得修改 Template、Page、Node、Template Instance Schema，不得更换持久化、状态管理、Drag & Drop、Renderer 架构，不得拆分 Page Editor / Template Editor、删除兼容逻辑、新增重大依赖或复杂抽象层。范围外问题只报告，不顺手重构、改 UI、升级依赖、删除代码或降低测试门禁。具体权限与执行流程仍只认 `AGENTS.md` 和 `WORKFLOW.md`，本节不建立第二套审批规则。

## 3. 稳定设计边界

### 3.1 模板是完整根构图

模板是可插入、复制、排序和删除的完整内容区块。产品只有一套母模板模型：所有新建、设计、保存、发布和页面装修使用统一的 `TemplateDefinitionV2`。每个母模板必须在机器合同中声明一个主要商业目的（品牌展示、商品销售、活动转化、内容传播或信任建立），并用节点结构、槽位与行动能力落实该目的。既有系统/个人记录只作为兼容读取和历史页面重放来源，选择后直接载入统一母模板编辑器，不再向运营者暴露另一种模板格式。模板内部对象不得降级为页面根画布散件，组件库商业分类也必须来自合同元数据，不能手写第二份分类。

页面运营可以替换内容并使用合同声明的少量实例覆盖，但不得在页面属性面板改变模板身份、语义角色、槽位数量、阅读顺序或行动上限。模板结构与默认构图只能由管理员在同一 Editor Shell 中切换到顶部“模板设计”工作模式，再从共享模板目录打开或新建母模板后编辑。页面装修中的模板组件库只负责点击添加、拖拽插入和显式升级当前页面实例，任何模板卡片或页面快捷操作都不得绕过模式权限直接修改模板。两种模式必须复用顶部设备切换、模式页签、撤销/重做、预览、保存、更多和发布等控件原语，并由 mode policy 决定动作、对象与可用状态；共享 UI 不得合并两套业务会话。模板草稿拥有独立选择、设备、历史、脏状态、预览和保存状态，不写入当前 `PageDocument`。当前页面覆盖只属于该实例，不得反向改写模板或其他页面。

### 3.2 三类编辑边界

- **统一母模板定义**：`TemplateDefinitionV2` 使用稳定 `templateId` / `nodeId` / `slotId`、注册节点类型、嵌套约束、共享内容与双端几何规则；模板身份、语义角色、槽位、默认构图、阅读顺序和行动上限由合同、定义与 Renderer 共同落实，结构增删和父子关系调整只发生在模板模式会话。
- **统一目录**：页面装修与模板设计只消费服务端统一母模板目录。正式版本、当前账号可见的兼容来源与超级管理员可编辑草稿由服务端一次聚合；前端不得重新建立系统、个人、正式、草稿四套并行请求与合并规则。兼容来源标签只解释数据出处，不构成产品模板类型。
- **保存与版本**：“覆盖模板”更新同一 `templateId` 的草稿；“另存为模板”创建新的 `templateId`。发布只创建下一个不可变模板版本，不修改任何页面。页面实例锁定插入或显式升级时选择的精确版本，不能因母模板后续覆盖或发布而静默变化。
- **默认、示例与空内容**：`defaultContent` 是页面实例可以继承的业务初值，`previewContent` 只用于模板设计与目录预览，不得进入公开页面。Slot 的 `emptyPolicy` 只能是 `hide` 或 `use-default`：显式清空时分别隐藏或恢复默认值；编辑态仍保留可选择的空槽占位。复杂对象必须按嵌套字段的真实内容判断空值，不能把 `{}`、空数组或全空字段误判为有效内容。
- **复杂组件写入边界**：母模板的布局、比例和样式写入节点设计属性，业务示例或默认值写入所选内容层；页面实例只编辑内容和合同允许的稀疏覆盖。三类数据不得相互覆盖或复制成第二份事实源。
- **页面实例独立**：同一页面根 `content` 中相同 `moduleType` 的实例不再自动共享设计，新插入实例使用所选模板保存的布局。旧页面现有 `__instanceOverrides.version=2` 继续按原值读取、保存和公开渲染，不自动转换或批量统一。桌面和移动几何独立，连续值必须受合同范围与模板画框约束。
- **内容编辑**：素材、文字、合法链接和业务对象可以替换；商品、门店、活动、预约和服务等事实必须引用各自业务来源，文档只保存稳定引用与实例配置，不复制第二份业务事实。

自由构图仍不是任意页面生成器：母模板只能新增注册表允许的节点并遵守父子嵌套、数量、尺寸与安全令牌约束，不得接受任意 HTML/CSS、无界坐标，或把模板内部角色移出模块画框。合同允许的对象可互相重叠并调整层级；普通重叠、激进裁切和文字拥挤只提示，不自动改写用户构图。合同未声明覆盖值的旧文档继续按系统默认渲染；历史 revision 不改写。

具体模板允许什么，以当前机器合同为准。本文件不列选项和值。

### 3.3 双端合同与中间宽度结果必须成立

机器合同分别声明桌面与移动两端的默认构图、结构、素材适配和阅读顺序。两端布局独立编辑、独立保存；移动端不是桌面机械缩小版，也不得因编辑一端而隐式覆盖另一端。

768–1199px 等中间宽度可以使用纯 CSS 调整网格、留白与文字排布，但素材来源、比例和阅读顺序继承桌面合同，不得建立第三个设备合同或内容来源。实际验收仍需覆盖手机、边界宽度、中间宽度和完整桌面。

图片比例是槽位素材规则，不等同于根模块高度。不得用单张海报画布比例反向决定网页模板结构。

### 3.4 真实状态与安全降级

模板实现应覆盖实际可能出现的空、加载、失败、完成和发布状态。缺少真实素材时使用明确的中性占位或合同规定的安全行为，不生成虚假珠宝、证书、价格、库存、活动或服务承诺填补空缺。

旧内容的兼容、迁移、退役和发布阻断必须根据当前数据模型与服务端校验设计；普通保存不得把未迁移区块静默描述为新合同版本。

### 3.5 Inspector 能力必须完整

Inspector 不是功能陈列层。任何可见控制项都必须沿同一事实链工作：控件状态 → `PageDocument` → 草稿保存 → 刷新回显 → 画布预览 → 发布校验 → 公开 Renderer。链路涉及异步业务对象时，还必须覆盖加载、空、失败、成功、请求失效、无效引用和恢复路径；只存在入口或局部 UI 不构成完成。

字段顺序从页面实例任务推导，不使用一份通用长表单覆盖全部模板：媒体模板先媒体，商品模板先真实商品选择，结构化业务模板先业务对象，文字主导模板先文字。页面属性面板只呈现实例内容、素材、链接、显隐和合同允许的少量实例覆盖，不再提供“模板编辑”页签或“另存到模板库”入口。模板设计只从编辑器顶部切换到同一 Editor Shell 的“模板设计”模式，再由共享模板目录打开或新建母模板；四区依次呈现模板组件库、完整模板结构面板、真实 Renderer 画布和模板属性面板。页面与模板目录复用搜索、用途分组、单列/双列切换、卡片尺寸和折叠规则；点击分别执行“添加到页面”和“打开进行设计”，拖拽仅作为辅助。两种模式复用树行、画布工具和属性字段组件，但页面实例树与模板语义节点树、页面实例覆盖与模板定义写入目标必须保持独立。页面 `LayerRail` 始终保持页面模块功能，不因模板设计切换职责。

页面工作空间的画布以整个模板实例为主选择。鼠标或触控命中模板内部已声明为页面可编辑的图片、文字、行动或业务对象时，可以附加 field/slot focus 并让右侧属性面板定位到对应字段；不得因此把内部对象加入页面结构树、显示移动/缩放手柄、触发上传器、素材选择、公开跳转或内部构图。命中不可编辑内容时保持模板实例的总体属性上下文。模板设计模式不受这一受控定位限制，可按节点注册表和机器合同选择、移动、缩放及配置母模板内部节点。

行动对象统一提供不跳转、商品、分类、页面和 HTTPS 外链五种互斥目标；商品与分类必须从真实引用控件选择，页面必须来自公开页面合同，外链仅接受完整 HTTPS 地址。切换目标类型必须清除其他类型的残留字段，服务端发布门禁与公开 Renderer 使用同一合同解释。视频对象除来源与封面外还提供视频说明，并明确呈现加载、可读取、失败、重试、更换与清除状态。

生成物中的 `CONTENT_TEMPLATE_EDITOR_ACCEPTANCE_MATRIX` 是 24 个活跃模板的机器可读验收矩阵，记录固定对象、内容字段、能力、边界、层级和双端默认几何；合同生成检查必须阻止任何活跃模板或适用对象缺失矩阵能力。

旧页面、历史 revision 与未保存页面草稿保留各自已有设计差异，不再要求同类设计一致，导入、刷新和历史恢复不得静默统一。未知或越界覆盖、零尺寸、必需对象隐藏及可确定被完全遮挡的行动对象仍按当前发布合同处理。统一母模板已建立 Schema、稳定节点树、通用 Renderer、同源语义校验、服务端草稿、不可变版本、精确页面实例与稀疏覆盖。模板发布与页面升级严格解耦：发布不读取或修改页面；页面升级必须在页面装修中显式发起、校验、保存草稿并重新发布页面。当前代码和可丢弃隔离 MySQL 证据不能授权连接现有业务库，目标环境 migration、真实页面批量升级和生产切换仍须单独审批。

兼容记录不再是可增长的活动模板体系：读取仍按原权限隔离，只用于旧页面重放和载入统一母模板编辑器；旧模型对外创建、更新、复制、重命名和删除入口保持关闭。首次覆盖兼容来源时建立对应的稳定统一模板身份，另存则建立全新身份；兼容记录、旧页面和当前页面草稿均不被覆盖。SYSTEM 模板使用 `ownerId=NULL、sourceType=SYSTEM`，CUSTOM 模板按 `ownerId` 隔离；只有 `SUPER_ADMIN` 能设计、保存和发布母模板。任何模板都不得保存价格、库存、客户、订单、支付、门店资料、资质、评价、活动权益或商品/分类解析结果等第二份业务事实。

## 4. 模板变更流程

### 4.1 先判断是不是模板变更

- 换图、改字、换合法链接、选择已有预设或调整合同已经允许的实例覆盖值，是内容编辑，不修改母模板规则。
- 新增模板，或改变槽位、默认比例、设备顺序、允许的实例覆盖能力、根构图、版本或发布校验，是模板变更。
- 只调整实现以恢复合同既有行为，是合同一致性修复；不得顺手扩大模板能力。

### 4.2 模板变更的唯一实施路径

1. 核对当前机器合同、相关 Schema、适配器、Renderer、服务端校验以及真实页面结果。
2. 说明用户结果、兼容范围、存量内容影响、回退方式和需要重新验收的模板。
3. 涉及产品取舍、全局品牌方向、权限、数据或发布语义时，先取得相应批准。
4. 只在权威 JSON 中修改模板事实，运行生成流程同步客户端和服务端只读产物。
5. 调整必要的 Inspector、预览、Renderer 和发布校验，使它们消费同一合同；不得手工复制同一字段。
6. 按受影响范围完成合同检查、类型检查、目标测试和真实浏览器验收。

不再要求为每个模板维护永久设计卡。临时方向稿、截图或方案只服务当次决策；确需长期保留的产品取舍写入 `docs/DECISIONS.md`，执行事实仍只进入机器合同。

## 5. 验收边界

- 合同结构或值变更：运行合同生成一致性检查和内容模板目标测试。
- 单模板实现变更：检查该模板在编辑器、预览和公开 Renderer 的受影响视口与关键状态。
- 共享 Renderer、顺序、高度或合同结构变更：所有当前活跃模板执行真实浏览器自动 DOM、顺序、非坍塌和溢出检查，人工视觉按风险抽样。
- Inspector 新能力：除对应范围外，验证默认/继承/覆盖/重置、保存与刷新回显、画布和公开端一致性、发布阻断、旧文档默认兼容；业务对象选择器还要验证搜索、筛选/分页、失效请求、去重、排序、数量边界、已选项解析与不可用原因。
- 品牌表达变更：另按 `docs/UI_GUIDE.md` 检查排印、图文层级、响应式、无障碍和性能。
- 发布与兼容变更：验证成功、失败、未知版本、类型不匹配和存量内容路径；静态合同检查不能替代真实发布联调。

构建成功只证明构建；合同通过只证明声明一致；单张截图只证明一个瞬间。完成结论必须限定在实际检查过的范围内。

## 6. 当前事实的读取顺序

出现文档、代码和页面不一致时，按以下顺序取证：

1. 实际运行与真实页面；
2. 当前机器合同、代码、类型、Schema 和配置；
3. 已核对的当前状态文档；
4. 决策记录与历史归档。

旧设计卡、旧蓝图、静态 HTML 预览和历史比例表不得覆盖当前合同或真实实现。发现冲突时暂停修改并报告，不在多个文件之间选择最顺眼的一套。
