# 页面内容模板规则

> 当前入口：本文件只规定模板体系的稳定边界与变更流程。
> 模板清单、状态、槽位、比例、顺序、预设、内容预算和预览结构只认 `contracts/page-builder/content-templates.contract.json`。
> 品牌视觉、排印、颜色、响应式、无障碍与性能只认 `docs/UI_GUIDE.md`。
> 最近核对：2026-08-20（模板规则单一来源收敛）。

---

## 1. 只保留两个现行来源

| 来源 | 唯一职责 |
| --- | --- |
| `contracts/page-builder/content-templates.contract.json` | 程序可执行的模板事实；客户端、服务端、预览和校验从它生成或读取 |
| 本文件 | 人需要理解的稳定原则、修改流程和验收边界；不重复合同字段与模板清单 |

其他文件的职责：

- `docs/UI_GUIDE.md` 负责品牌和体验标准，不保存模板字段。
- `docs/DECISIONS.md` 只记录已批准的长期取舍及原因，不充当当前模板台账。
- `PROJECT_RULES.md` 与 `WORKFLOW.md` 只声明项目硬边界和执行门禁，并引用本文件与机器合同。
- 生成的客户端、服务端 TypeScript 文件是构建产物，不是第二份可手工维护的规则。
- 适配器、Schema、Renderer 和样式是合同消费者；实现与合同冲突时先报告，不用局部默认值建立平行事实。
- `docs/archived/` 下的模板文档和静态预览只用于历史追溯，不具现行约束力。

禁止新增按模板手写的比例表、槽位表、状态表、静态缩略图规则或另一份前后端合同。需要了解某个模板时直接查询机器合同和当前实现。

## 2. 稳定设计边界

### 2.1 模板是完整根构图

模板是可插入、复制、排序和删除的完整内容区块。图片、文字、行动和业务对象是模板内部的语义角色，不是可在根画布任意拖动的散件。

运营可以替换内容并使用合同声明的实例覆盖能力，但不得借此改变模板身份、语义角色、槽位数量、阅读顺序、行动上限、默认响应式结构或品牌体验底线。母模板保存默认构图与能力边界；当前页面的覆盖只属于该 `PageDocument`，不得反向改写母模板或其他页面。

### 2.2 三类编辑边界

- **固定身份**：模板身份、语义角色、槽位数量、默认设备构图、阅读顺序和行动上限等由合同与 Renderer 共同落实。
- **受控实例覆盖**：只提供机器合同按模板声明的能力。可包括整体画面比例/高度模式、图片槽位比例与安全区内的位置/尺寸关系、焦点裁切，以及可选文字角色的位置、宽度、字号、对齐和颜色；优先使用预设，连续值必须有最小/最大值、响应式回退、溢出与对比度保护。未声明的控制项不得在 Inspector 中自行出现。
- **内容编辑**：素材、文字、合法链接和业务对象可以替换；商品、门店、活动、预约和服务等事实必须引用各自业务来源，文档只保存稳定引用与实例配置，不复制第二份业务事实。

受控实例覆盖不是自由设计器：不得允许任意 HTML/CSS、无界坐标、任意新增图层，或把模板内部角色拆散到根画布。合同未声明覆盖值的旧文档必须继续按母模板默认值渲染；重置单项或模块时应可恢复默认，不得影响其他页面。

具体模板允许什么，以当前机器合同为准。本文件不列选项和值。

### 2.3 双端合同与中间宽度结果必须成立

机器合同只声明桌面与移动两端的结构、素材适配和阅读顺序。移动端不是桌面机械缩小版；端点间的继承、回退或重排必须来自合同和当前实现。

768–1023px 等中间宽度可以使用纯 CSS 调整网格、留白与文字排布，但素材来源、比例和阅读顺序继承桌面合同，不得建立第三个设备合同或内容来源。实际验收仍需覆盖手机、边界宽度、中间宽度和完整桌面。

图片比例是槽位素材规则，不等同于根模块高度。不得用单张海报画布比例反向决定网页模板结构。

### 2.4 真实状态与安全降级

模板实现应覆盖实际可能出现的空、加载、失败、完成和发布状态。缺少真实素材时使用明确的中性占位或合同规定的安全行为，不生成虚假珠宝、证书、价格、库存、活动或服务承诺填补空缺。

旧内容的兼容、迁移、退役和发布阻断必须根据当前数据模型与服务端校验设计；普通保存不得把未迁移区块静默描述为新合同版本。

### 2.5 Inspector 能力必须完整

Inspector 不是功能陈列层。任何可见控制项都必须沿同一事实链工作：控件状态 → `PageDocument` → 草稿保存 → 刷新回显 → 画布预览 → 发布校验 → 公开 Renderer。链路涉及异步业务对象时，还必须覆盖加载、空、失败、成功、请求失效、无效引用和恢复路径；只存在入口或局部 UI 不构成完成。

字段顺序从模板任务推导，不使用一份通用长表单覆盖全部模板：媒体模板先媒体，商品模板先真实商品选择，结构化业务模板先业务对象，文字主导模板先文字。当前属性面板成熟化阶段以 Inspector 为编辑入口、画布为预览结果；画布直接操纵属于另一项需单独批准和验收的能力。

## 3. 模板变更流程

### 3.1 先判断是不是模板变更

- 换图、改字、换合法链接、选择已有预设或调整合同已经允许的实例覆盖值，是内容编辑，不修改母模板规则。
- 新增模板，或改变槽位、默认比例、设备顺序、允许的实例覆盖能力、根构图、版本或发布校验，是模板变更。
- 只调整实现以恢复合同既有行为，是合同一致性修复；不得顺手扩大模板能力。

### 3.2 模板变更的唯一实施路径

1. 核对当前机器合同、相关 Schema、适配器、Renderer、服务端校验以及真实页面结果。
2. 说明用户结果、兼容范围、存量内容影响、回退方式和需要重新验收的模板。
3. 涉及产品取舍、全局品牌方向、权限、数据或发布语义时，先取得相应批准。
4. 只在权威 JSON 中修改模板事实，运行生成流程同步客户端和服务端只读产物。
5. 调整必要的 Inspector、预览、Renderer 和发布校验，使它们消费同一合同；不得手工复制同一字段。
6. 按受影响范围完成合同检查、类型检查、目标测试和真实浏览器验收。

不再要求为每个模板维护永久设计卡。临时方向稿、截图或方案只服务当次决策；确需长期保留的产品取舍写入 `docs/DECISIONS.md`，执行事实仍只进入机器合同。

## 4. 验收边界

- 合同结构或值变更：运行合同生成一致性检查和内容模板目标测试。
- 单模板实现变更：检查该模板在编辑器、预览和公开 Renderer 的受影响视口与关键状态。
- 共享 Renderer、顺序、高度或合同结构变更：所有当前活跃模板执行真实浏览器自动 DOM、顺序、非坍塌和溢出检查，人工视觉按风险抽样。
- Inspector 新能力：除对应范围外，验证默认/继承/覆盖/重置、保存与刷新回显、画布和公开端一致性、发布阻断、旧文档默认兼容；业务对象选择器还要验证搜索、筛选/分页、失效请求、去重、排序、数量边界、已选项解析与不可用原因。
- 品牌表达变更：另按 `docs/UI_GUIDE.md` 检查排印、图文层级、响应式、无障碍和性能。
- 发布与兼容变更：验证成功、失败、未知版本、类型不匹配和存量内容路径；静态合同检查不能替代真实发布联调。

构建成功只证明构建；合同通过只证明声明一致；单张截图只证明一个瞬间。完成结论必须限定在实际检查过的范围内。

## 5. 当前事实的读取顺序

出现文档、代码和页面不一致时，按以下顺序取证：

1. 实际运行与真实页面；
2. 当前机器合同、代码、类型、Schema 和配置；
3. 已核对的当前状态文档；
4. 决策记录与历史归档。

旧设计卡、旧蓝图、静态 HTML 预览和历史比例表不得覆盖当前合同或真实实现。发现冲突时暂停修改并报告，不在多个文件之间选择最顺眼的一套。
