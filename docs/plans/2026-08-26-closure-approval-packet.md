# 全量闭环的最小批准包

> 核对时间：2026-08-26。本文把当前代码库中已经通过本地验证的内容，与仍需业务决定、数据库/环境授权或真实渠道证据的内容分开。用户已批准本文 A1、EN-A 与 D 的推荐方案；目标环境只读盘点原则获批，但尚缺唯一环境标识。本文仍不构成数据库写入、migration 执行、真实发送、Git 或发布授权。

## 结论

“把所有内容形成闭环”可以作为项目终局目标，但不能作为一次性执行指令。它同时覆盖本地代码、跨语言内容、Schema、目标数据库、真实通知、资金渠道、基础设施和生产发布；如果不按事实源和授权边界拆分，最容易出现三种错误：把静态测试当真实上线、把未来 Schema 当已接线功能、把外部内容或渠道缺失用占位实现掩盖。

当前专业判断是：

1. 保留现有本地候选版本，不回到 HEAD；本地工程门已重新全绿。
2. 继续把标准零售、Puck registry 14、公开商品与后台运营作为近期主线。
3. `/en` 仍是现行 M1 产品基线；除非产品负责人正式修改 `PROJECT_GUARDRAILS.md` 与 `DECISIONS.md`，不能在发布时忽略。
4. 真实通知必须复用 `Notification + NotificationDelivery + OutboxEvent`，不能继续扩散事务后的 fire-and-forget 邮件。
5. 当前最先应获批的外部动作只有“指定目标环境后的只读盘点”；在此之前不应执行 migration、seed、恢复、真实渠道或部署。

- 报价本人范围、优惠券 DTO/冻结/事务重验、后台售后三元关联和通知日志隐私已在本地闭合。
- 标准零售交易合同 63/63；加入 EN-A 与可靠通知第一批后，服务端全量 346/346、根测试、typecheck、lint、双端构建、24 模板合同、环境合同，以及 `/en`/客户通知浏览器合同 2/2 已通过。

## 新确认的设计缺口

### 1. 双语不是补 `/en` 路由

EN-A 已把语言维度贯穿公开路由、客户端 API/SSE 参数和服务端事实源前门禁；英文 availability 默认关闭且初始响应不可索引，因此不会把中文事实伪装成英文。尚未贯穿的是 PageDocument 独立修订/发布、商品/分类/设置英文事实、公共英文 UI 与最终 SEO。Schema 虽已有 `PageDocumentLocalization`、`ProductTranslation`、`CategoryTranslation` 与 `SeoSnapshot`，但 `PageDocumentRevision` 没有 locale/contentHash，`publishedRevisionId` 因而无法可靠证明“同语言不可变修订”。

裁决：保留六个 PageDocument key，不建立 `home-en` 等第二套页面事实；中文无前缀、英文 `/en`。英文缺失必须 unavailable/noindex，不能自动回退中文。

### 2. 通知第一批已形成本地候选，外部链仍未闭环

用户已批准“首批仅认证客户、每笔支付确认产生事实、服务通知与营销分离、订单快照为收件事实源、外部投递默认关闭”。当前订单创建和每笔支付确认已在业务事务内原子写入 Notification、Delivery 与只含内部 ID 的 Outbox；客户通知 API 绑定当前登录客户，Worker 具备抢占、租约、有限重试和保守的未知结果处理，账户注销不会把已取消投递重新激活。

仍未闭合的是目标数据库 migration 状态、真实 MySQL `SKIP LOCKED` 行为、授权测试收件人、SMTP 域名与配置、真实送达/退信证据，以及发货、退款、售后、咨询等后续事件的统一迁移。外部投递继续由 `NOTIFICATION_DELIVERY_ENABLED=false` 安全关闭；渠道“受理”只能记 `SENT`，没有送达回执不能记 `DELIVERED`。

### 3. 目标环境尚不可部署

- `/api/health` 只表示进程存活，`/api/ready` 才检查数据库；Compose 注释已在本轮修正。
- 仓库只有备份脚本，没有当前可执行的恢复脚本；备份默认同宿主机、明文、7 天保留，媒体归档也不是原子快照。
- 当前完整 seed 会同时创建默认仓库和已发布样例商品，不适合充当生产首管理员初始化。
- 微信支付证书路径变量已登记，但容器没有对应证书目录只读挂载。真实微信渠道不得因“变量合同通过”而开启。
- 当前 Compose 只有 HTTP 80；正式 TLS/443、续期、HSTS 与唯一终止点尚未实施。

## 推荐的后续批次

### A. 立即可做的本地决定

1. `G:\网站搭建2\client\NUL` 已获精确批准并完成删除。它是本轮 Windows 检查命令误生成的 45 字节测试结果 JSON，SHA-256 `91d1c43004802cd49950d78eb11c8fa7d05da8ffffe219a8b13b2f561bc00903`，没有业务用途；只删除了这一项。此前因 PowerShell 保留名语义产生的“全零文件”判断已纠正。
2. 确认 `/en` 是否继续作为 M1 硬门禁。推荐保留；若要延期，必须明确修改产品基线和发布范围，不能只在实现中忽略。
3. 若保留 `/en`，批准 EN-A：只实现统一 locale 类型、路由/SEO/noindex/API locale 安全轨道，英文 availability 默认关闭，不显示语言切换、不进入 sitemap、不创建占位英文内容。

### B. 目标环境只读盘点

需提供唯一环境名称、主机/平台 ID、数据库名、只读访问方式和负责人，并明确批准以下只读动作：

- 核验部署版本、镜像 digest、端口、TLS、挂载、卷、健康探针和脱敏日志；
- 无副作用请求前台、后台、`/api/health`、`/api/ready`；
- 用只读数据库账号检查 `_prisma_migrations`、目标表/列、Schema drift、孤儿 revision 和关键表行量；
- 只报告 Secret 是否存在及其来源/权限/轮换状态，不读取或回显值；
- 读取备份元数据和既有恢复记录，不打开真实 dump、媒体或业务明细。

本批禁止写库、migration、seed、容器/配置变更、真实发送和业务数据导出。

### C. Schema 与双语发布技术闭环

只有 B 的目标库状态明确后，才决定处理方式：

- 若任何非临时数据库已应用第 41 个 migration：不得改 checksum，使用前向修复 migration。
- 若所有非临时数据库都未应用：再评估是否在批准后修正/拆分当前 migration。

实施内容包括 locale-specific revision/hash/唯一约束、同语言发布指针、稳定 canonical hash、`pageKey + locale` 缓存/SSE/API，以及商品、分类、设置的严格 locale 查询。修改 Prisma Schema 和 migration 文件仍需单独批准；执行 migration 是另一项批准。

### D. 通知最小闭环

开始前需签认：

- 支付通知按每笔确认还是仅收齐；推荐每笔产生事实并明确剩余应收状态；
- 服务通知与营销同意分离；
- 收件地址采用订单快照还是客户当前档案；
- 首批是否只覆盖有 `customerId` 的认证客户订单；推荐是，避免把明文联系方式塞入 Outbox payload；
- 外部渠道安全默认关闭，真实测试收件人、费用、时间窗和操作人另批。

首批只接订单创建和支付确认；重复回调/主动查单/人工重复提交必须命中确定性去重键。之后再迁移发货、取消、完成、咨询回复，并统一订单中心与履约中心两个发货入口。退款和售后按签认矩阵逐事件进入，不一次性扩张。

### E. 隔离候选环境

在 B/C 完成且另获授权后，使用独立数据库、网络和卷：恢复数据库与两类媒体、演练精确 migration、TLS/CORS/CSRF/Cookie/安全头、health/ready、上传/媒体/SSE、前后台和浏览器路径。交易、支付、退款和真实渠道继续关闭。

进入本批前还需补完：非 seed 的安全管理员初始化、可执行恢复步骤、证书只读挂载、监控告警接收链与 TLS 唯一终止点。

### F. 正式内容、渠道与发布

六页中英文 PageDocument、商品/分类/属性翻译、SiteSettings、法务/交易文案、SEO/CTA、媒体权利必须逐项签认；随后才允许真实保存、审阅和发布。SMTP、短信、微信登录、微信支付、微信退款分别审批，真实支付/退款设金额上限并完成回调、查单、对账与异常回退。最终以不可变发布物、目标库和恢复证据进入 Go/No-Go。
