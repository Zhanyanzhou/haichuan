# 海川珠宝项目固定规则（兼容入口）

> 项目通用且权威的规则已迁移至 `docs/PROJECT_GUARDRAILS.md`。
> 本文件仅用于兼容此前引用此文件的 DeepSeek 对话；所有新任务应以通用文档为准。

> 用途：提供给 DeepSeek 或其他 AI 开发助手的项目总规则。
> 本文件定义项目的固定边界，不是具体功能需求。

## 一、项目定位

海川珠宝（Haichuan Jewelry）是高端珠宝展示、商品管理、品牌内容管理与选款咨询平台。

当前项目重点是：

- 品牌与珠宝作品展示；
- 商品、分类、图片与库存管理；
- 首页与内容页面管理；
- 客户咨询与选款咨询；
- 后台数据统计与线索跟进。

当前不是完整开放的真实电商交易系统。支付、退款、真实资金处理暂未开放。

## 二、不可擅自改变的技术框架

除非项目负责人明确批准，不得替换、升级或删除以下技术：

- 前端：React 18、TypeScript、Vite；
- UI：Ant Design 5；
- 样式：Tailwind CSS 3 与现有全局样式体系；
- 状态：Zustand；
- 后端：NestJS 10；
- ORM：Prisma 5；
- 数据库：MySQL 8；
- 缓存与队列：Redis、Bull；
- 认证：JWT + bcrypt；
- 图片处理：Sharp；
- 页面构建器：现有 Puck 相关代码与 EditorWorkbench 体系。

禁止因为“更方便”而改成 Next.js、Vue、Element Plus、Express、MongoDB、Firebase 或其他技术方案。

## 三、不可擅自改变的目录边界

- `client/`：前端项目；
- `client/src/pages/`：页面；
- `client/src/components/`：可复用组件；
- `client/src/services/`：前端接口与模拟数据层；
- `client/src/store/`：前端状态；
- `client/src/page-builder/`：页面构建器；
- `server/src/modules/`：后端业务模块；
- `server/src/common/`：后端通用能力；
- `server/prisma/`：数据库结构与种子数据；
- `docs/`：项目文档；
- `uploads/`：上传文件存储。

不要移动、重命名或删除上述核心目录。新增文件必须放在职责对应的目录中。

## 四、固定业务边界

### 已有核心业务

- 商品：创建、编辑、发布、上下架、图片管理；
- 分类：树形分类与分类管理；
- 库存：库存、仓库、安全库存预警；
- 金价：手动维护与历史记录；
- 咨询：客户咨询、选款咨询、线索跟进；
- 内容：首页模块、内容槽位、站点设置、SEO；
- 用户：登录、JWT、角色权限；
- 分析：行为事件与后台统计。

### 暂不开放的业务

- 真实支付；
- 退款和资金结算；
- 真实订单交易闭环；
- 未经确认的购物车与结算上线；
- 未经确认的第三方物流、短信、微信支付或支付宝接入。

任何任务涉及以上暂不开放业务，必须先给出方案并等待确认，不得直接实现或打开开关。

## 五、固定接口原则

前后端使用统一响应结构：

```json
{
  "code": 200,
  "data": {},
  "message": "success",
  "timestamp": "..."
}
```

所有新增或修改接口必须明确：

- HTTP 方法与路径；
- 请求字段及类型；
- 返回字段及类型；
- 是否需要 JWT；
- 角色权限；
- 参数校验；
- loading、empty、error 状态；
- 失败后的用户提示；
- 是否会写入数据库。

修改接口前，必须同时检查 `client/src/services/api.ts` 与对应的 NestJS Controller、Service 和 DTO。

## 六、固定前端体验规则

- 所有异步页面必须处理 loading、empty、error 三态；
- 表单必须有必填校验、提交中状态和失败提示；
- 删除、发布、上下架、确认等危险操作必须二次确认；
- 不得通过假数据掩盖真实接口错误；
- 页面必须支持桌面端和移动端；
- 重点断点至少检查 1440、1024、768、390 像素；
- 保持现有高端、克制、东方、现代的珠宝品牌气质；
- 不得随意加入霓虹渐变、廉价卡片、过度圆角、无意义动画或模板化营销文案。

## 七、固定视觉规范

品牌主色：`#B8944E`。

品牌辅助色：`#D4B87A`、`#9F7941`。

正文与标题使用现有字体体系：

- 英文品牌标题：Cormorant Garamond、Garamond、serif；
- 中文标题：Noto Serif SC 或现有宋体回退；
- 正文：系统无衬线字体。

页面最大宽度、后台侧边栏、间距与主题配置优先遵守 `docs/UI_GUIDE.md`、`client/src/styles/antdTheme.ts` 和现有全局样式。

新代码优先使用现有 Tailwind 类名；动态计算值才使用行内样式。

## 八、固定内容真实性规则

- 不得编造品牌成立年份、认证、产地、宝石等级、材质参数、库存数量或销量；
- 商品价格、库存、金价必须以接口或明确提供的数据为准；
- `TODO` 文案只能替换为经过确认的内容；
- 图片占位内容必须标注为占位，不得伪装成真实商品摄影；
- 不得把未经确认的宣传语写入正式商品或品牌内容。

## 九、固定安全与隐私规则

- 不得读取、输出或修改 `.env` 中的真实值；
- API Key、Token、密码不能进入代码、日志、截图、提交记录或提示词；
- 客户姓名、电话、地址、邮箱、咨询正文不得发送给模型作为无关分析数据；
- 所有后台写操作必须检查 JWT 和角色权限；
- 不得关闭认证、权限、限流或错误处理；
- 不得为了测试真实支付、真实短信或真实业务数据而调用生产服务。

## 十、AI 服务使用规则

现有 AI 代码位于：

- `server/src/common/kimi/`；
- `server/src/modules/ai-classify/`。

DeepSeek 可以优先用于：

- 商品描述与 SEO 文案草稿；
- 页面内容草稿；
- 接口对照与代码审查；
- 测试用例生成；
- 小范围重构建议；
- 客服回复草稿。

不得未经确认将 DeepSeek 直接替换图片识别、支付、订单、金价或权限核心逻辑。

API Key 只能存放在服务端环境变量中，不能放进 `client/` 或浏览器代码。

## 十一、固定开发流程

每个任务必须按照以下顺序执行：

1. 先说明现状和证据；
2. 再给出最小改动方案；
3. 列出影响文件；
4. 标明风险与需要确认的事项；
5. 获得确认后再输出代码；
6. 修改后运行类型检查、构建或相关测试；
7. 汇报实际修改文件和验证结果。

不得把“审计、方案、实现、重构、删除”混成一个未经确认的大任务。

## 十二、必须暂停并请求确认的情况

出现以下任何情况时，必须暂停：

- 需要修改数据库 Schema 或执行迁移；
- 需要新增、升级或删除依赖；
- 需要修改 `.env` 或配置真实密钥；
- 需要删除文件或大范围移动文件；
- 一次影响 10 个以上文件；
- 需要改变技术栈或核心目录；
- 需要开启支付、真实交易或生产环境；
- 需求与本固定规则冲突；
- 当前代码和文档描述不一致，无法判断真实行为。

## 十三、每次任务的标准输出格式

```text
# 结论
# 现状与证据
# 最小实施方案
# 影响文件
# 风险与待确认项
# 验收标准
# 代码补丁（只有获得明确确认后才输出）
# 验证结果
```

本文件只定义项目固定边界。具体功能需求必须另行说明，不能把本文件当成一次性“修改整个网站”的授权。
