> 版本：专业版 v11 · 最后更新 2026-09-03（页面构建器章节只保留可见界面与交互，不再重复模板数据模型和生命周期）
> 方向来源：产品定位、品牌原则和公开页面职责只认 `docs/PROJECT_GUARDRAILS.md`；本文件不独立定义项目方向。
> 项目与品牌基线的视觉投影：**高级珠宝品牌级数字体验**——安静、克制、精准、有文化质感，以珠宝与工艺为视觉中心。

## 标准一 · 项目与品牌基线的视觉投影与适用范围

### 1.1 品牌目标的视觉承接

本节不重新定义海川珠宝是什么。视觉与交互必须把 `docs/PROJECT_GUARDRAILS.md` 确立的产品定位转化为可观察结果：突出作品、材质、工艺与服务的可信度，并避免呈现为批发商城、促销会场、通用 SaaS 模板或短期流量落地页。

客户前台的五个体验支柱：

1. **作品为主角**：第一视觉焦点落在珠宝、佩戴关系或工艺细节上，而不是装饰、价格或按钮。
2. **信息有秩序**：内容少而准确，层级稳定；极简不等于隐藏必要信息。
3. **服务有分寸**：转化以探索系列、预约鉴赏、定制咨询、选款咨询为主，不使用强迫式成交话术。
4. **品质可验证**：视觉质量、内容真实性、性能、无障碍和移动端体验同时达标，不能以“高级感”为由牺牲可用性。
5. **旅程有连续性**：每个 CTA 都准确承接当前作品或服务上下文，点击后的页面、表单、空态和人工服务继续同一意图，不用无关跳转制造表面上的“可操作”。

本规范中的“高级珠宝品牌级”描述的是体验质量，不证明品牌拥有“世家”、历史传承、奖项、认证或行业地位。任何此类对外表述必须由品牌负责人提供证据并单独审核。

成熟奢侈品的共性只能提供质量底线，不能代替海川的品牌识别。当前 Cormorant Garamond、香槟金识别点及任何通用东方纹样都只是受控实现选项，不是已经确立的永久品牌资产。正式品牌系统上线前必须分别确认 Logo 锁定与最小使用规则、字体授权及中英文字体关系、统一影像语言、可持续的品牌母题和对外文案语汇；未确认时继续使用中性系统，不用临时默认值虚构品牌传统。

### 1.2 规则级别

- **硬规则**：涉及已批准品牌资产与核心识别、内容真实性、可访问性、版权或安全；不满足不得交付。
- **默认规则**：成熟奢侈品网站的推荐基线；确有页面目标时可例外，但必须说明理由并用与改动相称的真实页面证据验收。
- **参考值**：用于快速判断的经验范围，不作为机械像素检查；视觉结果和用户任务优先。

未逐条标注时按以下口径解释：内容真实性、版权、安全、键盘可达、语义和法定对比度属于硬规则；字体比例、栅格、CTA 结构、组件语言和品牌表达属于默认规则；留白比例、动效时长、经验范围与竞品测量属于参考值。带“当前实现”的类名、组件名和路径只描述现状，不自动升级为永久品牌规则。

### 1.3 适用边界

- 本规范完整适用于首页、系列、作品展陈、作品详情、选款中心、品牌故事、定制、联系、隐私及客户前台；它只规定这些职责对视觉层级、CTA、构图、交互状态与无障碍的影响，不重新定义路由、交易或权限规则。
- 页面装修器生成的公开页面必须遵守同一规范；模板不能绕过品牌、内容、性能和无障碍门禁。
- 管理后台不做全局奢侈品化改版；只复用品牌标识、基础色、信息层级、状态完整性、响应式和无障碍规则。后台第一目标始终是清晰与效率。
- 邮件、社交图片、广告和线下物料可参考本体系，但需按各媒介单独验收，不能直接把网页截屏当成成品。

### 1.4 视觉决策顺序

任何前台视觉任务按以下顺序推进：

1. 先看真实页面或截图；无图时明确标记为假设，不得凭空评价。
2. 明确页面任务、目标受众和唯一主焦点。
3. 先确定内容与信息层级，再定版式，最后选择图片和动效。
4. 优先删减无效元素，不用装饰掩盖内容或素材问题。
5. 在真实桌面与移动端页面中验收，而不是只看代码或孤立组件。

### 1.5 客户旅程与页面任务

成熟奢侈品网站不是只追求视觉停留，而是用克制的节奏完成四个连续任务：

1. **发现**：让用户快速理解本页的作品、系列或服务主题；
2. **理解**：提供足够的材质、工艺、尺寸、价格或服务信息，不让摄影替代事实；
3. **信任**：展示可核验的品牌信息、隐私说明、服务条件、联系与售后路径；
4. **行动**：在合适时机引导探索、收藏、选款、预约、咨询或已批准的购买流程。

成熟品牌的服务关系不止发生在成交按钮：预约前说明、咨询后的下一步、定制过程、交付、养护与售后都属于数字款待。海川只展示当前真实可提供且已经批准的服务，不为模仿成熟品牌虚构门店、时效、保修、养护或终身服务；已公开的服务入口必须保持上下文、状态和联系路径连续。

新建或实质改版的关键客户旅程页面必须声明一个主要用户任务和一个主要成功信号；局部修复、隐私页、错误页和法规内容沿用既有页面任务，不为形式新建 KPI。没有分析基础设施时可使用内容理解、咨询完成、关键事实可达、错误恢复或性能/无障碍达标等可验收信号。不得只以点击率或成交率牺牲品牌信任；禁止虚假稀缺、预选同意、隐藏费用、阻碍退出等暗黑模式。

### 1.6 页面职责的视觉投影

公开页面职责只认 `docs/PROJECT_GUARDRAILS.md` 第 2 节；身份、数据可见性、交易资格与开关只认 `docs/PUBLIC_ACCESS_MATRIX.md`。本节不复制业务规则，只规定它们在界面上的可观察结果：

| 场景 | 视觉、CTA、构图与状态影响 |
| --- | --- |
| 品牌叙事与作品展陈 | 以编辑影像、作品和短章节建立单一焦点；作品链接、预约或咨询保持克制，不在叙事画面内堆叠结果工具、价格、库存或购买控件。 |
| 选款中心 | 搜索、筛选、排序、结果与选款操作形成清楚的任务层级；loading、empty、error、无结果、已选与不可用状态均须稳定占位并给出下一步。 |
| 统一作品详情 | 大图与作品事实优先，主行动区按已解析的 `SalesMode` 呈现一个主要 CTA；具体文案层级见 6.2，权限或开关未满足时必须隐藏敏感行动或显示可理解的安全降级。 |
| 账户与合作服务 | 合作申请不占用品牌主导航和公开叙事焦点；适用的合作报价只作为已审核账户中的附加行动，不与普通客户主行动争抢层级。 |
| 内容不足或服务不可用 | 未准备好的叙事页不以巨大留白、默认模板或单独跳转冒充完成；使用已批准的安全空态，说明当前状态，并只提供一个仍然真实可完成的顾问、选款或返回行动。 |

品牌公开文案仍以作品、设计、材质、工艺和服务为主角；页面视觉不得借供应商、批发或低价话术建立价值。

## 标准二 · 网站如何用文字

### 2.1 一句话原则

> 衬线做标题（细字重），无衬线做正文；中文不加宽，英文大写加宽；层级靠字号和留白区分，不靠颜色和边框。

### 2.2 字体双轨

下表是当前实现基线，不等同于最终品牌字体授权。上线使用前必须核对字体许可、中文字符覆盖、字重文件、回退效果和加载成本。

| 用途 | 字体栈 |
| --- | --- |
| 英文标题 / 品牌名 | Cormorant Garamond, Garamond, serif |
| 中文标题 | Noto Serif SC, Songti SC, SimSun, serif |
| 正文（中英） | -apple-system, PingFang SC, Helvetica, sans-serif |

> 英文展示标题与中文展示标题分别使用适合各自语言的字体；正文统一以高可读性的无衬线字体为主。禁止把所有中文机械套用英文衬线字体，也禁止为追求“品牌感”加载过多字体。

### 2.3 排印 Scale（模数比例 3 : 1.6 : 1）

| 层级 | 桌面 px | 移动 px | 用途 |
| --- | --- | --- | --- |
| 展示标题 Display | 68 | 40 | 品牌大标题、Hero |
| 主标题 H1 | 34 | 28 | 页面主标题 |
| 区块标题 H2 | 24 | 20 | 区块标题 |
| 系列名 / 副标题 | 18 | 16 | 系列名、副标题 |
| 正文 | 15 | 14 | 正文 |
| 辅助 | 12 | 11 | 注释、辅助 |

### 2.4 字重

| 场景 | 字重 |
| --- | --- |
| 标题（前台） | 300 ~ 500，偏细，禁止粗黑体 |
| 正文 | 400 |
| 后台标题 | 600（无衬线） |

### 2.5 字距（4 场景）

| 场景 | 字距 |
| --- | --- |
| 中文标题 | `0` 或 `-0.2px`（不加宽） |
| 英文全大写标题 | `+1.5px`（加宽） |
| 大字号 | 收紧，可微负 |
| 小字号 | 放宽，可 `+0.5px` |

### 2.6 行距与行长

| 项 | 数值 |
| --- | --- |
| 标题行距 | `1.2 ~ 1.4`（字越大越紧） |
| 正文行距 | `1.6 ~ 2.0`（字越小越松） |
| 正文行长 | 每行 ≤ 45 字 |

### 2.7 对齐三法

| 对齐 | 适用 | 感觉 |
| --- | --- | --- |
| 左对齐 | 默认、正文、多行标题 | 舒适、现代 |
| 居中 | 短标题、产品图下方 | 庄重、对称 |
| 两端对齐 | 仅在长文经过真实中文排版验收时使用 | 克制使用，避免字间空洞与阅读断裂 |

### 2.8 中西混排

- 中英文之间留 1/4 空格。
- 标点统一：中文语境用全角，英文语境用半角。
- 数字、英文用西文字体，中文用中文字体，不混用。

### 2.9 前台 vs 后台（文字分界）

| 项 | 前台 | 后台 |
| --- | --- | --- |
| 标题 | 衬线，字重 300 ~ 500 | 无衬线，字重 600 |
| 正文 | 无衬线，字重 400 | 无衬线，字重 400 |

### 2.10 文字禁用

- ❌ 粗黑体大标题、中文标题加宽字距、衬线正文
- ❌ 促销腔、感叹号堆砌、价格轰炸、长段落
- ❌ 靠颜色和边框区分层级（应靠字号和留白）

## 标准三 · 网站如何用间距与布局

### 3.1 一句话原则

> 留白用于建立节奏与层级；删掉无效信息，保留完成用户任务所需的事实。品牌叙事区默认一个主焦点，功能页面按任务组织信息。

### 3.2 间距 Scale（4px 子网格，8px 主节奏）

| 档位 | 值 | 前台用途 | 后台用途 |
| --- | --- | --- | --- |
| xs | 8px | — | 紧凑内边距 |
| sm | 12px | — | 表单项间距 |
| md | 16px | — | 卡片内边距 |
| lg | 24px | 卡片网格间距 | 模块间距 |
| xl | 32px | 卡片网格间距 | 大模块间距 |
| 2xl | 48px | 图文间距 | — |
| 3xl | 64px | 区块内模块间距 | — |
| 4xl | 80px | 页面左右边距 | — |
| 5xl | 96px | 区块垂直间距 | — |

### 3.3 栅格

- 12 列栅格；容器最大宽度 1280px，居中。
- 正文文字栏更窄（≤ 720px），不拉满全宽。
- 一切元素落在网格上——秩序产生高级感（Müller-Brockmann）。

### 3.4 版式与留白基线

- Hero、系列封面和品牌叙事画面默认只设 1 个视觉焦点，其余元素为它服务。
- “留白约 40%、文字不超过画面约 30%”只作为品牌叙事区的诊断参考，不是商品详情、表单、隐私正文和移动端的机械硬指标。
- 功能页面可以提高信息密度，但必须通过分组、间距、字号和渐进披露保持秩序；不得用隐藏关键信息制造虚假的极简。
- 品牌叙事区优先使用两类版式：**对称**（产品居中，庄严经典）或**不对称但平衡**（图一侧、文字反向留白，现代编辑感）；功能页面可按任务采用网格、分栏或渐进披露，但必须保持统一对齐和单一主层级。

### 3.5 响应式断点（布局随断点变化）

| 断点 | 行为 |
| --- | --- |
| 桌面 ≥ 1440 | 12 列，边距 80px |
| 小桌面约 1024 | 保留主要层级，减少并列模块，边距 32 ~ 48px |
| 平板约 768 | 边距 24 ~ 32px，双列按内容降为单列 |
| 手机 ≤ 390 | 单列，边距 20px，留白 ≥ 20% |

### 3.6 前台 vs 后台（间距布局分界）

| 项 | 前台 | 后台 |
| --- | --- | --- |
| 间距 | 大留白（48 ~ 96px 为主） | 8pt 网格、紧凑 |
| 布局 | 12 列、留白驱动、单一焦点 | 高信息密度 |
| 对齐 | 左对齐 / 居中 | 左对齐为主 |

### 3.7 间距与布局禁用

- ❌ 满屏信息堆砌、模块挤在一起无呼吸感
- ❌ 左一个右一个散乱对齐、多焦点
- ❌ 移动端把留白挤没、强行多列
- ❌ 正文文字栏拉满全宽（超过 720px）

## 标准四 · 色彩与材质表达

### 4.1 全站共享色彩底盘

成熟奢侈品牌的共同规律不是共享同一种“奢华色”，而是以稳定的中性界面承托各自摄影与品牌资产。海川尚无经独立确认的专属品牌色，因此网站不发明第二品牌色；前台以近白/象牙白、石墨、矿物灰和细线建立中性底盘，黄金、宝石、肤色与空间色彩由真实影像承担。小面积香槟金只能作为非功能性的识别点，不构成全局品牌色或交互主色。

| 语义角色 | 标准色值 | 用法 |
| --- | --- | --- |
| 主画布 / 表面 | `#FFFFFF` | 默认页面、卡片、表格、表单与商品展示背景；前台整体保持近白 |
| 次级画布 | `#F4F5F5` | 矿物灰低对比分区、图片承托与后台布局背景；前台象牙白氛围优先由影像和连续叙事表面表达，不另建米黄底盘 |
| 主文字 / 主操作 | `#181A1B` | 石墨色标题、正文、主要操作和浅色背景焦点 |
| 次级文字 | `#5F6568` | 辅助事实、说明和表格次级信息 |
| 最低功能文字 | `#6E7477` | 图注与弱信息；仍须满足对应字号的对比度要求 |
| 分隔线 | `#DDE1E2` | 1px 分隔、输入框与非唯一边界 |
| 强分隔线 | `#B8BEC1` | 可操作控件边界与需要更高非文本对比度的结构 |
| 深色画布 | `#111315` | Hero 承托、菜单与少量编辑型章节 |
| 反色文字 | `#F7F8F8` | 深色画布和影像上的文字、图标与操作 |

### 4.2 客户前台应用剖面

- 客户前台采用“中性界面、影像有色”：UI 只使用共享底盘，商品金属、宝石、人物和场景可以在真实摄影中保留色彩。
- 大面积暖棕、咖啡、米黄或金色蒙层不能替代品牌资产，也不能用来把普通图片统一染成“奢华”。只有真实编辑影像的叙事和材质需要时才允许出现相应环境色，并必须保留珠宝真实色彩、明确主焦点和足够文字对比度。
- 默认画布为纯白；次级画布只用于连续的功能或叙事分区，不在同一视口碎片化交替多种近白色。
- 不把金色、香槟色、米黄、青玉色或竞品识别色升级为海川全局界面品牌色。香槟金只允许在眉题细线、小型编号、章节标记等非功能识别点克制使用，不承担正文、按钮、链接、焦点、选中态、销售状态或大面积背景；实际令牌引入仍须通过新的品牌决策与令牌迁移。
- 主要按钮使用近黑底反色字，深色背景使用反色按钮；链接与选中态通过字重、下划线、边界或黑白反转表达，不用装饰色承担层级。
- 透明白字导航的下方必须是可证明对比度的真实 Hero 媒体或 `#111315` 承托区；滚动后切换为白底近黑字。
- 不用高饱和渐变、霓虹色、彩虹色、玻璃拟态、金属渐变、半透明灰卡或大面积彩色底营造“奢华”。质感来自材质、比例、排印与摄影。
- 普通正文至少达到 WCAG AA `4.5:1`，大文字至少 `3:1`；商品图片不得通过 CSS 滤镜改变真实材质颜色。

### 4.3 管理后台应用剖面

- 管理后台使用同一共享中性底盘，但不复制前台的大留白、展示字体、透明导航或沉浸式深色章节。
- 主要操作与选中态使用 `#181A1B`，悬停使用 `#101213`，按下使用 `#000000`；浅色选中背景使用 `#ECEEEF`。
- 成功、信息、警告、错误是功能语义，不属于品牌装饰色，可以使用低饱和绿、蓝、琥珀和红；每个状态必须同时提供文字或可理解图标。
- 后台页面不得使用品牌金、墨棕、米金底或前台影像色作为通用按钮、焦点、图标和选中态。
- “同一标准”指共享色彩底盘、对比度和治理方式，不表示客户前台与管理后台采用相同信息密度或艺术表现。

## 标准五 · 摄影、图片与视频

### 5.1 素材分轨

| 类型 | 视觉要求 | 主要用途 |
| --- | --- | --- |
| 产品图 | 纯白、暖白或透明背景；柔光；材质真实；主体稳定 | `/catalog` 结果与选款、作品详情主图 |
| 编辑图 | 有明确叙事、佩戴关系、空间与景深；经过统一艺术指导 | Hero、系列、品牌故事、专题 |
| 工艺图 | 清晰呈现镶嵌、金工、宝石和手作细节 | 详情、工艺与定制 |
| 服务图 | 真实、克制地表现顾问、空间或流程 | 联系、预约、定制服务 |

### 5.2 图片硬规则

- 不得编造实物颜色、宝石大小、证书、工艺结果或佩戴效果；AI 生成图只能作为内部概念稿，公开前必须完成人工真实性、版权和品牌审核。
- Hero 和系列封面应优先呈现已审核的具体作品、工艺细节或真实佩戴关系；人物、空间和造型服务于珠宝，不以泛化时尚人像、巨大品牌字样或装饰性金属造型替代真实作品焦点。
- 每个公开 Hero 或系列章节必须作为一套完整素材包验收：已审核的作品或系列关联、适合桌面与移动端的安全裁切、真实 DOM 标题、准确 CTA 目标、有效替代文本、可追溯来源与商用授权，以及落字区域的实际对比度。任一关键项缺失时不得以图内英文、泛化年度主题或编辑器默认值补位；应保留为草稿，或改用单独批准的体面短页。
- 产品图与编辑图不能混作同一种资产；`/catalog` 商品结果必须保持统一背景、比例、主体尺度和裁切逻辑，`/products` 的编辑式展陈则按叙事目的使用经艺术指导的作品图或编辑图。
- 默认比例：产品卡 `4:5`（随模板契约派生，与商品网格实现一致）；系列与 Hero 根据构图使用横幅或全宽媒介，但必须为桌面和移动端分别设置安全裁切。
- 关键标题、系列名、材质事实、服务说明和 CTA 必须是可选择、可访问、可本地化的页面文字；不得只把这些信息烙在图片或视频中。图片内确有艺术字时，页面仍需提供语义等价的真实文字，不能用空标题或空替代文本承载关键内容。
- 使用高分辨率源图、响应式尺寸、明确 `width/height` 或 `aspect-ratio`，避免模糊、拉伸和布局跳动。
- 珠宝金属必须保留真实高光、火彩和通透感；禁止重滤镜、过度锐化、塑料质感、硬投影和虚假的闪光特效。
- 每张有信息价值的图片提供准确替代文本；纯装饰图使用空替代文本。替代文本描述内容，不堆关键词。
- 第三方图片、字体、视频、音乐、图标和设计稿必须有可追溯授权；含第三方或竞品品牌名称、商标、包装、识别性文案或受保护视觉资产的素材未经授权不得公开，不确定时只能作为内部草稿。
- 已公开的未授权、授权失效、隐私或安全问题素材按 `docs/PROJECT_GUARDRAILS.md` 的处置边界先停止公开暴露，再完成替换后的桌面、移动和公开页面复核；本视觉规范不另行定义 CMS 操作流程。

### 5.3 视频与动图

- 只在静态图片无法表达工艺、佩戴动态或品牌情境时使用视频。
- 自动播放视频必须静音、可暂停、有静态封面，并遵守“减少动态效果”偏好；不得阻塞首屏内容和主要操作。
- 不用无限循环闪烁、强制全屏、滚动劫持或音频自动播放制造戏剧感。

## 标准六 · 组件与交互语言

### 6.1 导航与页头

- 主导航保持短、稳定、可预测；同级入口不重复，营销活动不得挤占品牌与作品的主层级。
- 合作申请只在“我的账户”及其合作服务区域提供，不进入品牌主导航；未审核访客不得从导航或公开页面直接看到合作报价。
- Logo 周围保留清晰安全空间，不与搜索、账户、菜单或活动标签拥挤排列。
- 桌面和移动端导航必须支持键盘、清晰焦点、ESC 关闭和滚动锁定恢复；透明页头跨越浅色/深色图片时必须保证可读。

### 6.2 按钮与链接

- 每个内容单元只设一个主要行动；主次通过层级与位置区分，不靠同时出现多个高对比按钮。
- 默认使用近黑实心或细边框按钮；同一页面保持一致。香槟金识别点不得作为按钮底色、链接色或唯一交互提示。
- 品牌叙事页 CTA 优先使用“探索系列”“查看作品”“预约鉴赏”“定制咨询”等克制表达。统一详情按照业务层已经允许的 `SalesMode`、资格和功能开关呈现一个主要行动，其文字必须准确描述点击后的真实结果：咨询当前作品、加入或继续选款、携作品信息预约、进入已批准的零售购买路径，或提交定制需求。不得把普通咨询写成“已获得报价”，也不得在报价、下单或支付能力尚未具备时使用暗示已经成交的文案。已审核合作商在适用设计上可以另见合作报价附加行动，但不得与普通客户主行动争抢层级。禁止“立即抢购”“疯抢”“最后机会”等强迫式话术。
- 所有交互状态包含 hover、active、focus-visible、disabled 和 loading；触控目标不小于 `44 × 44px`。

### 6.3 卡片、标签与图标

- 产品卡默认无厚边框、重阴影和大圆角；以图片、留白、文字和轻微状态变化建立层级。
- 徽章只用于真实且必要的状态；禁止批量添加“热卖、爆款、必买、限量”等未经确认的营销标签。
- 图标采用统一线性或统一实心体系，尺寸和描边一致；客户前台不使用 Emoji 代替正式图标。
- 弹窗、浮层和悬浮入口保持少量且有明确退出方式，不遮挡珠宝主体和关键内容。

### 6.4 表单与服务转化

- 奢侈品体验不能以隐晦为代价。字段标签、必填项、隐私说明、错误原因、提交状态和后续流程必须清楚。
- 表单默认只收集完成服务所需的最少信息；不得为了“客户画像”增加无当前用途的隐私字段。
- 失败时给出可理解提示和恢复方式，成功时说明下一步；不得静默失败或伪造服务承诺、响应时效。

### 6.5 设计令牌、组件与页面装修治理

- 本文件定义设计意图；运行时色值、字体、间距、圆角、阴影、层级和动效必须由现有全局设计令牌或组件实现。页面内硬编码不成为新标准。
- Puck/CMS 可配置项应优先使用令牌、语义化变体和受控选项。机器合同可以为特定模板开放有边界的实例级颜色、字号、对齐、比例和几何调整，但必须限制范围、提供安全默认与重置，并实时检查对比度、溢出和响应式结果；实例值不得改写全局令牌。不得开放任意 HTML/CSS、阴影、动画或无界自由布局来绕过品牌与安全门禁。
- 新组件先证明现有组件无法覆盖，再新增可复用变体；禁止为单页创建第二套按钮、卡片、导航或表单语言。
- 全站共享色彩底盘只能在本文件定义一次；客户前台和管理后台分别通过语义别名消费，页面硬编码、组件局部主题与装修实例不得建立平行色盘。

- 能直接操作的任务优先使用 Canvas、结构树、选择器、数值控件、拖拽和即时预览；主要操作必须有键盘可达的等效结果。操作后焦点、选中对象、未保存状态和预览保持同步。
- 跨模式设计提取或其他复杂变更使用结构化差异呈现可应用、保留、冲突和排除项；载入结果必须继续明确显示为未保存，不能把建议、预览或内存草稿呈现为已持久化或已发布。
- 控件必须呈现真实加载、空、失败、成功、无效引用、并发冲突和发布阻断状态，并提供与风险相称的恢复动作；控件可见不代表功能完成，画布和公开结果必须与已保存事实一致。

## 标准七 · 动效与节奏

- 功能交互默认 `160 ~ 240ms`；编辑型入场可使用 `400 ~ 800ms` 的低幅度淡入或位移。数值是参考范围，连续操作反馈不得迟缓。
- 动效只用于解释层级变化、焦点转移、状态反馈或材质氛围；没有信息价值的装饰动画应删除。
- 单一区域只保留一个主要动效，不同时叠加缩放、旋转、发光、视差和粒子。
- 禁止滚动劫持、持续漂浮、弹跳 CTA、夸张 3D 翻转、光效扫过文字和无暂停自动轮播。
- 支持 `prefers-reduced-motion`；减少动态效果时仍须完整传达内容和状态。
- Hero 默认优先单一叙事画面。轮播必须有明确编辑理由，通常不超过 3 帧，提供手动控制、当前位置和暂停能力。

## 标准八 · 文案与内容语气

### 8.1 品牌语气

- 克制、准确、温和、自信；用作品、材质、工艺和服务事实建立价值，不用空泛自夸。
- 标题短而有意义，通常 2 ~ 10 个中文字；不为追求短句牺牲可理解性。
- 一个视觉单元采用“一个标题 + 一句必要说明 + 一个主要 CTA”的默认结构；复杂详情和法规内容不受此长度限制。
- 中文为主，英文只在系列名、品牌表达或必要术语中使用；中英文语义必须一致。

### 8.2 内容禁区

- 不得编造品牌历史、创始年份、传承代数、设计师身份、奖项、认证、材质、来源、工艺、产地、稀缺性、宝石等级、库存、销量、价格、保值能力或售后承诺。
- 禁止促销腔、感叹号堆砌、价格轰炸、虚假限量、虚假倒计时、伪造排队人数、暗示性库存紧张和“全网最低”等表达。
- 公开品牌文案以作品、设计、材质、工艺和服务为中心，不用“源头工厂”“厂家直销”“批发低价”“一手货源”等供应商或低价话术建立品牌价值；确需披露的来源或合作事实必须真实、必要并符合当前受众权限。
- 未确认内容标记为草稿或占位，不得进入公开发布状态；历史已发布内容需要独立审核，不能因默认模板合规就视为已经合规。
- 公开端的安全空态或故障降级必须是单独批准的公开内容，不得直接把编辑器 seed、内部占位文案或未发布草稿作为公共回退。
- 作品进入 `/catalog` 或统一详情前，至少必须具备已批准的公开名称、有效主图、品类与材质核心事实、明确 `SalesMode` 及与之相符的一个主要 CTA；适用的价格、库存、证书或服务条件仍按对应事实源与权限展示。关键项缺失、文本损坏或媒体失效时应阻止公开并回到后台完善，不用破图、乱码长名、大量“—”或虚构默认值填满页面。
- 商品参数、价格、库存和服务条款以对应业务单一事实来源为准；视觉组件不得自行派生或改写经营事实。

## 标准九 · 响应式、无障碍与性能

### 9.1 响应式

- 验证范围按 `WORKFLOW.md` 的改动分级执行：局部改动至少检查一个受影响桌面视口、一个移动视口和真实问题边界；组件或断点改动增加受影响断点前后；全局系统、页面骨架和发布验收执行 `1440 × 900`、约 `1024px`、约 `768px`、`390 × 844` 代表矩阵，必要时增加超宽屏与小屏设备。
- 移动端不是桌面缩小版：重新确定焦点、图片裁切、内容顺序、按钮位置和折叠逻辑。
- 不能出现横向溢出、被固定页头遮挡、文字压图、触控目标重叠或关键 CTA 落在不可达区域。

### 9.2 无障碍

- 所有功能可使用键盘完成；焦点顺序符合视觉顺序，焦点样式清晰且不能被移除。
- 正文对比度至少 `4.5:1`，大文字至少 `3:1`；香槟金识别点不得承担正文、交互或唯一状态信息。
- 标题层级语义连续；按钮、链接和表单控件使用正确原生语义或等效无障碍属性。
- loading、empty、error、success 状态可被辅助技术理解；错误不只改变颜色。

### 9.3 性能

- 高分辨率不等于上传原始大图。图片使用适合视口的尺寸和现代格式，首屏关键图优先加载，屏下图延迟加载。
- 首屏媒介必须预留尺寸，避免累计布局偏移；字体控制字重和字符集，避免加载无用字体文件。
- 品牌首页和作品详情以 Core Web Vitals 良好阈值为目标：LCP ≤ 2.5s、CLS ≤ 0.1、INP ≤ 200ms；无法实测时必须标记未验证，不能以本机观感代替。
- 动画、视频和页面构建器模块不得阻塞导航、表单、商品信息或可访问性树。

## 标准十 · 页面类型默认模式

成熟品牌页面不是模板模块的集合。每次公开前必须明确一个叙事命题、一个主要视觉焦点、一套贯穿页面的影像语言和一个主要行动；章节可以变化节奏，但不得在同页拼接彼此冲突的字体、色彩、摄影、装饰母题或交互语法。页面装修模板是实现工具，不是页面艺术指导的事实来源。

| 页面 | 主焦点 | 默认结构 | 禁止倾向 |
| --- | --- | --- | --- |

## 标准十一 · 视觉验收与变更治理

### 11.1 修改前

- 新页面、实质改版或全局视觉变更：获取当前页面桌面和移动端截图，并说明页面任务、目标受众、唯一主焦点及本次不改内容；局部修复只检查受影响视口和真实问题边界。
- 检查现有 Logo、字体、品牌色、图片授权和内容事实；缺失项必须标记待确认。
- 先判断问题属于图片、图文关系、信息层级、字体、色彩、交互还是性能，禁止用全局重设计解决局部问题。

### 11.2 修改后最低验收

以下是验收维度，不是每次局部改动都机械执行的固定套餐。按 `WORKFLOW.md` 选择受影响维度；新页面、实质改版、全局品牌系统、页面装修共享 Renderer 和发布验收必须覆盖全部适用项。未受影响的维度可标记“不适用”，但不能把未检查写成已通过。

1. **焦点**：眯眼看时第一焦点是否落在珠宝或本页核心任务上。
2. **删减**：是否仍有可以删除而不损害理解和转化的元素。
3. **一致性**：字体、颜色、间距、按钮、图标和图片比例是否来自本规范或已有令牌。
4. **双端**：桌面与移动端真实页面是否分别成立，而非仅无报错。
5. **状态**：loading、empty、error、success、disabled、focus 是否完整。
6. **可访问性**：键盘、对比度、替代文本、标题结构和减少动态效果是否可用。
7. **性能**：首屏图、字体、视频和布局稳定性是否经过实际检查。
8. **真实性**：公开文案、图片、价格、库存、材质和服务承诺是否有来源或处于安全草稿状态。
9. **完整度**：Hero/系列素材包与目录/详情最低公开字段是否齐全；页面是否只有一个清楚的叙事命题、主焦点、影像语言和主要行动。

视觉改动只有在“相关代码检查 + 受影响维度的真实页面/浏览器验收 + 必要状态验证”完成后，才能在该范围内称为完成。截图可以记录视觉证据，但不能替代交互、字体加载、响应式和状态检查；构建成功、单张效果图好看或某一视口无问题，都不能单独外推为全页面完成。

### 11.3 例外与规范变更

- 单页面因专题艺术指导需要偏离默认规则时，记录偏离项、理由、适用页面和桌面/移动端证据；不得顺手修改全局令牌。
- 修改 Logo、香槟金识别点的用途或实际色值、核心字体、全局色盘、排印比例或交互基调属于品牌系统变更，必须先获得项目负责人明确确认。
- 新规则必须写入本文件；其他治理文件只引用，不复制具体数值。发现本规范与真实实现不一致时，先报告差异，不自动把现状写成标准。
- 本规范不证明当前页面已经合规。每次发布仍需以真实页面、真实内容、真实素材授权和当次验证结果为准。

## 附录 A · 管理后台排版、密度与无障碍

> 本附录是管理后台视觉数值的唯一详细来源。`docs/ADMIN_COPY_GUIDE.md` 只定义中文内容语言并引用本节；页面样式、组件文档或业务说明不得再建立第三套字号、间距或色彩标准。前台既有基线不因本附录改变。

### A.1 证据层级与法庭审校

数值和判断按以下四类标注：

1. **W3C hard requirement**：WCAG 2.2 AA 无障碍硬门槛，不得被品牌审美覆盖。
2. **Ant official default**：当前项目组件体系的官方默认与后台密度基线，可由项目令牌有理由地偏离。
3. **Haichuan project token**：海川后台为清晰、效率、可信和低误操作作出的项目设计决策，不是法规或行业统一标准。
4. **Luxury benchmark only**：珠宝品牌官网只用于研究克制、比例、秩序和品牌气质，不提供后台字号标准。

短法庭审校：原告主张精确令牌能减少漂移并建立秩序；该主张由旧实现中的两套品牌金、两套行高、26/30 px 页面标题和 10/11 px 功能字得到支持。被告指出大留白、低对比金色、衬线功能字及全局主题替换会降低效率并影响并发页面；该风险由现有共享样式得到支持。**法律助理意见**：只在共享令牌与后台壳层实施最小迁移；WCAG 为硬门槛，Ant 为默认基线，海川偏离必须记录理由，竞品只作艺术参考。禁止逐页机械替换和后台奢侈品化改版。

官方依据：

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)、[文本间距](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing)、[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow)、[点击目标最小尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast)。
- [Ant Design 主题令牌](https://ant.design/docs/react/customize-theme/)、[表格组件](https://ant.design/components/table/)、[数据展示规范](https://ant.design/docs/spec/data-display/)、[布局规范](https://ant.design/docs/spec/layout/)。
- 艺术参考仅取官方站点：[Cartier 珠宝系列](https://www.cartier.com/en-us/jewelry/all-collections/)、[Van Cleef & Arpels 珠宝系列](https://www.vancleefarpels.com/us/en/collections/jewelry.html)、[Tiffany 珠宝](https://www.tiffany.com/jewelry/)、[Bvlgari 珠宝](https://www.bulgari.com/en-us/jewelry)。由这些样本归纳的“少量强调色、稳定对齐、明确主次、克制装饰”属于艺术观察，不复制其文案或具体像素。

### A.2 后台排版层级

后台操作文字统一使用高可读无衬线字体栈。衬线字体最多用于纯品牌标识，不用于页面标题、导航、表格、表单、状态、错误、确认或 KPI 事实。中文操作文字 `letter-spacing` 默认为 `0`；只有不承担操作或状态的英文大写分组标签可使用不超过 `0.08em` 的字距，且不得低于 Caption 层级。

| 层级 | 字号 / 行高 | 字重 | 用途 | 来源类型 |
| --- | --- | --- | --- | --- |
| Page title | `26 / 34px` | `600` | 页面唯一 H1 | Haichuan project token |
| Section title | `18 / 26px` | `600` | 页面主要分区 | Haichuan project token |
| Card / Table title | `16 / 24px` | `600` | 卡片、表格、弹窗区块标题 | Haichuan project token |
| Body / Table cell | `14 / 22px` | `400`，强调 `500` | 正文、表单、表格与常规操作 | Ant official default（`14px`、约 `1.57`）+ Haichuan project token |
| Secondary | `13 / 20px` | `400` | 次级说明、时间与元数据 | Haichuan project token |
| Caption | `12 / 18px` | `400` 或 `500` | 辅助标签、图注；不得承载主要操作 | Haichuan project token |
| Code / ID | `13 / 20px` | `500` | SKU、订单号、请求 ID、版本号 | Haichuan project token |
| Numeric / KPI | `28 / 36px` | `600` | 首页事实数值；保持无衬线 | Haichuan project token |

- 功能性文字原则上不低于 `12px`，正文和表格以 `14px` 为基线；这是 **Haichuan project token**，不是 WCAG 规定的固定最小字号。
- `12px` 文字不得使用香槟金识别点或低对比灰。普通文字与背景至少 `4.5:1`；大文字至少 `3:1`（W3C hard requirement）。
- 金额、计数、百分比、日期时间列、KPI、分页总数及等宽 ID 使用 `font-variant-numeric: tabular-nums`；自然语言中的零散数字不强制。
- 文本必须允许用户覆盖到行高 `1.5` 倍、段后距 `2` 倍、字距 `0.12em`、词距 `0.16em`，且不丢失内容或功能（W3C hard requirement）。

### A.3 间距、密度与响应式

Ant Design 以 `8px` 为布局基础单位；海川采用 `4px` 子网格与 `8px` 主节奏。令牌为 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px`（Ant official default + Haichuan project token）：

| 令牌 | 默认用途 | 来源类型 |
| --- | --- | --- |
| `4px` | 图标与短标签、紧邻元素微调 | Haichuan project token |
| `8px` | 按钮间距、行内控件、紧凑单元 | Ant official default + Haichuan project token |
| `12px` | 表格纵向内边距、紧凑卡片间距 | Haichuan project token |
| `16px` | 卡片基础内边距、字段内说明 | Haichuan project token |
| `20px` | 常规表单行距、平板页面 gutter | Haichuan project token |
| `24px` | 字段组、模块间距、小桌面 gutter | Haichuan project token |
| `32px` | 主要模块分隔 | Haichuan project token |
| `40px` | 大区块或页头与正文分隔 | Haichuan project token |
| `48px` | 页面底部安全留白；非默认模块留白 | Haichuan project token |

布局应用：

- `1440px` 桌面：页面 gutter `28px`，主要模块间距 `32px`，卡片内边距 `20px`；`1024px` 小桌面：gutter `24px`、模块间距 `24px`；`768–1023px` 平板：gutter `20px`、卡片 `16px`，工具栏允许换行。（Haichuan project token）
- 表单行距 `20px`，相关字段组间距 `24px`，不同语义字段组 `32px`；按钮之间 `8px`，主次按钮组与危险操作组至少 `16px` 分隔。（Haichuan project token）
- 筛选条和工具栏的单行最小高度 `40px`，换行时保持 `8px` 行列间距；不得为了塞进单行压缩标签或点击目标。（Haichuan project token）
- 后台不把前台 `48–96px` 大留白作为默认。高级感来自对齐、比例、克制色彩和稳定节奏，不来自降低信息密度。

### A.4 控件与表格

| 控件密度 | 高度 | 适用场景 | 来源类型 |
| --- | --- | --- | --- |
| 紧凑 | `32px` | 表格内次级操作、筛选条；不可用于危险主操作 | Ant `32px` 默认基线 + Haichuan project token |
| 默认 | `36px` | 后台常规按钮、输入框、选择器 | Haichuan project token；较 Ant 默认略舒展以降低误操作 |
| 大 | `40px` | 页面主要提交、登录、关键确认 | Ant official default（LG `40px`）+ Haichuan project token |

- 指针点击目标最低 `24 × 24 CSS px`，或满足 WCAG 2.2 的间距/等效等例外（W3C hard requirement）。海川常用操作推荐至少 `32 × 32px`，主要与危险操作推荐高度 `36–40px`；危险操作不得只呈现微小图标（Haichuan project token）。
- 表格正文与表头均以 `14px` 为基线。海川默认单元格纵向/横向内边距为 `12 / 16px`，紧凑表格为 `8 / 8px`；Ant 官方基线为标准/中/小纵向 `16 / 12 / 8px`，海川采用中等密度作为默认以兼顾扫描效率和误触风险。
- 时间、状态和操作列保持完整且尽量不换行；空单元格统一显示 `—`。Ant 官方示例使用 `-`，海川选择更易辨识的长破折号属于项目文案决策。
- 长文本可截断，但完整值必须能通过键盘可达的 Tooltip、展开详情或复制控件获得；不能只依赖鼠标悬停。商品编码、订单号等优先支持复制并保留可访问名称。
- 固定列只保留识别对象和主要操作所必需的列；横向滚动限制在表格容器，不得让整页双向滚动。数据表可使用 WCAG 重排例外，但表格外的标题、筛选与分页仍须重排，单元格内容仍不可丢失。
- QA 至少检查浏览器 `200%` 文本缩放；WCAG 重排硬门槛按等效 `320 CSS px` 宽度（通常为 `1280px` 视口 `400%` 放大）评估。缩放时允许表格容器横向滚动，不允许操作栏、筛选条或分页被裁切。

### A.5 任务可见性与渐进披露

后台的简洁以“减少理解、查找和操作成本”为准，不以首屏元素数量少、面板默认收起或页面留白多为准。每个页面、弹窗、抽屉和编辑器面板必须先明确当前主要任务；对象身份、真实状态、主要操作、未保存状态、适用限制和关键后果默认可见；当前任务的必要字段直接可用，其他必填、已修改字段和错误可通过有意义的摘要与一键定位呈现，不要求全部控件同时展开。用户不应逐个打开折叠区才能发现待处理项。（Haichuan project rule）

**默认呈现与内容取舍：**

- 首屏先呈现“当前对象与状态 → 主要任务内容 → 主要操作与结果”，相关字段按任务分组连续排列；不得用卡片、分割线、说明文字或重复标题把一个连续任务切成多段视觉噪声。
- 同一事实只保留一个权威展示位置。删除一句说明后若不影响用户作出决定、正确操作、理解风险或从失败中恢复，该说明默认不进入主任务区；后台中文表达细则见 `docs/ADMIN_COPY_GUIDE.md`。
- 主要操作应在完成其前置条件的位置可见；禁用时说明尚缺条件。权限不足、引用失效、保存冲突、发布阻断和未保存状态不得伪装成普通空态或藏入帮助内容。
- 详情较长时可以先显示摘要，但摘要必须足以识别对象、当前状态和待处理事项；完整值须通过键盘可达的详情、复制或展开方式取得。

**可视表达与直接操作：**

- 状态、进度、趋势、比较、层级、顺序和修改差异分别优先使用状态标签/步骤、图表、对比表、树形结构、可排序列表和差异高亮；单一数值、精确明细和高密度事实优先使用数值、表格或结构化字段，不为装饰而图表化。
- 能由控件状态、选中关系、即时预览或结构化结果直接说明的事实，不再用段落重复解释；能通过选择、切换、排序、调整、接受/拒绝和撤销直接完成的任务，不要求用户阅读操作步骤或手工重做。
- 可视化仍须提供对象名称、指标、单位、时间范围、精确值获取方式、状态文字和异常原因；图标、颜色、形状、动画或鼠标悬停不得单独承担必要信息。
- 指针直接操作必须有键盘可达的等效业务结果，不要求机械复制同一手势。拖拽排序提供上移/下移或等效菜单，Resize 提供方向键或数值输入，Hover 操作在键盘聚焦时同样可见，快捷键可发现且不覆盖文本输入和浏览器常用操作。
- 操作后立即同步选中态、预览、差异与未保存状态；批量或 AI 建议优先显示字段级“原值 → 建议值”、可接受/拒绝项、冲突和排除项，不用长篇总结代替可核对变化。风险、限制、失败恢复和不可逆后果仍使用简短明确文字直接呈现。

**折叠、手风琴、抽屉和“更多设置”仅在同时满足以下条件时使用：**

1. 当前主要任务的必要字段直接可用，其余分组能凭摘要识别内容与状态，并一步展开定位；
2. 关键权限、风险和危险后果在执行前直接可见，不依赖展开才能发现；分层显示不改变字段值，不省略校验；
3. 收起后不影响用户判断当前状态、修改范围、异常、风险和操作结果；
4. 容器标题在关闭状态下仍显示有意义的摘要，并标识已修改、存在错误或需要处理的数量；
5. 展开控件具备正确语义、键盘操作和可感知的展开状态，展开后不会意外重置输入、滚动位置或未保存内容。

以下做法禁止：

- 把主要操作、未保存状态、权限或危险后果藏入默认收起区域；必填、已修改字段和错误若分层显示，外层须有可理解的摘要并能一键展开定位，不能只标一个无含义的数量；
- 为了缩短页面而让每个普通字段组都默认折叠，或使用嵌套折叠、连续抽屉、弹窗套弹窗代替清楚的页面结构；
- 用户编辑、校验失败或保存失败后自动收起相关内容，导致输入、错误或恢复动作离开视野；
- 仅以“高级”“更多”命名而不说明内容、当前值或影响；
- 在桌面有稳定空间时，以视觉整洁为由隐藏高频操作，再要求用户反复展开和关闭。

**允许的例外：**

- 窄屏可收起低优先级筛选、长篇只读元数据或批量辅助选项，但对象、状态、当前筛选摘要、错误和主要操作仍须可见；展开顺序与焦点移动必须可预测。
- 店铺装修在 `<1200px` 窄屏可使用覆盖式抽屉承载结构或属性面板，模式、选中对象、未保存状态、保存/发布状态和恢复入口仍须可见，重新打开后保留上下文。`>=1200px` 的四区基础框架只按 `PROJECT_RULES.md` §7 固定，不能用本通用例外收起面板或改变比例；区内字段与低频内容的分层仍按本节执行。
- 法规、风险、数据影响或不可逆后果即使文字较长也不得为了简洁而省略；可以分层组织，但关键结论必须在执行动作前直接可见。

**最低验收：**

- 用户无需盲目展开即可识别对象、状态、主要操作、未保存修改和错误摘要；当前主要任务可直接完成，分层字段可以从摘要一步定位。错误定位不丢输入、焦点上下文或未保存状态。
- 默认态、已修改态、校验失败态、加载/空/错误态及受影响窄屏至少各检查一次；使用折叠时追加键盘展开、焦点顺序、关闭摘要、状态保留和错误定位检查。
- 评审不能只比较点击次数或首屏高度；必须确认删除、隐藏或分层后没有降低任务完成率、状态可判断性、错误恢复能力和高风险操作的可理解性。

### A.6 色彩、状态与焦点

- 后台继承 §4.1 的共享色彩底盘；交互主色与正文使用 `#181A1B`，次级文字 `#5F6568`，最低功能文字灰 `#6E7477`，布局背景 `#F4F5F5`，不再定义品牌金或墨棕交互色。
- 普通正文至少 `4.5:1`；可操作图标、用于识别控件的边框和焦点状态至少 `3:1`（W3C hard requirement）。禁用控件虽有 WCAG 例外，仍应保持可辨识且不得与可操作状态混淆。
- 成功/完成用绿色，进行中/信息用蓝色，待处理/警告用琥珀色，失败/危险用红色，草稿/停用用中性灰；每个状态必须同时显示文字或图标形状，不只依赖颜色（Haichuan project token + WCAG 使用颜色原则）。
- 状态标签采用“深色文字 + 浅色底 + 可辨边框”：成功 `#356348 / #EFF5F1 / #ACC4B4`，警告 `#7A531A / #FBF4E8 / #D4BD96`，错误 `#8C3F3B / #FAF0EF / #D7B6B4`，信息 `#335F7D / #EEF4F7 / #ADC3D0`，中性 `#5F6568 / #F3F4F4 / #D5D9DA`。阈值仍以 W3C hard requirement 为准，具体组件上线前复核实际字号、字重和背景。
- 键盘焦点采用至少 `2px` 的 `#181A1B` 外轮廓并保留 `2px` 间隔；深色背景使用 `#F7F8F8`。焦点必须与相邻颜色达到至少 `3:1`，不得只依赖背景明度的微弱变化。

### A.7 治理、迁移与静态门禁

- 主题、共享壳层和状态组件先迁移；业务页面按访问频率和风险分批处理。迁移必须区分装饰色、真实媒体色与语义状态色，禁止不读语义的仓库级机械替换。
- `scripts/verify-admin-ui-standards.mjs` 对共享后台文件检查旧品牌金/墨棕、低于功能字号下限、英文三点加载、泛化危险确认及不足 2px 的焦点线。确有语义色例外时必须在脚本白名单中写明选择器与理由。
- 每次令牌变更记录受影响组件、预期视觉差异和浏览器证据。当前附录建立规范，不代表尚未迁移的业务页面已经合规。
