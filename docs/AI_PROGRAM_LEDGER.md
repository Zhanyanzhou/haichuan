## 当前工作包

当前优先工作包为 **公开咨询授权生命周期、首页等待体验、库存写入恢复与真实环境闭环**，目标是先消除旧客户身份或已撤销员工权限在并发窗口中读取私有数据、写入或重新排队咨询运营动作的代码缺口，避免公开首页读取期间出现不可理解的整屏空白，并关闭库存响应丢失后的重复增减风险，再把当前本地候选带入获批真实环境验收：

- **结果与范围**：客户资料、本人订单/详情/物流、地址、收藏、本人评价、本人合作申请、本人报价列表/详情和合作设计文件元数据读取不再把 Guard 通过时的 principal 降级为裸 ID；账户注销持续绑定入口 `id + authVersion`；顾问发送客户可见回复、领取 Lead、重试失败通知或员工调整库存时不再只依赖请求入口的角色判断。公开首页在已发布文档读取期间提供可见、稳定且不虚构内容的状态。库存 `in/out/adjust` 全部绑定操作者看到的 `expectedQuantity`，不再允许可重复增减的无基线写入。本工作包只调整既有服务、事务锁序、控制器接线、公开等待态、库存恢复语义和回归，不改 Schema/migration，不扩大角色权限，不连接生产或发送真实外部消息。
- **当前证据/修改**：上述客户读取均传递完整 `id + authVersion`，在同一 `Serializable` 事务中先以客户共享锁复核 `ACTIVE + authVersion`，再用同一 transaction client 进行领域读取；旧身份若先完成改密、换绑或注销，领域查询和物流供应商调用均为零。合作申请的客户状态和最新申请也位于同一快照，避免员工审核并发时拼接两个 autocommit 时点。账户注销在头像文件预处理前先以共享锁核验同一 principal，并在真正的注销事务第一步以排他锁再次复核；换绑等已递增认证版本但密码仍相同的旧会话因此不会预处理头像或执行任何注销写入。物流供应商查询有意保留在共享锁事务内，避免关闭账户先提交后仍把运单号发给外部供应商；这是隐私线性化优先于事务时长的明确取舍。顾问回复、领取 Lead 和失败通知重试事务都首先以员工行锁复核当前 `ACTIVE` 且角色仍为 `SUPER_ADMIN`、`ADMIN` 或 `CUSTOMER_SERVICE`，通过后才进入客户、Lead、Outbox、Activity、来源镜像与通知写入；入口 Guard 通过后若员工已停用或角色已撤销，相关领域读写为零。库存写事务同样先锁定员工并复核当前 `ACTIVE` 且角色仍为 `SUPER_ADMIN`、`ADMIN` 或 `WAREHOUSE`，再锁商品并以 `expectedQuantity` 条件更新到唯一目标数量；相同 `in/out` 请求在首写已提交但响应丢失后再次到达会得到 409，且不重复规则重算、业务审计或通知。后台遇到网络、408、409 或 5xx 时只读权威库存：目标值表示已生效、原值表示未生效且只允许操作者再次确认、第三值表示其他写入、读取失败表示结果待确认，四种路径均不自动重放 PUT。本人评价列表不再返回 `review-image:v1:*` 内部引用，而以受控媒体 URL 和 `review-submission:v1:<sha256>` 完整意图指纹支持响应丢失后的精确核验；图片顺序或其他提交字段不一致时不会误报精确成功。首页 published GET 在途时改为稳定且不虚构内容的可见状态。库存服务与审计聚焦 `7/7`、库存浏览器恢复 `5/5`、后台运营状态整文件 `28/28`；Node `22.23.2` 下服务端全量 `1521` 项中 `1498` 通过、`23` 项真实环境测试明确跳过、`0` 失败，两端类型检查与生产构建、目标 ESLint 均通过。
- **依赖/停止条件**：当前仍是 Prisma 桩、单进程测试、本地构建和开发 Vite `page.route` Mock 浏览器证据，不证明真实 InnoDB 双连接锁等待、完整 Nest HTTP 在途认证/权限变化与评价或库存响应丢失、物流供应商延迟/超时、SMTP、目标代理或生产会话；员工刷新会话家族撤销也不由本次角色行锁证据覆盖。库存此次采用带基线的目标状态 CAS，而不是新增持久化事件幂等事实；没有 Schema/migration，也没有恢复交易或资金能力。迁移安装阻断解除且获得隔离数据库后，执行真实 MySQL 并发、完整 HTTP 响应丢失/服务重启、库存员工撤权与双视口本人回读验收；在此之前不提升成熟度，`HC-COMMERCE` 继续暂停。
- **既有支付候选**：隔离支付 simulator 已达到 `LOCAL_HTTP_SIMULATOR_CANDIDATE` 停止条件，保留 provider mode、生产拒绝、回环签名、支付/退款/通知/账单合同以及真实 Nest HTTP 和双视口消费证据；在完整 `AppModule`、MySQL、供应商 sandbox 与资金批准到位前不继续扩张，也不提升为真实集成。
- **回退**：读取链仅回退完整 principal、共享读门禁和 transaction client 接线；咨询运营仅回退员工首锁与对应回归；首页仅回退中性等待态和浏览器断言；库存仅回退全类型基线、员工首锁、CAS 与 GET-only 恢复语义。均不涉及 Schema、migration、业务数据、外部状态或支付模式。

- **验收**：对同一版本/环境实际核验 runtime、Compose、数据库/管理员/开关、存储、恢复、边缘/告警、外部渠道和回退；无操作权或不能采集的 claim 明确失败。覆盖错误哈希、错误签名者、跨环境/版本证据和只有自报 JSON 的拒绝路径；本地契约检查不能替代真实签名与目标环境执行。
- **当前边界**：此处不表示工作流已实现、远端已核验或生产已授权，也不替代 D.34 的基线发布门禁。未启用高保证层时，不因这些增强项未完成而阻断符合基线的候选。
